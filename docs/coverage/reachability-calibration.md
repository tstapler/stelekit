# Reachability scan calibration against R8 `-printusage` (Task 0.2b)

Scan: `scripts/ci/reachability-scan.py` at commit `622867638f` (78 candidate types, 59 of them declared in sources that compile into the Android app; the other 19 are in `jvmMain`, `iosMain` or `wasmJsMain`). Baseline: `scripts/ci/reachability-baseline.txt`.

## How the R8 report was produced

One-off, not committed (minify stays off). `androidApp/build.gradle.kts` `release` was temporarily set to `isMinifyEnabled = true` with one proguard file:

```
-dontobfuscate
-dontoptimize
-ignorewarnings
-dontwarn **
-keepattributes InnerClasses,EnclosingMethod,Signature,*Annotation*
-printusage <scratch>/r8-usage.txt
```

```
ANDROID_HOME=$HOME/Android/Sdk timeout 30m ./gradlew --no-daemon :androidApp:minifyReleaseWithR8   # BUILD SUCCESSFUL in 38s
```

The first attempt (without `-keepattributes`) failed with `Attribute InnerClasses requires EnclosingMethod attribute`; the `-keepattributes` line fixed it. The only entry points are those AGP derives from the manifest (no app keep rules), so "removed" means "unreachable from `SteleKitApplication`, `MainActivity` and the other manifest components". The report lists 3,347 `dev.stapler.stelekit` entries. A line ending in `:` is a kept class with removed members; a line without it is a wholly removed class. Only whole-class removals are compared.

## Diff

- Scan candidates that are Android-compiled: 59. R8 removed the whole class for **58** of them.
- **1 disagreement, scan-only: `LruWeigher`** (`cache/LruCache.kt:113`). It is a `typealias`; the compiler erases it, so no class exists for R8 to report. The real type, `SteleLruWeigher`, is used. The scan lists the alias because nothing references the alias name. Reason: typealias, expected.
- **R8-only: 180 whole-class removals** for types the scan treats as referenced. Counted from their declarations: 73 data/value classes, 45 classes, 30 interfaces, 22 objects, 6 annotation classes, 4 enums. The scan is name-based: any mention of a name in another production file counts as a reference, including type-only uses and uses from code that is itself dead. R8 works on bytecode reachability from the manifest roots, so it is the stricter oracle. Two reasons explain the 180, by inspection of the list below and not proven per type: (a) reachable only from other dead code (for example `DriveFileBrowserViewModel`, `AssetPipelinePlugin`, `BackgroundSyncScheduler`, which exist because those features are not wired yet) and (b) compile-time-only or erased declarations (annotations such as `DirectSqlWrite`, interfaces and ports, inlined constants holders). The scan does not model (a) beyond one level (ADR-002 "Limits"); `WiringCompletenessTest` and the observable-effect catalog are the layers meant to catch it.

## Summary

| Disagreement | Count | Reason |
|---|---|---|
| Scan lists, R8 removes | 58 | agreement |
| Scan lists, R8 keeps | 1 (`LruWeigher`) | typealias, erased by the compiler |
| R8 removes, scan does not list | 180 | name mention or type-only use that bytecode reachability ignores, or reachable only from dead code (above) |

The scan is deliberately looser than R8: it does not flag a type that is mentioned anywhere, so the CI ratchet cannot fail on a type that is merely reached through other dead code. Types reachable only from dead code are the job of the wiring catalog, not this scan. Not calibrated: `jvmMain`, `iosMain` and `wasmJsMain` types (19 of the 78 candidates), because R8 only sees the Android app.
