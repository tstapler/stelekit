# Validation Plan: desktop-quick-capture

**Date**: 2026-09-05

## Happy Path Scenario

Given SteleKit is running on desktop with an active, unlocked graph, when the user presses the
global hotkey, types "Buy milk", and presses `Ctrl+Enter` (`Cmd+Enter` on macOS), then a new
`Block` containing "Buy milk" is appended to today's journal `Page` via `CaptureWriter`, flushed to
disk by `GraphWriter`, and the popup shows "Saved to today's journal" before auto-hiding — matching
`CaptureActivity`'s save target (requirements.md AC1).

## Test Stack

- **Unit**: JUnit 5 + Kotlin coroutines-test, on `jvmTest`. `IN_MEMORY` repository backend for
  `CaptureWriter`/`CaptureController` logic tests (fast, no real DB/disk). Compose UI component
  tests use `ComposeTestRule` (`createComposeRule()`), still classified "Unit" here since they
  exercise one composable in isolation with fakes, matching this repo's existing `jvmTest`
  convention for Compose screens.
- **Integration**: `jvmTest`, `SQLDELIGHT` backend + real temp-dir `PlatformFileSystem`/`GraphWriter`
  for DB+disk round-trips; real `java.nio.channels.SocketChannel`/`ServerSocketChannel` (JEP-380 UDS)
  bound to a temp-dir socket path for `CaptureSocketListener`/`CaptureSocketClient`; real
  `Files`/`Path` APIs against a temp `PendingCapturesDirectory` override for the poller and writer.
  Screenshot/visual-state tests use Roborazzi (Gradle-only, per `TESTING_README.md`).
- **E2E / UX**: Compose UI tests (`ComposeTestRule`) for keyboard-interaction and state-rendering
  criteria; manual/human-tester steps for anything requiring a real OS session, a real screen
  reader, an unplugged mouse, or a real global-hotkey conflict — none of which are headless-CI
  reproducible. Manual steps are called out explicitly per row above, not silently assumed covered.

| Stack | Coverage command | Target |

- All public service methods (`CaptureWriter`, `CaptureController`, `PendingCaptureWriter`,
  `PendingCapturePoller`, `CaptureSocketListener`, `CaptureSocketClient`): happy path + error paths
  covered above.
- All external integrations (SQLDelight DB, disk via `GraphWriter`, Unix-domain socket, pending-
  captures directory poll loop): unit-mocked (fakes) + at least one real integration test each,
  per the table above.
- UX acceptance criteria: 12 of 14 have an automatable Compose UI test; the remaining 2
  (screen-reader announcement content, and physical mouse-unplugged completion) are manual-only by
  nature and are marked as such rather than claimed covered.
- One story (1.3.1, real OS hotkey registration) has no automated integration-equivalent — real
  global-hotkey binding against a live desktop session isn't headless-testable — covered instead by
  a manual per-OS smoke test, called out explicitly rather than silently omitted.
