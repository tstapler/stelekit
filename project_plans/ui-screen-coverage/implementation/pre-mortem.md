| 3 | `Stage.REVIEW` in `ImportScreen.kt` is a `private` composable-internal enum (line 34: `private enum class Stage { INPUT, REVIEW }`); tests for Story 2.1.2 cannot inject `stage = REVIEW` directly and must drive the full INPUT flow via the UI, which requires wiring `UrlFetcher`, `AhoCorasickMatcher`, `PageSaver`, and `matcherFlow` — complexity not reflected in the plan's story definition or effort estimate. | Story 2.1.2 implementation stalls while the developer tries to find a way to set stage to `REVIEW` without going through `InputStage`, or discovers the setup requires substantially more fake wiring than any other story. | Update Story 2.1.2 in plan.md to explicitly document that `Stage` is private composable state, that reaching REVIEW requires clicking through the INPUT stage, and to provide a minimal fake wiring recipe (a `NoOp` `PageSaver`, a `StateFlow.value`-backed `matcherFlow`, and an empty `UrlFetcher`). Increase the story effort estimate from XS/S to M. | P2 |
| 4 | Story 1.3.2 (`AllPagesScreen`) test for "clicking a page row invokes onPageClick with the correct Page" fails with `NoMatchingNodeException` when the target row is below the Robolectric viewport; `performScrollTo()` is mentioned in the plan preamble but not in the per-story test specs, so it is omitted. | Test fails locally with `No semantics node matching node matcher` on the first attempt; developer is confused because the test passes with a 1-item list but fails with a 10-item list. | Add an explicit note to Story 1.3.2 in plan.md: any test asserting on a list row at index ≥ 5 must call `composeTestRule.onNodeWithText(row.name).performScrollTo()` before `performClick()`. Cross-reference the LazyColumn viewport note in the project context. | P2 |

If a new uncovered file appears, adjust Story 3.1.2/2.1.x test counts upward, or scope a new micro-story to cover it. Document the denominator as "line count at baseline date" in plan.md's risk section so drift is visible. | P3 |

## P1 Items (address before implementation)

- [ ] **Failure #1 — Wrong JaCoCo XML path**: Update the Story 3.1.1 grep command in plan.md from `kmp/build/reports/jacoco/jacocoAndroidTestReport/jacocoAndroidTestReport.xml` to `kmp/build/reports/jacoco/jacoco-android.xml`, which is the path set by `xml.outputLocation` in `kmp/build.gradle.kts:1682`. Run `./gradlew :kmp:jacocoAndroidTestReport` once on the current branch and verify the file is present at the corrected path before any story work begins.
- [ ] **Failure #2 — No automated gate for 55% overall**: Add a mandatory closure criterion to Story 3.1.1 in plan.md: the story is not complete until `grep 'ui/screens' kmp/build/reports/jacoco/jacoco-android.xml | grep LINE` shows ≥55% *after all prior stories have merged to the target branch*. If the project cannot add a Gradle task that fails the build below 55%, designate a specific reviewer whose sign-off on the Story 3.1.1 PR requires seeing the actual XML output pasted into the PR description.
