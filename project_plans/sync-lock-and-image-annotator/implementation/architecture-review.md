## Concerns

- [ ] **R1. Task 1.3c / ADR-001 decision 7: quiesce holds the worktree lock, then drains through code that takes the same lock.** `quiesce` does `GitWorktreeLocks.lockFor(shadowKey).lock()` (`GraphMoveQuiesceStrategy.android.kt:96-97`), then `drainWriteBack` calls `target.flush()` (`:124`). The production flush is `GitShadowFlushActor.flush`, which does `GitWorktreeLocks.lockFor(worktree.shadowKey).withLock {...}` (`GitShadowFlushActor.kt:47-48`). `kotlinx.coroutines.sync.Mutex` is not reentrant, so a non-empty write-back queue self-deadlocks until the 30 s quiesce timeout. It does not fire today only because the unit test injects a fake flush and nothing constructs the real target in production. The plan keeps "gate, then `GitWorktreeLocks`, then drain" and its new test uses a fake sync, so it would not catch this once Task 1.3b wires the strategy. Remediation: in Task 1.3c either drain via an unlocked flush variant (for example `flushLocked()` on the actor, analogous to `syncFromSafRootLocked`) or take the worktree lock only around non-flush work; add a test with a real `GitShadowFlushActor` and a non-empty queue that must complete. Also store the gate lease and the worktree lock atomically (a cancellation between `gate.withLock` and `heldLocks[...] =` leaks the gate; the current code has the same shape for the worktree lock).
- [ ] **R2. ADR-006 / Task 2.4a: `isFit` semantics below the new floor are unspecified.** The ADR says `isFit` "compares against `FIT_SCALE`". If it stays `scale <= FIT_SCALE + FIT_EPSILON` (as at `AnnotationViewTransform.kt:61`), then every scale in 0.25 to 1 is `isFit`, and the `clamped()` short-circuit (`if (s <= MIN_VIEW_SCALE + FIT_EPSILON) return Fit`, L112) would snap a 0.25 transform back to the identity at scale 1, defeating Story 2.4. Add to the ADR and Task 2.4a: `isFit` and the short-circuit use `abs(scale - FIT_SCALE) <= FIT_EPSILON`, and add an AC "at scale 0.5, `isFit` is false and `clamped` preserves 0.5".
- [ ] **R3. ADR-001 decision 4: fallback gate key can split one repo across two gates.** If `getConfig` fails transiently (closed or busy DB; it is a suspend DB read and can throw, not only return `Left`), the run uses `graph:<id>` while a concurrent run with a readable config uses `keyFor(repoRoot)`; the two do not exclude each other and the step-2 error path then runs ungated against the real repo's key. Also the clone path derives its key from the destination path (Task 1.4d), which must normalise identically to `repoRoot`. Remediation: catch `Throwable` (rethrow `CancellationException`) in `resolveGateKey`; on any unreadable config prefer a per-graph key that the readable path also acquires (take both, graph key then repo key, always in that order), or retry the read once before falling back; add a test that a config-read failure while a run holds the repo key still coalesces or skips.
- [ ] **R4. Task 1.4e file list vs its own text.** The text requires changing `fetch(...).toTickOutcome()` (defined at `PeriodicSyncDriver.kt:52-55`, which maps everything but `Offline` to `Failure`), but `PeriodicSyncDriver.kt` is not in the task's file list (it appears only in 1.4b). `TaskOutcomeMapping.kt` is listed under `CM/jobs/schedule/` "(path as found)"; actual path is `CM/git/TaskOutcomeMapping.kt` (VERIFIED), and it must stay out of `jobs/schedule` (import rule). Fix both, and add the explicit rule: `toTickOutcome` maps `SyncInProgress` to `Skip(Busy)`.
- [ ] **R5. Quiesce gate key source.** Task 1.3c says "key from the same resolver `GitSyncService` uses", but `AndroidGraphMoveQuiesceStrategy` takes only `shadowWorktreeTarget(op)` and has no `GitConfigRepository` or `repoRoot`. Name the injected `(StorageMoveOperation) -> String` key lambda and add it to the constructor parameter list in Task 1.3b, otherwise the quiesce gate and the sync gate can use different keys and the whole ordering fix is vacuous. Also state what a `UiPress` that loses the gate to a held quiesce lease does (rerun bit is set; the follow-up fires on `release`, after the move, against possibly relocated storage): either refuse presses while a quiesce lease is held or document that the follow-up re-resolves config.
- [ ] **R6. ADR-003 / Story 3.2 carry-over (unchanged, still open).** The repair added the precedence table and `PlaneKind`, but ADR-003 itself marks `HeightOffset` composition with a plane UNVERIFIED and defers it to Task 3.2a. Acceptable only if 3.2a is ordered before 3.3c in the wave list (it is, per the plan's dependency graph); keep that ordering an explicit gate in Phase 4.
