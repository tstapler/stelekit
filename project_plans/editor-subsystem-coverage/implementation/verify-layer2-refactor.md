# Layer 2 test refactor review (businessTest/editor/commands)

Scope: the three added test files only. No production changes proposed. Cost classes are token cost: XS < 1k, S 1-3k, M 3-8k.

Dead code / unused imports: none found. Every import in all three files is referenced.

## Prioritised list

1. **CommandManagerTest.kt:166-236 (5 tests)** - extract a recorder helper. Each test repeats `val events = mutableListOf<Triple<String, NotificationType, Long?>>()`, `CommandManager(this) { msg, type, ms -> events += Triple(msg, type, ms) }`, `advanceUntilIdle()`. Add a private class `Recorded(val manager: CommandManager, val events: List<Triple<...>>)` plus `private fun TestScope.recordingManager(): Recorded` (builds, advances, returns). The no-callback tests at :239, :249, :270, :277 (and `CommandManager.create` at :258) can use a sibling `TestScope.idleManager(): CommandManager`. This also lets `notice(...)` be typed once. Cost: S.
2. **CommandManagerTest.kt:13-27 vs CommandSystemRegistryTest.kt:13-21** - two near-identical private `EditorCommand` factories (`command` vs `cmd`) and a duplicated `NOT_AVAILABLE` const (:27 / :21). Same package, so move one shared `internal fun testCommand(id, type, label, config, condition, execute)` and `internal const val NOT_AVAILABLE` into a new `CommandTestFixtures.kt` in this test package. Caveat: differing defaults (`execute` returns `Success()` vs `Success("ok")`; `cmd` has no `condition`); either unify the default or keep the explicit lambdas at the few call sites that check `"ok"`. If kept private, same-package duplicate top-level private names do not clash, so this is safe but still duplicated. Cost: S.
3. **Context fixtures spread across files** - `SELECTION` (CommandManagerTest.kt:33) is identical to `CSEL` (EssentialCommandsTest.kt:11). Put one in the shared fixtures file (item 2), and give them readable names (`C0`, `CSEL`, `CBLOCK`, `CBAD`, `PALETTE` at EssentialCommandsTest.kt:10-14 are cryptic: `EMPTY_CONTEXT`, `SELECTION_HELLO`, `BLOCK_CONTEXT`, `OUT_OF_BOUNDS_SELECTION`, `PALETTE_CONTEXT`). Cost: XS (rename) + XS (dedupe).
4. **CommandManagerTest.kt:147-161** - the `var runs = 0` + `execute = { runs++; CommandResult.Success("ok") }` pair appears twice; fold into a tiny `countingCommand(config)` returning the command and a `() -> Int` reader, or just keep (low value). Cost: XS, optional.
5. **CommandManagerTest.kt:110-145** - 512-case truth-table test is long (35 lines) with 9 nested `for` loops and a manual `checked` counter. Extract `private fun combos(n: Int): Sequence<List<Boolean>>` and destructure, replacing the nested loops and the `kibitzer:ignore deep-nesting` waiver, and assert `combos(9).count() == 512` instead of the mutable counter. Cost: S.
6. **CommandManagerTest.kt:91-108** - `isAvailable_should_BeFalse_When_AnyOneOfThreeRequirementsIsMissing` and `..._BeTrue_When_AllThreeRequirementsPresent` build the same `cmd` and full context; share a `val full` and `allRequired` config as a class-level private val, and merge the true case into the false test as its first assertion. Cost: XS.
7. **EssentialCommandsTest.kt:158-175** - four copy-pasted `run(...)` + two asserts; convert to the same `listOf(Triple(...))` loop already used in `systemCommands_should_ReturnActionKeys` (:186-198). Note `search` also asserts `query == ""`; keep that one separate. Cost: XS.
8. **EssentialCommandsTest.kt:135-150** - `blockCommands_should_EchoBlockIdOrEmpty` encodes the optional extra as `("position" to "after")` / `null` pairs and a trailing `if (extra != null)`; make `extras` a `Map<EditorCommand, Pair<String,String>?>` or two lists (with extra / without) to drop the nullable-pair indirection. Also `run(command, CBLOCK)` executes twice per command. Cost: XS.
9. **Naming**:
   - CommandSystemRegistryTest.kt:29 `getCommand_should_ReturnRegistered_And_NullForUnknown`, :49 `unregister_should_RemoveExisting_And_NotThrow_When_Unknown`, :61 `registerAll_should_RegisterEach_And_AcceptEmptyList`, :185 `clearHistory_should_Empty_And_Delegates_Should_ReachRegistry` each fold two behaviours (and :185 has a grammatical "Should" in the middle). Split :185 into `clearHistory_should_EmptyHistory` and `getCommand_And_getAvailableCommands_should_DelegateToRegistry`; the others are acceptable but split if you want one-reason-to-fail tests. Cost: XS-S.
   - CommandManagerTest.kt:35 doc says "through the real essential commands" but the `isAvailable` tests (:41-145) use synthetic commands; reword the KDoc. Cost: XS.
10. **CommandSystemRegistryTest.kt** - `CommandRegistry()` + `registerAll(...)` + `CommandSystem(registry)` setup repeats in ~8 tests (:94-199); add `private fun systemOf(vararg commands: EditorCommand): Pair<CommandRegistry, CommandSystem>` or just `systemOf(...)`: CommandSystem` where the registry is not needed afterward. Also `CommandContext()` is passed to `executeCommand` ~10 times; a private `private val CTX = CommandContext()` removes noise. Cost: S.
