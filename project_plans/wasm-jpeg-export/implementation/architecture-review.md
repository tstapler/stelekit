## Concerns
- [ ] **Story 3.1.2 / Epic 4.1 (Story 4.1.1)** — The riskiest new code in this plan — the first-ever `ByteArray`↔JS bulk-binary interop in the repo (per ADR-001's own "Consequences" section) and the exact "6M interop calls" risk `requirements.md` calls out — has its only automated verification path (`getImageData` round-trip, Story 3.1.2's own AC) routed through `wasmJsTest`/Karma in Story 4.1.1, which Phase 4 explicitly marks a stretch goal, downgradable to "known gap" per Task 4.1.1b if Karma proves flaky (a real, plan-sanctioned outcome, not hypothetical — `research/pitfalls.md` §6 already flags zero prior `wasmJsTest` track record). If Phase 4 is skipped, Epics 3.1 and 3.2 ship with zero regression coverage beyond `flattenToOpaqueRgba`'s pure-function tests. — **Remediation**: either make a minimal Story 4.1.1 smoke test a merge gate (even a flaky one beats zero coverage on a first-of-its-kind interop path), or, if the stretch-goal framing stands, shrink the untestable surface per the next finding so at least the non-`js()` logic has fast coverage.
- [ ] **Task 3.1.3b (`isJpegDataUrl` / `stripJpegDataUrlPrefix`)** — Both are pure `String` functions with no JS dependency, yet the plan places them in `wasmJsMain/.../ImageEncoderInterop.kt`, so they're reachable only via the stretch-goal `wasmJsTest` (see above), never via fast `commonTest`. They also each hardcode the literal `"data:image/jpeg;base64,"` independently — two copies of the same magic string with nothing enforcing they stay in sync (Task 3.1.3a's `canvasToDataUrl` call site is a third place `"image/jpeg"` appears). — **Remediation**: move these two functions (and the `quality.coerceIn(0, 100)` clamp, already duplicated from `ImageEncoder.jvm.kt:31`) into a plain-Kotlin file with no `js()` calls so they're `commonTest`/`jvmTest`-reachable; better, collapse the pair into one `parseJpegDataUrl(dataUrl: String): ByteArray?`-shaped function (Parse-Don't-Validate: validate-and-extract in one step, one copy of the prefix constant) per the `type-driven-design` lens.
- [ ] **Observability Plan vs. Task 1.1.2a** — The Observability Plan states failure detail is carried "further up via `bakeAndEncode()`" into `Left(EncodingFailed)`, but Task 1.1.2a's actual code sketch constructs `EncodingFailed` with a hardcoded generic string (`"JPEG encode returned no bytes"`), not the real platform-specific cause. The actual JS exception message (or which internal guard produced the empty array) is logged via `println` in `ImageEncoder.wasmJs.kt`'s catch block and never reaches the `Either` at all — it's console-log-only, exactly as JVM/Android's existing `catch (e: Exception) { ByteArray(0) }` already is. This is a genuine, foreseeable diagnostics gap on the plan's newest, highest-risk platform, and the plan's own two sections disagree about it. — **Remediation**: this is a docs-only fix, not a design change — correct the Observability Plan's wording to state plainly that per-cause diagnostic detail is console-log-only and does not reach `EncodingFailed.message` (ADR-002's chosen boundary makes this an accepted, pre-existing-pattern trade-off, not a new regression — it just needs to be described accurately).

## Nitpicks
- Task 3.1.1a's "throwaway probe function" has no paired cleanup task; add a one-line reminder to remove the spike code once the marshaling question is resolved, so it doesn't linger in `ImageEncoderInterop.kt`.
- Task 3.2.1a's `encodeToJpeg` packs guard clause + pixel flatten + 4-step canvas interop + MIME check + base64 decode + `try`/`catch` into one expression-bodied function (~10 logical steps). Given this file can't be stepped through with a JVM debugger, consider named intermediate `val`s (already implied by the prose) to make each step loggable independently during the Task 3.1.1a/2.1.1d empirical spikes.
- Once the Observability Plan wording is corrected (see Concern 3), add a one-line KDoc caveat on `DomainError.ExportError.EncodingFailed` noting its `message` is a fixed literal from this call site, not a propagated platform error string — avoids a future reader assuming otherwise.
