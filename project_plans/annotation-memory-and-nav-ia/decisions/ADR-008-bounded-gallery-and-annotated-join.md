# ADR-008: Gallery reads and the Files "Annotated" badge are bounded (paged / chunked IN)

**Status**: Accepted (amended 2026-11-08 for the ADR-006 merge decision) | **Date**: 2026-11-08

## Context
`GalleryViewModel` collects `getAllImageAnnotations()` as a standing unbounded flow (architecture.md headline 4; VERIFIED path `ui/gallery/GalleryViewModel.kt`), contradicting CLAUDE.md "graph-scale reads must be paginated, projected, or chunked". The "Annotated" badge on Files needs an asset-to-annotation lookup (ux.md option C), which must not become an O(graph) join.

## Options
1. Keep the unbounded flow (rejected: GC thrash and OOM class at 8,000+ rows).
2. **Page Gallery with `getImageAnnotations(limit, offset)` (+ tag-filtered variant), page size <= 100, and look up annotation status for the visible Files page only via a chunked `IN` query (<= 500 keys).**
3. SQL JOIN inside the asset query. Weakness: couples two repositories and complicates paging.

## Decision
Option 2. New queries are read-only so `RestrictedDatabaseQueries` stubs are not needed; adding them to `SteleDatabase.sq` still requires regenerating `kmp/src/generated/sqldelight/` (CLAUDE.md "MANDATORY" step). No new table, so no `MigrationRunner` entry. `QueryPlanAuditTest` covers the new queries; a `LargeGalleryBatchingTest` mirrors `LargeGraphWarmStartCrashTest`.

**Amendment (repair pass, 2026-11-08)**: sorting per `GallerySortOrder` and tag aggregation move into SQL (`ORDER BY`, bounded `getDistinctAnnotationTags()`), and any index they need is a `MigrationRunner` entry (task D.7c); "no new table" does not imply "no migration".

**Amendment (2026-11-08, ADR-006 DECIDED: merge)**: the Gallery and the Assets browser are now one Library screen, so the bounded read is one paged query (limit <= 100) over the asset index with the annotation state (`annotated`, measurement count) **joined at query level** (an `EXISTS` / aggregate sub-select against an index on the annotation image key; a `UNION ALL` branch for annotations without an asset row if spike D.7a-0 finds any). This supersedes option 2's "chunked `IN` lookup for the visible Files page": there is no separate lookup, hence no per-item or per-page N+1, and one query per page is a test assertion. Filters (Annotated, media type, Orphaned, tag, search) and the four sort orders are in the same SQL, and paging is **keyset** (see Defaults 3), not `OFFSET`; tag chips come from a bounded `getDistinctAnnotationTags()` projection; the status-line count is a debounced `countLibrary(query)`. Every Flow-backed read ends in `catchDbError`. Indexes for the join key and each sort/filter path are `MigrationRunner` entries (task D.7c). The CLAUDE.md graph-scale rule stands: no unbounded `getAll`, no standing whole-table observer.

## Consequences
- Applies to the merged Library (the earlier note that the screen might later be merged is overtaken: the merge is decided).

## Defaults - owner may override: Library filter, sort and search semantics (Repair 4, final form Repair 5, 2026-11-08)

These fix the semantics so `LibraryFilterRulesTest`, `LibraryScreenFilterTest`, `LibraryAnnotatedJoinTest`, `LibraryFilterSqlParityTest` and the D.7a queries share one definition. Rationale and UI behaviour: `design/ux.md` LD-1..LD-20 (the ux.md rows are the source; this list restates them at repository level). Each item can be overridden at the task named in ux.md.

1. **Groups (LD-1)**: Type is multi-select with OR inside the group; Show (Annotated, Orphaned) and Tags (multi-select, OR) are separate conditions; groups and search combine with AND. No "All" chip. Type membership is the `AssetMediaType` table of LD-11 (Images = IMAGE, PDFs = PDF, Audio = AUDIO, Video = VIDEO, Docs = DOCUMENT, Other = FILE or any other stored value).
2. **Contradictions (LD-1)**: prevented in `LibraryFilterRules` (pure, commonMain) by dimming: a non-image Type chip and Annotated/tag chips dim each other. Annotated with Orphaned is **not** a contradiction (LD-16). `normalize(state)` drops conflicts from restored or deep-linked state. The repository assumes a normalized `LibraryQuery`; an unnormalized one returns an empty page rather than an error.
3. **Sort and paging (LD-2)**: Recently added is the default; the two annotation sorts put unannotated items last; Name A-Z is ASCII case-insensitive. **Keyset paging**: each sort has a non-null key tuple ending in the item id (Recently added `(imported_at_ms DESC, item_id DESC)`; Recently annotated `(COALESCE(last_annotated_at_ms,-1) DESC, imported_at_ms DESC, item_id DESC)`; Most measurements `(annotated DESC, measurement_count DESC, imported_at_ms DESC, item_id DESC)`; Name A-Z `(lower(file_name) ASC, item_id ASC)`), and a page request carries the previous page's last key tuple as an expanded lexicographic predicate (no row-value syntax). An item present for the whole scroll is returned exactly once; items added or removed mid-scroll show on the next refresh.
4. **Search (LD-3, LD-7)**: tokenise the trimmed query on whitespace and on the separator set `_ - . , / " [ ]` (max 5 tokens); at least 2 characters (1 character = no search, hint; 0 = unfiltered); every token must be a **word-prefix match** in the file name, an annotation tag or an annotation label (tokens may match different fields); ASCII case-insensitive (SQLite `LIKE` without ICU; non-ASCII letters match with exact case); `%` and `\` literal via `ESCAPE '\'`; 300 ms debounce; no page names, no file contents.
5. **Search SQL shape (LD-7)**: for each token `:pi = '% ' || esc(token) || '%'` (Kotlin-built), `hay(x) = ' ' || REPLACE(...x mapped by the separator set to spaces...)`, predicate `(:pi IS NULL OR hay(file_name) LIKE :pi ESCAPE '\' OR EXISTS (annotation row of the item with hay(tags) LIKE :pi ESCAPE '\') OR EXISTS (annotation row joined to measurement_annotations with hay(label) LIKE :pi ESCAPE '\'))`. `tags` is the JSON text column of `image_annotations` (`'["a","b"]'`), whose punctuation is in the separator set, so no `json_each` is needed. The pattern starts with `%`, so the search path is a bounded LIMITed scan of the filtered range, allowed in `QueryPlanAuditTest` for this path only; no FTS table is added (a new FTS table would be a `MigrationRunner` entry and a write path to keep in sync, judged out of proportion for a 100-row page; revisit if D.7a-0 measures the scan above the frame budget on the 8,030-row fixture). Any other index the audit shows missing is a `MigrationRunner` entry (D.7c). The existing asset search (`SteleDatabase.sq`, `file_path LIKE :query ESCAPE '\'` with a caller-built pattern) uses the same escaping convention.
6. **Count (LD-5)**: `countLibrary(query)` uses the same `WHERE` without ordering or keyset predicate, as `SELECT COUNT(*) FROM (SELECT 1 ... LIMIT 10001)`, displayed "10,000+" above 10,000.
7. **Measurement count and multi-page images (LD-15)**: one card per asset; `measurementCount` is the sum over all annotation rows of the asset.
8. **Persistence (LD-4)**: filters and search are session state (restored after process death, reset on a fresh launch); the sort order is a persisted preference (`libraryDefaultSort`). The scroll anchor restore (LD-19) loads pages from the top until the anchor id is found, at most 10 pages.
9. **Verification**: `LibraryFilterSqlParityTest` (businessTest) asserts that the in-memory reference filter and the SQL return the same ids in the same order on random item sets and normalized states, including the dedicated search cases (multi-word, `%`/`\` literals, 1 character, ASCII case, non-ASCII case, separators, multi-field tokens) and paging by keyset across 8,030 rows with no repeat or skip; `QueryPlanAuditTest` covers each sort order, each filter and their common combinations (task D.7a).

## Amendment (2026-11-09, Epic D implementation): spike D.7a-0 results and what shipped

Answers to the D.7a-0 questions, from the implementation (`repository/LibrarySql.kt`, `repository/LibraryRepository.kt`, `LibraryFilterSqlParityTest`, `QueryPlanAuditTest`, `LibraryE2ETest`):

- (a) **Join key**: `asset_index.file_path = image_annotations.file_path` (both absolute paths under `<notes>/assets/`: `ImageImportService.reservePath` for annotations, `AssetIndexService` for the index; INFERRED from the code, not yet checked against a real graph's two tables). The join is a set of correlated sub-selects on the new index `idx_image_annotations_file_path` (`SteleDatabase.sq` and `MigrationRunner` entry `idx_image_annotations_file_path`, with `ANALYZE`).
- (b) **Annotations without an asset row**: not found in fixtures, not measured on a real graph. The `UNION ALL` branch is **not implemented**; such rows do not appear in Library until the asset index has them (`LibraryAnnotatedJoinTest.annotationWithoutAnAssetRow_isNotInTheAssetBackedList` pins the behaviour). Open item: measure on a real graph before the old Gallery screen is deleted.
- (c) **File name**: no column; the basename comes from `file_path` with `REPLACE(file_path, RTRIM(file_path, REPLACE(file_path, '/', '')), '')`.
- (d) **Last annotated at**: `MAX(image_annotations.imported_at_ms)` for the asset's annotation rows (there is no update time).
- (e) **Search plan**: bounded by `LIMIT`; the default sort reads `idx_asset_imported_at` with an incremental tie-break sort, the annotation sorts and Name A-Z scan the asset index once per page (annotation tables are only reached through indexes, asserted by `QueryPlanAuditTest.library paged queries reach annotations only through an index`). Timings on 8,030 rows are printed by `LargeLibraryBatchingTest` (`LIBRARY_QUERY_TIMINGS`). No FTS table.
- (f) **Two drivers**: the `REPLACE`/`RTRIM`/`LIKE ... ESCAPE` predicate returns the expected rows on the JVM driver (`LibraryFilterSqlParityTest`) and on the Android driver on the Pixel_Fold AVD (`LibraryE2ETest.wordPrefixSearchWorksOnTheAndroidDriver`).

Deviations from the text above:

- **Per-request SQL, not generated queries.** The SQLDelight dialect used here (`sqlite_3_18`) cannot parse `REPLACE()` ("result column expected, got REPLACE"), and one fixed text per sort would carry every optional predicate. `LibrarySql` therefore builds the page and count statements per request and runs them through the driver; only the index and the bounded tag projection (`selectAnnotationTagSets`) are in `SteleDatabase.sq`. Reads are suspend functions returning `Either`, with `try/catch` instead of `catchDbError` (they are not Flows).
- **Tag filter**: up to 5 tags (OR), `LIKE '%"tag"%'` against the raw `tags` text. `SqlDelightImageAnnotationRepository` writes tags as raw `["a","b"]` without JSON escaping, so a tag containing `"` or `\` is stored corrupt (pre-existing; a quote breaks the JSON, a backslash makes `tagsList` fail to parse). Not fixed here.
- **Count**: `SELECT COUNT(*) FROM (... LIMIT 10001)`, shown as "10,000+".
