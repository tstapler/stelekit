## Blockers

- [ ] **C.5 (AnnotationPersistenceQueue), C.5c, Tech Debt Disposition table** — VERIFIED violation, missing from the disposition table. `SqlDelightMeasurementAnnotationRepository.saveMeasurementAnnotation` / `saveMeasurements` (`kmp/src/commonMain/kotlin/dev/stapler/stelekit/repository/SqlDelightMeasurementAnnotationRepository.kt:39-80`) call `queries.insertMeasurementAnnotation` and `queries.transaction` directly under `withContext(PlatformDispatcher.DB)`. They are annotated `@DirectRepositoryWrite`, which `DirectRepositoryWrite.kt:5-10` defines as a compile-time ERROR opt-in meaning "must go through DatabaseWriteActor to prevent SQLITE_BUSY". `AnnotationEditorViewModel` opts in at lines 507, 597, 642, 703, 716, 736 and 847. `research/architecture.md` section 4 ("obeys the DatabaseWriteActor rule") and section 2 ("-> DatabaseWriteActor") are wrong about this. The plan builds a new queue on top of the bypass, moves the opt-in into one class (C.5 AC 5), and only "evaluates" actor routing in C.5c "if no schema change is needed". The actor already has a generic `execute { }` (`DatabaseWriteActor.kt:763`), and routing needs no schema change. CLAUDE.md says "Route writes through `DatabaseWriteActor` (preferred)". Lens 4 rule: a known violation in a touched area with no disposition row is a blocker. — **Remediation**: (a) Add a disposition row, "`SqlDelightMeasurementAnnotationRepository` direct writes: Refactor-first". (b) Make C.5c a refactor task sequenced before C.5b. It wraps the two write methods in `actor.execute {}` (or adds typed actor methods) and injects the actor into the repository. The queue then calls the repository and never opts into `DirectRepositoryWrite`. (c) Change C.5 AC 5 to "no `DirectRepositoryWrite` opt-in remains in `ANN/`". (d) Correct `research/architecture.md` sections 2 and 4.

- [ ] **All commonTest-placed tests (A.2, C.1, C.2, C.10, D.2, D.5, A.5 `ImageSamplingTest`)** — Bazel wiring gap. Plan section "Cross-cutting rules" says tests run under `bazel test //kmp:business_tests`. But commonTest is not globbed into `business_tests`. `kmp/src/commonTest/kotlin/BUILD.bazel:104-133` (`business_common_tests`) is an explicit `srcs` list, and each class must also be registered in `AllBusinessTests` (guarded by `AllBusinessTestsCompletenessTest`). The plan has about 10 new commonTest classes (`ExitRecordFormatterTest`, `ProcStatParserTest`, `CalibrationDecodeInvarianceTest`, `LoupeLayoutPropertyTest`, `AreaCloseTolerancePropertyTest`, `NavModelCoverageTest`, `NavSectionBuilderTest`, `NavCommandsTest`, extended `ImageSamplingTest`) and no task lists `BUILD.bazel` or `AllBusinessTests.kt`. Result: the tests are silently skipped under Bazel (the repeat of the "businessTest suite gap" in MEMORY.md) or fail the completeness guard. — **Remediation**: add the `commonTest/kotlin/BUILD.bazel` `business_common_tests` entry and the `AllBusinessTests.kt` registration to the Files list of every task that adds a commonTest class. Add an explicit verification step: `bazel test //kmp:business_tests` must report the new class names. Alternatively place pure-logic tests in `businessTest` (globbed) and keep commonTest only where multi-target runs matter.

## Concerns

- [ ] **A.2c, Story A.2 AC 3 (trim memory with a level)** — `MemoryPressureListeners` (`kmp/src/commonMain/kotlin/dev/stapler/stelekit/ui/MemoryPressureListeners.kt:17-37`) is `register(listener: () -> Unit)` and `notifyListeners()`. It carries no trim level, so "deliver `RUNNING_CRITICAL`" cannot be expressed. The plan treats the file as a small edit. Changing the signature touches `StelekitViewModel.onMemoryPressure`, the asset pipeline listener and `MemoryPressureListenersTest`. — Add a task "extend fan-out with a typed `MemoryPressureLevel` (commonMain enum), keeping the no-arg overload". Disposition: Extend, and list the existing callers and test.

- [ ] **A.2d (`EditorDiagnosticsSampler` in androidMain)** — The sampler needs `undoDepth`, tool, screen and image dimensions from the commonMain ViewModel, and the plan does not say how they are wired. Android code must not reach into the VM, and a commonMain-to-androidMain dependency can only be an interface. — Define `EditorDiagnosticsSource` / `EditorDiagnosticsSink` (interface, commonMain) implemented by the VM's read-only view. Inject the Android sampler through `ScreenRouter`/`AnnotationEditorScreen` parameters, as the haptic callback is injected. Add this to A.2d's Files list.

- [ ] **A.5b / ADR-003 (`LoupeRegionDecoder` as expect/actual)** — `expect` requires an `actual` on every target (android, jvm, wasmJs, iOS). A.5b and the Files list name only AM and jvmMain actuals and prose "fallback"; no iOS/wasm actual files are listed. ImageIO region decode on JVM and `BitmapRegionDecoder` also have different EXIF behaviour. — Prefer a commonMain `fun interface LoupeSource` with an Android implementation (and optionally JVM) injected from the platform shell. The default is the cached-bitmap strategy, so no `expect` is needed. If expect/actual is kept, list all four actuals.

- [ ] **C.1b (`ImageBounds` / `NativeImageSize` "expect/actual")** — The Files list has `ImageBounds.android.kt` and `ImageBounds.jvm.kt` but no commonMain declaration and no wasm/iOS actuals. Grep finds no existing `ImageBounds`. `ExifOrientationReader` and `OrientationTransform` already exist in commonMain (`platform/image/ExifOrientationReader.kt`). — Make the orientation-swap rule pure in commonMain (`NativeImageSize.oriented(w, h, exifOrientation)`, property-tested). The platform part is a small `fun interface ImageBoundsReader` returning raw (w, h, orientation). Parse at the boundary and hold `NativeImageSize` in the ViewModel as a nonzero-positive value type rather than raw `Int`s.

- [ ] **D.7 / D.7b / ADR-008 (paged Gallery)** — `GalleryViewModel` sorts and aggregates tags in memory over the full list (`GalleryViewModel.kt:89-91,115-120`: `sortImages`, `availableTags` from `images.flatMap { it.tags }`). Paging at 100 rows breaks both sort order and the tag chip list. Neither the story nor the ADR has a sort-in-SQL query or a tag projection. — Add to D.7a: `ORDER BY` per `GallerySortOrder` in the paged queries (index-backed, audited in `QueryPlanAuditTest`), and a bounded `getDistinctAnnotationTags()` projection. Add a "load more" or paging-state type to `GalleryState`.

- [ ] **D.6a (Files "Annotated" badge lookup)** — The join key between an `Asset` and an `ImageAnnotation` is never stated. Say which column and which repository the chunked `IN` query uses and who owns it. The query sits in `ImageAnnotationRepository` but the keys come from `AssetRepository`, so the repository ends up coupled to asset identity. — State the key (for example an image path or uuid column on `image_annotations`) and the query signature `getAnnotatedKeys(keys: List<String>): Either<DomainError, Set<String>>`. Add `catchDbError` equivalence and an `UpgradeResilienceTest` entry for any new Flow-backed read.

- [ ] **C.8c, C.9c, C.1b, B.2c (VM growth)** — The Tech Debt row says "VM only delegates", but C.8c places crosshair/nudge state logic behind `BT/CrosshairPlacementTest`, and C.9c, C.1b and B.2c add more VM members. That adds methods to a 1,049-line `@Suppress("LargeClass")` ViewModel (`AnnotationEditorViewModel.kt`). The research recommended isolating via seams, and this deepens the violation. — Extract `CrosshairPlacementState` (pure, commonMain) as C.8c's class and have the VM hold one field. Cap net VM line growth for Epic C: track `wc -l` in the PR and gate on "no net growth".

- [ ] **ADR-005 vs Cross-cutting rules (scope ownership)** — ADR-005 says the queue "is owned by the editor scope". Cross-cutting says `UndoHistory` and `AnnotationPersistenceQueue` "own their scopes internally". `UndoHistory` is a pure data structure and needs no scope. A second scope would split cancellation and the `CoroutineExceptionHandler`. — Decide: the queue takes no caller scope and creates `CoroutineScope(SupervisorJob() + Dispatchers.Default + handler)` itself with an explicit `close()` called from the VM's `onCleared`/dispose. Strike `UndoHistory` from the scope-owner claim.

- [ ] **A.3 / ADR-002 (`uiautomator` dependency and Bazel)** — The `uiautomator:2.3.0` dependency is added to `kmp/build.gradle.kts` `androidInstrumentedTest` (currently `kmp/build.gradle.kts:392-406` has none; only `macrobenchmark/build.gradle.kts:86` has it). Instrumented work is correctly Gradle-only, but note that the `AM` `MoreSheet`, probe and sampler must still compile under the Bazel `android_main` target. `ProcStatParser` and the diagnostics sources need no new Bazel dependencies, but `MoreSheet.android.kt` and the sampler need Bazel `kt_android_library` deps checked (`bazel build //kmp:android_app --config=android` in CI). — Add `bazel build //kmp:android_app --config=android` to each Android-source task's verify step.

- [ ] **D.4 (MoreSheet)** — Sheet open/close state must live in commonMain (`AppState` or the ViewModel) because `GraphContentStatusAndBottomBar.kt` (commonMain) triggers it and `MoreSheet.android.kt` renders it. `toggleSidebar()` (`StelekitViewModel.kt:1882`) is the existing mechanism. A parallel boolean is not named. — Specify `AppState.moreSheetOpen` + `StelekitViewModel.setMoreSheetOpen`, and an expect/actual (or composition-local) slot for the Android renderer; desktop keeps the sidebar.

- [ ] **Test placement (A.4, B.2)** — `ImageLoaderConstructionCountTest` and `CoilSeamTest` are jvmTest "pure seam" tests. Coil 3 and `buildSteleKitImageLoader` are commonMain, and CLAUDE.md says logic with no platform API goes to commonTest (businessTest). `jvmTest` needs `scripts/jvm-display-check.sh` and gives no signal on a Wayland-only machine. — Place them in `businessTest` unless a real renderer is required.

- [ ] **Epic ordering (AnnotationEditorScreen/VM serialization)** — The plan acknowledges six tasks serialized on `AnnotationEditorViewModel.kt` and five on `AnnotationEditorScreen.kt` but gives no merge-conflict mitigation. Several of these (C.3b, C.5b) change behaviour that A.4/A.5 benchmarks measure. — Pin one owning agent per file per wave, or sequence C.3/C.5 behind B.5c so "before" numbers come from the unmodified code.

## Nitpicks

- `CM/ui/annotate/LoupeLayout.kt` (C.2a) overlaps the existing `LoupeGeometry.kt` (`loupeInnerOffset`). Put `clampLoupeOffset` in the existing file or document the split.
- Glossary says `NavDestinationSpec` carries `icon` while the ADR calls the model "pure". Hold an icon key (enum) and map to `ImageVector` in the renderer so the model stays platform-free and property-testable.
- `NativeImageSize` is placed in `CM/model/`. It is an image value type, so `platform/image/` or `ui/annotate/` fits better than the page/block domain package.
- ADR-001 initial gate "post-gesture idle CPU % < 10" is listed as a hard gate, but B.5b says sustained CPU is report-only until calibrated. Make the ADR and B.5b agree on which CPU metrics start as `Gate`.
- B.4a "Output-channel spike" is a prerequisite for B.3/A.3 scenarios producing any output. The dependency graph shows B.4 parallel to B.3, so move B.4a into wave W-A or W-B.
- ADR-004 and ADR-006 remain `Proposed`/pending; this is acceptable because of the explicit C.1a and D.1 gates.
