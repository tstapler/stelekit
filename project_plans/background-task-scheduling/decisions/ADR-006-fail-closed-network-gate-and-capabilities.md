# ADR-006: Fail-closed network gate, capability-driven disabled options, androidx.work stays at 2.9.1

**Status**: Accepted (implemented; Android 14/15 foreground-service limit numbers remain unconfirmed, plan Task 4.1.2d; standby and OEM behaviour is PENDING OWNER device runs)
**Date**: 2026-11-10

## Decision
- `NetworkGate.evaluate(policy, online, isMetered: Boolean?)` is pure and three-valued. `Unmetered` runs only when `isMetered == false`; `true` and `null` skip with `MeteredNetwork` / `UnknownNetwork`. The generic `TaskWorker` runs it before `task.run`, so a skipped tick makes no network or git call. The existing LFS `?: false` default is not reused. A skip is not a failure and does not trigger backoff.
- The WorkManager constraint (`NetworkType.UNMETERED`) is evaluated by the system (JobScheduler/WorkManager), not through `NetworkMonitor`; the live check in `TaskWorker` reads `NetworkSnapshotProvider` (`ConnectivityManager`). They are deliberately two different signals, which is why the `null` rule below exists. Copy says "Unmetered networks only".
- Cold-process signal (repair loop 1): the worker gets `online`/`isMetered` from a single `NetworkSnapshotProvider` (androidMain implementation over `ConnectivityManager`, built from the worker `Context`, also used by LFS). A provider that throws or returns `isMetered == null` yields `Skip(UnknownNetwork)`, never proceed. `NetworkGate.evaluateMetered(policy, isMetered)` is the explicit helper (`online = true`) for callers with no online signal.
- `null` still fails closed even when WorkManager already verified `UNMETERED` (the two signals can differ, e.g. `SecurityException` in `AndroidNetworkMonitor.kt:69-74`). For periodic work the next period retries; for one-shot work the skip becomes bounded `Result.retry()` then terminal `failure` carrying the error in output data (ADR-004; skips and real failures share one `runAttemptCount` budget), so a one-shot is never reported successful without running.
- `SchedulerCapabilities(minIntervalMinutes, minFlexMinutes, supportsUnmetered, supportsCharging, supportsBatteryNotLow, supportsJitter, runsInBackgroundWhenClosed)`. Desktop: `supportsUnmetered = false`, `supportsCharging = false`, `runsInBackgroundWhenClosed = false`; the UI shows those options disabled with a reason. iOS/Web `Noop`: everything false.
- `BackgroundRestrictionProbe` returns a `RestrictionReason` enum (None, BatterySaver, AppRestricted, StandbyRestricted); `isRestricted()` stays as a derived helper. The probe cannot see Rare/Frequent buckets or OEM killers, so "no hint" never means "on time".
- androidx.work stays 2.9.1 (and `work-testing` 2.9.1). Spike 0.1.1 (ADR-002) confirmed `WorkInfo` readback of constraints, flex, initial delay and `nextScheduleTimeMillis` on 2.9.1, and found `ListenableWorker.setNextScheduleTimeOverride` ABSENT from 2.9.1 (`javap`); the earlier claim that 2.9.0 has it did not hold for 2.9.1. No bump is needed because that API is not adopted (ADR-002); it would be a separate change only if per-run jitter from inside the worker is wanted later. A 2.12.0 bump is not part of this plan; it is a separate change only if Spike 0.1.1 finds a blocking gap.
