## Test Stack
- **Framework**: `kotlin.test` (`@Test`, `assertNotNull`, `assertEquals`) + `kotlinx-coroutines-test` is present in the file's imports for the untouched `test progressive loading phases` test, but the three rewritten/reference midnight-watcher tests deliberately use `runBlocking` (real `Dispatchers.Default` + wall-clock `delay`), not `runTest`'s virtual-time scheduler — per plan.md's Pattern Decisions table, because `startMidnightBoundaryWatcher` shares `StelekitViewModelDependencies.scope` with ~20 other infinite `init`-time collectors, and putting that scope under `TestCoroutineScheduler` risks `advanceUntilIdle()` hanging forever.
- **Fakes**: `FakeClock`, `InMemoryPageRepository`, `InMemoryBlockRepository`, `InMemorySearchRepository` (all pre-existing, `kmp/src/jvmTest/kotlin/dev/stapler/stelekit/testing` and `dev/stapler/stelekit/repository`). No mocking library is introduced or needed — `JournalService` is exercised as a real concrete instance per requirements.md's "Existing reference implementation" section.

## Coverage Targets and How to Measure
- `./gradlew jvmTest --tests "dev.stapler.stelekit.db.GraphLoaderProgressiveTest"` must exit 0 (AC-05).
- `grep -n "while (isActive)" kmp/src/jvmTest/kotlin/dev/stapler/stelekit/db/GraphLoaderProgressiveTest.kt` must produce no output (AC-02 verification, per plan.md Task 1.1.5a).
- No line-coverage percentage target applies — this is a test-only change with no new production lines to cover.

## Known Coverage Gaps (carried from adversarial-review.md)
- **"delay call removed" is not caught by any test in this file** (including the pre-existing, untouched reference test at line 841). If `delay(delayMs)` at `StelekitViewModel.kt:1976` were deleted, the loop would busy-spin instead of waiting but would still converge to the same final repository state that every outcome-based polling assertion checks for. This is a pre-existing limitation of the repository-polling observation strategy, not something introduced or worsened by this rewrite — AC-01 should not be read as fully closed against that specific mutation.
- **`FakeClock.instant` is a plain (non-`@Volatile`) `var`** read cross-thread (test thread writes via `advance()`, the `Dispatchers.Default` watcher coroutine reads via `now()` on a different OS thread), with no JMM-guaranteed visibility. This rewrite triples exposure to that risk (1 real-path test → 3). It "happens to work" only incidentally via thread-pool dispatch ordering; a one-line `@Volatile` fix in test-only `FakeClock.kt` was recommended but is not itself an acceptance criterion of this change.
- **The guard test's negative-assertion window (Task 1.1.3a) has ~400ms of margin** (`delay(1200)` against a nominal ~1000ms watcher wake-up), the thinnest of the three rewrites, versus the 8000ms budget given to the positive second-crossing poll. A false failure isn't expected (the page really is absent either way), but this is the first knob to widen if the suite proves flaky under CI load.
- **Story 1.1.4's try/finally wrap of the reference test (line 841) makes AC-06 weaker than a true "untouched baseline" check** for that specific test — non-regression rests on the plan's "purely additive cleanup" reasoning rather than an unmodified diff.
