# ADR-006: The digest is a dedicated OWNED page: created as a new file, replaced under an owned-file contract through a separate `OwnedPageWriter` interface

Status: PROPOSED (blocked on owner decision OD-H7, the scoped exception to the CLAUDE.md rule "never re-render an existing file"; Story 5.1 measures the cost; amended by plan review patch 3) | Date: 2026-11-09 | Epic: E5

## Context
CLAUDE.md: cross-graph writes go through `TargetWriterRouter` under `GraphWriteLock`; off-graph writes only splice; "never re-render an existing file". Verified in code (reviews round 1 and 2):
- `SpliceRequest` has only appended `BlockInsertion`s; `RoundTripGuard.verifyBytes` requires the original to be a subsequence of the output, so any replacement of an existing block fails by construction.
- `TargetWriter` has `write`, `deletePageFile`, `fileHash`, `removeBlocks`, `readExisting` and no replace; `ActiveTargetWriter.write` refuses `ExistingContentChanged` when a block differs.
- `ActiveTargetWriter` is a RE-RENDERING writer: it serialises through `LogseqPageSerializer` and `GraphWriter.savePage` (and renders with `properties = emptyMap()` because page properties are re-read as a first block), and `TargetWriterContractSuite` compares BLOCK DATA, not bytes. `MarkdownTargetWriter` is byte-faithful. So no byte-level or CRLF criterion can be required of the Active writer, and a body hash over file bytes would flag a false `EditedByUser` after any re-save.
- `TargetWriter` has 14 implementors, fakes and wrappers (4 production, 10 in tests; counted by grep) (production: `ActiveTargetWriter`, `MarkdownTargetWriter`, `RoutedTargetWriter`, `capture/ActiveWriteHooks.kt` `RefusingWriter`; tests: `FakeTarget` in four files, `FaultyTarget`, `FakeWriter`, `NoopWriter`, `RoutedWriter`, `CountingTarget` and the `object : TargetWriter by real` wrapper in `MergeUndoTest`).

## Options considered
A. Extend `SpliceRequest`/`RoundTripGuard` with `ReplaceOwnBlock`. Rejected: weakens the guard that protects every user page.
B. Append-only dated digest blocks. Rejected: unbounded growth and it still edits an old block to mark it superseded.
C. Add `replaceOwnedPage` to `TargetWriter`. Rejected: breaks every implementor and fake above for a capability two writers need.
D. A separate small interface `OwnedPageWriter { suspend fun replaceOwnedPage(page, expectedPriorHash): Either<DomainError, WriteOutcome> }` implemented only by `ActiveTargetWriter` (the one production writer a running device uses for its active graph) and delegated by `RoutedTargetWriter`, reached through `TargetWriterRouter.withWriter { w -> (w as? OwnedPageWriter) }` so the shared contract and its fakes are untouched. `MarkdownTargetWriter` is NOT an implementer: the router picks it only when the target graph is not the ready one, which for this job is a graph switch mid-run (R3-A M6). CHOSEN.
E. No wiki page at all: write the digest as a non-page asset, `assets/stelekit-sketch/<slug>/exports/digest.md`, through `AtomicFileWriter` (Story 2.0), with the LLM step reading the in-memory render. Needs no `TargetWriter`, no marker and hash protocol, no `GraphWriter` interaction and no CLAUDE.md exception, but does not meet the requirement "write the fused digest back to a dedicated page". It is the FALLBACK selected by conditional Story 5.4x if OD-H7 is answered "no" (R3-V M5); D remains the upgrade path.

## Decision
- Digest destination: a dedicated page (title from `digestPageTitle`, default set in Story 5.0). The page properties are `stelekit-owned:: true`, `stelekit-digest:: <slug>`, `stelekit-digest-hash:: <hash>`. Recognition accepts the marker in the page properties OR in the first block (the Active round trip may demote page properties to a first block; Story 5.1 probes which).
- ONE hash: `OwnedHash = sha256(canonical block form)`, the same canonical form idea as `BlockContentHash.of` (`merge/TargetWriter.kt`), computed over the body blocks without the marker properties and independent of renderer, line endings and re-saves. `Unchanged` is decided on that form on both writers. `expectedPriorHash` is this hash. The byte-level `fileHash` compare-and-swap is an internal detail of `MarkdownTargetWriter` (same `withWriter` block, so there is no TOCTOU window).
- Error taxonomy reuses the existing types: refusals are `DomainError.MergeError.WriteRefused(WriteRefusedReason)` with THREE new variants `WriteRefusedReason.NotOwned`, `WriteRefusedReason.EditedByUser` and `WriteRefusedReason.Conflicted`, added to the sealed interface in `merge/TargetWriter.kt:11` (a sealed interface of data classes with an abstract `message`; there is no `toUserMessage`, VERIFIED, so each variant supplies `message`; `DomainError.kt` does not change; `RouterOffGraphRoute.kt:138-150` has an `else` arm and classes the new variants as `permanent = true` deferrals); a writer that does not implement `OwnedPageWriter` (`RefusingWriter` when there is no path or write actor, the off-graph Markdown writer, a wrapper) makes `withWriter { it as? OwnedPageWriter }` return null, which maps to the existing `MergeError.Retryable` with the `RefusingWriter.busy()` text, never to `NotOwned`; retry is the existing `MergeError.Retryable` from `WriteRetryReason.PageBeingEdited`, so the router's retry loop applies; outcomes are the existing `WriteOutcome.Created`/`Updated`/`Unchanged` (an owned replace is `Updated`; no `Replaced` variant, so no new exhaustive `when` in `PageMergeService` or `RouterOffGraphRoute`).
- Criteria: `ActiveTargetWriter`, the only implementer, replaces blocks (delete old blocks, save new blocks, roll back on failure) through `DatabaseWriteActor` and `GraphWriter.savePage`, never raw markdown behind `GraphWriter`; its criteria are block-data equality plus the marker, not bytes. The byte-faithful, CRLF and atomic-replace criteria of the earlier draft belonged to a Markdown implementation that no production path reaches and are dropped; `MarkdownTargetWriter` changes only through the Story 2.0 extraction of `AtomicFileWriter`.
- Git merge behaviour of an owned page: because the hash is over canonical blocks, device B pulling device A's digest computes the same hash and writes nothing (`Unchanged`), so the common two-device case needs no byte identity. When both devices regenerate different content before syncing, git reports a real conflict; the owned page is never hand-merged: a file containing conflict markers is classified `Conflicted` (not `EditedByUser`), the digest job skips it with a visible "resolve the sync conflict" entry, and regenerates once the conflict is resolved in git. `TwoDeviceConvergenceTest` runs two Active-writer devices over a shared fake file system standing in for the git remote, which is what a real deployment is: each device runs the job for its own active graph.
- Justification against "never re-render an existing file": that rule protects USER-authored bytes in files that mix user and app content. An owned page has no user-authored content by contract, and the hash proves it: the instant the user edits it, the writer refuses. Every other page keeps the unchanged splice-only path.
- Deterministic block uuids via `UuidRemap` and explicit `id::`; a post-write read-back compares `OwnedHash`. `MergeUndo` is not involved (the digest does not go through `PageMergeService`, so no manifest records it).
- Created path: file absent is written through the normal new-page path; if the file appears between the check and the write, the result is `NotOwned`.

## Consequences
Story 5.4 splits: 5.4a (interface, `OwnedHash`, `OwnedFileGuard`, the three refusal variants in `merge/TargetWriter.kt`, the null-implementer mapping, an abstract `OwnedPageWriterContractSuite`; sized S), 5.4b (Active writer, router exposure, concrete suite, lock-order test; sized L = two M), 5.4c (`DigestWriter`); 5.4a and 5.4b merge as one slice. Files that change: `ActiveTargetWriter`, `RoutedTargetWriter`, `TargetWriterRouter`, `merge/TargetWriter.kt` (new variants only); files that do NOT change: the `TargetWriter` interface, `MarkdownTargetWriter` (for this feature), `RefusingWriter`, `DomainError.kt` and every test fake listed above. If OD-H7 is "no", conditional Story 5.4x implements option E instead and 5.4a-5.4c are not built. CLAUDE.md gets the scoped exception paragraph only after OD-H7 (a separate owner-approved commit). Regression: `OwnedPageWriterContractSuite` against the Active writer (block-data criteria), `OwnedRefusalMappingTest` (null implementer -> `Retryable`), `OwnedFileGuardTest`, `DigestWriteIdempotenceTest`, `DigestSelfFeedTest`, `OwnedReplaceLockOrderTest`, `TwoDeviceConvergenceTest`.
