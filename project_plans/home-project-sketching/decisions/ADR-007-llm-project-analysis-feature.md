# ADR-007: `LlmFeature.PROJECT_ANALYSIS`: unset means disabled, explicit provider, structural hard-block outbound gate

Status: PROPOSED (blocked on owner decision OD-H4, authorising the opt-in "Analyse projects after sync"; amended by plan review patch 3) | Date: 2026-11-09 | Epic: E5

## Context
Existing LLM features run only on user action. `LlmSettings.getSelectedProviderId` returns `null` when unset and `null` means "Auto" (first eligible provider); `DISABLED_SENTINEL` is honoured only if explicitly stored; new `LlmFeature` entries are picked up automatically by `LlmProviderSettings` (iterates `LlmFeature.entries`) and `PerFeatureProviderPicker` offers an "Auto" item for every feature. Four call sites copy the pattern `null -> registry...firstOrNull()` (`LlmSynthesisService`, `VoicePipelineFactory`, `CaptureEnrichmentCoordinator`, `GraphContentTagVoiceSetup`). The repo is public and the data is a home floor plan (confidential). There is no generic outbound redaction gate (`LogRedactor` is for logs).

## Decision
- `PROJECT_ANALYSIS` is added to `LlmFeature` with its own picker in `ui/components/settings/`. For THIS feature unset means DISABLED (opposite of the existing features). The resolution has one home, `LlmSettings.resolveExplicitProvider(feature)`, used by `ProjectAnalysisService` only; the four existing `null -> Auto` call sites are untouched. The picker REMOVES the "Auto" item for this feature and shows "Not configured" when unset. `LlmCredentialMigration` is NOT used (its steps are one-shot and marker-guarded, and writing the disabled sentinel would show "Disabled" instead of "Not configured"). Test `unsetProviderNeverCalls`.
- Acknowledgement: a per-provider dialog stating that floor-plan dimensions leave this device, persisted per `(provider id, model id)` in `LlmSettings`; changing the provider or model invalidates it; the text depends on the provider kind (a custom OpenAI-compatible endpoint can be local, so its wording asks the user to confirm where it runs).
- The digest/JSON artifact is regenerated on sync by pure local code with no LLM involvement. The LLM step runs only when the per-graph setting "Analyse projects after sync" (default off) is on AND a provider was chosen AND the gate passes.
- The payload is a projection over a CLOSED vocabulary (`LlmPayloadBuilder`, Story 5.5b): the opaque slug only, opaque dimension ids, labels from the registry (the only free-text field), display value plus num/den, a status enum, source kinds with opaque refs (`<kind>:<hash id>`); the local `refTable` (human locators) never leaves the device. No page titles, no filenames, no project display name. Because labels are free text, the owner sees the exact outbound text in a preview (Story 5.6c) before the first analysis; acceptance is bound to the preview's hash, and a changed label set re-prompts.
- `OutboundLlmGate.check(...)` returns `Either<GateViolation, GatedPrompt>`. The gate types live in `llm/` (not `projectbridge/`), which avoids an `llm` -> `projectbridge` -> `llm` cycle. `GatedPrompt` is a plain class, NOT a data class (a generated `copy()` would bypass the opt-in), with an `internal` constructor annotated with a new `@RequiresOptIn(level = ERROR)` annotation (`@GateIssued`, the repo's `DirectSqlWrite`/`DirectRepositoryWrite` pattern) that only `OutboundLlmGate` opts into (a reflection test asserts no `copy` and no public constructor); `ProjectAnalysisService` accepts only a `GatedPrompt` (reflection test: no raw-`String` overload; an audit test: `@OptIn(GateIssued::class)` appears in exactly one production file). It gates the payload, the system prompt and the user's question. HARD BLOCK: a violation means no provider call and a visible failure. It fails on path/URI/email patterns, street-address patterns, any whole token on an EXPLICIT private-term list (the owner-maintained per-graph setting `outboundPrivateTerms`, default empty, plus the local `$STELEKIT_PRIVATE_DENYLIST` file on desktop) and any `ref` not matching `^(table|svg|yaml|prose|user|derived):[a-z0-9]{6,16}$` or any project identifier outside the slug set (the slug validator accepts both the generated `proj-<6 hex>` and the fixture form `proj-closet-1`).
- Imported drawings (media class `DRAWING`) are excluded from the image-description pipeline (Story 0.3, by path and by identity).
- Tests use `FakeLlmProvider` (exists in `BT/llm/LlmSynthesisServiceTest.kt`) with golden prompts; no network. The golden proves the artifact contains the answer, not that a real model reads it.
- The answer is stored as a new `PendingLlmSuggestion` variant in the inbox and is never auto-applied.

## Consequences
Blank-input rule: an empty model never reaches the provider. Failure shows in the JobTracker entry. Files touched are listed in Stories 5.5b/5.6a/5.6b/5.6c. A graph-derived page-name denylist was REJECTED (R3-A M5): on an 8 000-page graph ordinary registry labels (`Rod`, `Shelf`, `Width`) are page names, so the gate would block nearly every payload and train the owner to switch the control off; the control is the closed vocabulary, the structural patterns, the explicit private-term list and the owner-visible preview. The answer is shown in the inbox as a read-only, non-page-mutating variant (Accept = dismiss). Stories 5.6a, 5.6b and the LLM step of 5.7b do not start before OD-H4 is answered.
