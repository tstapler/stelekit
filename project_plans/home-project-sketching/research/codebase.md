## 1. Annotation model and persistence
- `CM/model/ImageAnnotation.kt:50` `Calibration(method, pixelsPerMeter, confidencePercent)`; `:87` `ImageAnnotation` (uuid, blockUuid, pageUuid, graphPath, filePath, calibration, `unit: MeasurementUnit`, tags, sensorData). It requires a photo `filePath` and a block/page owner, so a blank-canvas sketch does not fit this type.
- `CM/model/MeasurementAnnotation.kt:24` `MeasurementUnit` = METERS, CENTIMETERS, MILLIMETERS, FEET, INCHES, FEET_INCHES (1/16" rounding). `:84` `MeasurementAnnotation(imageUuid, annotationType, normalizedPoints, valueMeters: Double?, valueDisplay, label, colorHex, bleDeviceId)`. `AnnotationType` = DISTANCE, AREA, ANGLE, LABEL, GRID_REF. Points are normalised 0..1 image coordinates; the real value is a `Double` in metres.
- Tables: `CM/../sqldelight/dev/stapler/stelekit/db/SteleDatabase.sq:1023` `image_annotations` (carries `pixels_per_meter`, `unit`, `tags` as JSON text) and `:1058` `measurement_annotations` (FK `image_uuid` with ON DELETE CASCADE). The comment at `:1021` says the sidecar JSON `<graph>/.stelekit/images/<uuid>.measure.json` is authoritative and the table is a cache. Mirrored in `CM/db/MigrationRunner.kt:392` (image_annotations), `:433` (measurement_annotations), `:553` (imported_at index).
- Repository: `CM/repository/ImageAnnotationRepository.kt:17` (get all / by uuid / by page / by tag; save; delete). Implementation `CM/repository/SqlDelightImageAnnotationRepository.kt:35`. Tag JSON is built by hand with no escaping at `:61` (`"\"$it\""`), and the tag query is `LIKE '%"tag"%'` at `SteleDatabase.sq:1084`. This is the known "tag JSON escaping" carry-over.
- Export: `CM/ui/annotate/AnnotationExporter.kt:26` is a pixel-bake only (`bakeAnnotations` `:33`, `bakeAndEncode` `:64`) and emits no SVG or structured model. `CM/ui/annotate/AnnotationDriveExporter.kt:24` (`export` `:32`) uploads the baked image and measurements to Drive. `CM/calibration/CalibrationService.kt` has `computeFromReference` `:35` and `estimate` `:178`.
- Fit for a unit-space sketch: there is no exact-rational type (everything is `Double` metres), and the `Calibration` basis problem (Epic C.1) is still open. I recommend **new tables**, additive and idempotent: `sketch_sheets` (sheet type plan/elevation/section, unit, scale, optional `source_asset_uuid` for an imported drawing), `sketch_primitives` (points in rational 1/16" ticks or integer sixteenths), `sketch_dimensions` (name, value in sixteenths, source/provenance, tolerance), and fused-model rows. Each table needs a `SteleDatabase.sq` entry **and** a `MigrationRunner.all` entry (`MigrationRunnerSchemaSyncTest` enforces this), a regenerated `kmp/src/generated/sqldelight*` commit, and `@DirectSqlWrite` forwarding stubs in `RestrictedDatabaseQueries` (CLAUDE.md). Reads should use `asDbFlowList`. Writes go through `DatabaseWriteActor` at one priority (plan C pre-mortem failure 4, HIGH/LOW channels have no cross-channel ordering). A drawing imported as a calibrated sheet could reuse `ImageAnnotation` and `Calibration` as-is (pixels to inches via named known dimensions).
- Inch fractions: only `FEET_INCHES` display logic exists, with no canonical rational type. Search the `ui/annotate` formatter before writing a new one (INFERRED; not opened).

## 3. Wiki and sync path
- Git sync: `CM/git/GitSyncService.kt:55` (`sync()` at `:271`). After the merge it calls `graphLoader.beginGitMerge(reloadPaths)` and `reloadFiles(...)` (`:454-455`), then pushes (`:~470`). On success it builds `SyncState.Success(localCommitsMade, remoteCommitsMerged, lastSyncAt, autoMergedPaths)` at `:484` and publishes it on `syncState: StateFlow` (`:146`; `lastSyncAt` flow `:160`). **Hook point:** collect `syncState` for `Success`, or add a callback right after `recordLastSyncAt` (`:~491`). `autoMergedPaths` and `reloadPaths` give the changed files. Orchestrators: `CM/ui/GitSyncCoordinator.kt:61`; Android `androidMain/.../git/WorkManagerSyncScheduler.kt:122` (`GitSyncWorker`) runs scheduled syncs without UI.
- Reload path: `CM/db/GraphLoader.kt:64` (`reloadFiles` `:982`, `loadDirectory` `:1211`, `externalFileChanges: SharedFlow` `:516`). The watcher is suppressed during git merges.
- Background-job UI: `CM/jobs/InProcessJobs.kt:27` `JobTracker.begin(kind, title)` and `track(...)` `:48`, so a post-sync digest job should be tracked there.
- Safe write-back rules (CLAUDE.md "Cross-graph writes"):
  - Use `CM/merge/TargetWriterRouter.kt:38` `withWriter(target, block)` `:56`. It picks the active or off-graph writer under `CM/db/GraphWriteLock.kt:26`. Never hold one lock while acquiring another, and do not call `awaitPendingMigration` under a lock.
  - Never write the active graph's markdown behind `GraphWriter` (`CM/db/GraphWriter.kt:57`; `GraphWriterPort.savePage` `:65`).
  - Off-graph writes are splice-only: `CM/merge/MarkdownSplicer.kt:38` `splice(original, SpliceRequest)` `:55`, vetted by `CM/merge/RoundTripGuard.kt:66` (`probe` `:71`, `splice` `:83`), which refuses any change to existing blocks.
  - Every inserted block gets a remapped uuid, explicit `id::` and `src-id::` (`UuidRemap`). Set `properties["id"]` before saving.
  - Consequence for a digest: append it as a **new block** (or a new page such as `<Project>/Digest`) with `id::` property. Never re-render or edit an existing table block in place. A regenerated digest needs an "update own block by `id::`" path; the splicer today only inserts (INFERRED; confirm in `SpliceRequest` `:15`).
- The sidecar JSON for the machine-readable model could live under `<graph>/.stelekit/` (as `.measure.json` does) so it is never parsed as a page.
