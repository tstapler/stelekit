## Blockers
- [x] (RESOLVED by repair; see Re-review) **Off-graph write re-serializes the target's file, which can silently drop target content.** Task 1.1.3c / 2.3.1b-c read the existing target page into `MergePage`, merge, then render the whole page through `LogseqPageSerializer`. That serializer writes only `content` plus `properties`. It has no `id::` and no handling of `block_type`, `collapsed`, fenced or org content, or anything the parser normalizes. The only round-trip test (Story 1.1.3) starts from `Block` trees, not from arbitrary real markdown. This breaks the requirements' core guarantee that nothing is removed from the target, and the guard is "Merge is additive-only". Story 2.3.1's AC example (append C to `- A\n- B`) hides the problem. — Make the off-graph write a splice that preserves the original bytes and inserts only new blocks, or require `serialize(parse(file)) == file` before rewriting and otherwise route to the inbox or refuse. Add a property test over real-world markdown fixtures asserting that the original text is preserved byte-for-byte for untouched blocks.
- [x] (RESOLVED by repair; see Re-review) **UUID identity is not guaranteed across the stage -> disk -> parse hop, and idempotence (the headline metric) depends on it.** `stage()` (Task 2.4.2c) spills source pages as markdown, and the serializer does not emit `id::`. A parsed block then gets a fresh or derived uuid, so `UuidRemap` (deterministic from `merge:<sourceGraphId>:<sourceUuid>`) and `src-id::` change on every run, and repeat merges duplicate blocks. The same applies to off-graph target blocks, whose DB uuids are not in the file, so `readExisting` (file) and the Active writer (DB) see different identities for the same block. The plan defers this to Spike 0.1.3 with a conditional "Task 1.1.4c". Story 1.1.4 does not exist, so the fix is not scheduled. The stories that must hold the invariant (1.1.2, 1.2.1, 2.4.2 idempotent apply, 5.1.1) are not marked GATED. — Decide now: stage as structured JSON (a serializable `MergePage`/`MergeBlock` carrying the uuid) instead of markdown. Make "`id::` emitted for explicitly-uuid'd blocks" a committed task (not conditional) with an owner story. Add an AC that proves the same merge run through `MarkdownTargetWriter` and `ActiveTargetWriter` yields identical outcomes.

## Concerns
- [ ] **`GraphWriteLock` covers only opening, not teardown.** Story 2.1.1c takes the lock around opening the target id. `switchGraph` (`GraphManager.kt:804`) is a non-suspending `fun` that tears down the previous graph (cancels jobs, closes the factory) from the UI dispatcher. A merge page batch running through `ActiveTargetWriter` against the outgoing graph can hit `ClosedSendChannelException` or a closed driver mid-batch. The router's mid-run-switch AC only covers the inactive-to-active direction. — Also take the lock around teardown of the old id, or have `ActiveTargetWriter` treat closed-channel as "retry through the router" and add a test for active-to-inactive mid-run.
- [ ] **Picker filtering is O(graph) per keystroke.** Task 2.4.1b/Story 2.4.1 build search/namespace/tag/date filtering on `getPages(limit, offset)` plus a pure predicate. The AC wants "total result count via a count query, not a full list" and says "no `.sq` change preferred". With only paged scans, the count and any tag filter (page props) require scanning all 8 030 pages (~81 round trips) per query change. — Use `SearchRepository`/FTS or add bounded SQL for namespace/date/journal filters plus a count query (with the `.sq`, `RestrictedDatabaseQueries`, regenerate steps already described), or explicitly cap and debounce, and add a `QueryPlanAuditTest` entry.
- [ ] **iOS/Web "copy UI" effectively disabled.** Requirements list iOS and Web in scope for copy/merge UI. Story 4.5.1 disables the target when the platform `FileSystem` cannot address the other graph path. The "pull-on-switch" path was rejected and kept only as a "Resume" for interrupted copies. Without it, these platforms get no working copy flow. — Define the staged apply-on-activate path (reusing the staging dir and `ActiveTargetWriter`) as the supported fallback for platforms where `MarkdownTargetWriter` is unavailable, with its own AC.
- [ ] **Journal filename format is hard-coded in ACs but marked unresolved.** Story 4.1.3's AC asserts `journals/2026_10_07.md`, but `GraphWriter.getPageFilePath` uses `FileUtils.sanitizeFileName(page.name)` and the plan lists the format as an open question blocking Story 1.2.2. The off-graph appender can create a journal file that the loader names or dedupes differently, producing a second journal for the same date. — Resolve before 4.1.3 by reading how journal pages are named and loaded. Test that an off-graph-created journal is reconciled to the same page as `ensureTodayJournal` on open.
- [ ] **Android share features dropped for named targets.** `CaptureViewModel` has image prefix handling (`[image: path]`, path in `cacheDir`), link suggestions and stub-page creation tied to the active graph (`graphStillActive`, `performSave`). Story 4.1.3 only appends plain text. Image shares to a non-active graph keep a cache-dir path that can be evicted, and the linked-text suggestions have no off-graph equivalent. — State explicit behaviour (copy image into the target `assets/`, or disable suggestions for off-graph targets) and add ACs.
- [ ] **Conflict identity depends on `generateDeterministic` quality.** It is two FNV-1a 64-bit hashes of the seed and its reverse (128 bits, but not a cryptographic or independent hash). Remapped uuids land in an `INSERT OR REPLACE` table, so a collision silently replaces another page's block. The spike checks only the existing-collision behaviour. — Add a guard in the apply path: before saving, check that `uuid'` is not already used by a different page (or fail the page), plus a regression test.
- [ ] **Scope vs. appetite.** About 100 five-minute tasks cover undo, conflict review, link closure, asset copying, a share inbox, Direct Share shortcuts, and a `merge_force_inbox` developer toggle. The requirements say undo is "to be evaluated". The shortcuts are labelled a cut line but are still in the plan. — Mark Story 4.2.2 and the inbox image path as post-MVP in the dependency order, and cut `merge_force_inbox` unless Spike 0.1.1 fails.
- [ ] **Plan text references a `GraphActivated` event that does not exist** (grep finds no such symbol). Task 4.4.1b correctly says to observe `activeRepositorySet`, but the Glossary and Story 4.4.1's AC still use it. — Fix the wording so the inbox drain trigger is unambiguous, and say how a drain avoids racing the initial load.

## Re-review (scoped to former blockers 1 and 2)

**Verdict: CONCERNS.** Blockers 1 and 2 are closed at the design level. No new blocker. Four concerns, one of which (R1) must be written into the plan before Story 2.3.2 starts. Checked against the code, not only the plan.

### Blocker 1 (off-graph write drops target content): resolved
`MarkdownSplicer` (insert-only) plus `RoundTripGuard` plus byte-preservation fixtures (Story 1.1.4, 2.3.1) remove the re-render. Brand-new pages are the only whole-page render, so there is nothing to drop. Attempts to break it:
- Whole-file render on the off-graph path: none left (Task 1.1.3c, 2.3.1c).
- Guard too strict: the plan records this as an unresolved measured unknown (fixture pass rate); the failure mode is inbox routing, not data loss. Acceptable.
- Splicer can't find insertion offsets: Task 1.1.4c has a fallback line scanner. Acceptable, but see R3.

### Blocker 2 (UUID identity across stage -> disk -> parse): resolved for the off-graph path
`StagedPage` JSON carries uuids, `id::` is a committed task (Story 1.1.4), `UuidRemap` is always-remap SHA-256 with no target oracle, and the gated-story list is complete. Verified: `MarkdownPageParser.generateUuid` (db/MarkdownPageParser.kt:39-64) uses `properties["id"]` verbatim, so an emitted `id::` round-trips. okio is a commonMain dependency (kmp/build.gradle.kts:129), so SHA-256 is available.

### Remaining concerns
- [ ] **R1 (fix in the plan before Story 2.3.2): `ActiveTargetWriter` has no `id::` emission.** The active path persists the file through `GraphWriter.savePage` -> `LogseqPageSerializer.serialize` (GraphWriter.kt:517, 670), which writes only `block.properties` (LogseqPageSerializer.kt:38-44). The plan adds `id::` only in the merge renderer used by the off-graph splicer, and says the serializer is unchanged. A new block with `uuid'` but no `properties["id"]` is saved to the DB with `uuid'` but to the file without `id::`. On the next reload the parser derives a positional uuid instead, so (a) `((uuid'))` rewrites in other copied blocks dangle after restart, and (b) the Story 2.3.2 contract-parity AC ("identical final block uuids, read back from file vs DB") cannot pass. Idempotence still holds via `src-id`, which is an ordinary property, so this is not a blocker. Fix: `ActiveTargetWriter` sets `properties["id"] = uuid'` on every inserted block (the parser keeps `id` in properties via `mergedProperties()`), and the parity test reads the file back and re-parses it.
- [ ] **R2: active path is not byte-preserving and the guard doesn't apply.** `GraphWriter.savePage` re-renders the whole page (loses CRLF, trailing whitespace, any construct the parser normalizes). This is existing editor behavior, but a merge into a page the user never edited now normalizes it. State this as accepted in ADR-001, or run `RoundTripGuard` on the active path too and warn. The contract-parity AC should compare block data, not file bytes.
- [ ] **R3: positional uuids shift on mid-file insertion.** Blocks without `id::` get `UuidGenerator.generateDeterministic("$pagePath:$parent:$index")` (MarkdownPageParser.kt:60). Placement inserts "after nearest preceding matched sibling", which shifts the index, and so the uuid, of every later unlabeled sibling (and their descendants) on reload. This also makes off-graph `readExisting` uuids depend on using the same `pagePath` string as the DB. Merge matching uses `src-id`/content, so correctness holds, but uuid churn can orphan DB-side state such as refs. Prefer append-after-last-sibling where no anchor requires otherwise, or splice `id::` onto shifted unlabeled siblings (which violates insert-only; so prefer the first), and test with unlabeled fixtures.
- [ ] **R4: edit-after-copy semantics are undefined.** Re-copying when a copied block (matched by `src-id`) was edited in the target: the plan only defines same-uuid/different-content as a conflict sibling, with `uuid'` derived from the same `(graph, S)`, i.e. identical to the existing block's uuid. State the matching rule (src-id match with differing content: conflict sibling with a distinct derivation that also carries `src-id`, and a later run treats an existing sibling with equal src-id and equal content as `Unchanged`), and add it to the Story 1.1.2 idempotence property generators.

### Contradictions with requirements
None found for the two blockers. The "nothing removed from target" and "idempotent" guarantees now hold on the off-graph path; R1/R2 are the places the active path is weaker.
