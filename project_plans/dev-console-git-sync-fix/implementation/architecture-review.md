## Blockers

- [ ] **Story 2.4 / Task 2.4c / Glossary `ActiveGitSyncRegistry`** — The plan invents a process-wide `ActiveGitSyncRegistry` for the worker to find the live `GitSyncService`, but one already exists and is already used by the worker's fast path: `object GitSyncServiceRegistry` (`androidMain/.../git/WorkManagerSyncScheduler.kt:252`, consumed at :133), plus `GraphManager.registerGitSyncService` / `_activeGitSyncService` (`GraphManager.kt:1364`, called from `GraphContentGitSyncSetup.kt:43`). A third registry in commonMain gives three sources of truth for "which service is live", and "delegate to the live service" is already how `GitSyncWorker.doWork` behaves (it only calls `fetchOnly` instead of a full sync). The desktop path needs no registry at all: `GitSyncService.startPeriodicSync` lives inside the service. — **Remediation**: delete `ActiveGitSyncRegistry`. Task 2.4c becomes "change the fast path at `WorkManagerSyncScheduler.kt:~133-140` to call `service.runScheduledSync(graphId)` via the existing `GitSyncServiceRegistry`; the slow path (`runSlowPathFetch`, :213) becomes `ColdSyncRunner`". Update glossary, Tech Debt row for `WorkManagerSyncScheduler.kt`, dependency graph.

- [ ] **Task 2.4d / Glossary `MergeAbortResult` / ADR-004 "new `abortMerge`"** — `GitRepository.abortMerge(config): Either<GitError, Unit>` already exists (`GitRepository.kt:50`), is implemented in both repos (`AndroidGitRepository.kt:375`, `JvmGitRepository.kt:358`) and called by `GitSyncService.kt:643`. The plan treats it as new with a `NotSupported` default and a `MergeAbortResult` type; changing the signature breaks three implementers plus tests. More seriously, the existing implementation is `ResetType.HARD` (documented at `AndroidGitRepository.kt:~383-395`), which **discards every uncommitted local edit**. The cold-worker pipeline (fetch, merge, push, abort on conflict) runs with no live graph and no `EditLock`; the plan only specifies the "clean tree" happy path and never says what happens when the tree is dirty (normal state: edits sit uncommitted until `autoCommit` runs). A conflicting cold merge on a dirty tree therefore either fails mid-merge or HARD-resets the user's unsynced notes. — **Remediation**: (1) reuse `abortMerge` as is, drop `MergeAbortResult` and "default NotSupported"; (2) make the cold path explicit: it must run `status` and, if dirty, either commit local edits first (same `autoCommit` rule as `sync()`) or return `ColdSyncOutcome.FetchedOnly` without merging; never call `abortMerge` on a tree that was dirty at merge start; (3) add a jvmTest "dirty tree + conflicting remote, cold run" asserting no edit is lost; (4) answer the owner question with this precondition stated, since the current wording ("acceptable to abort?") hides the data-loss path.

- [ ] **Story 3.1 / 3.3 vs Tech Debt row `db/GraphLoader.kt`** — The disposition table says GraphLoader gets only "port methods on `GraphLoaderPort`, a WARN in `reloadFiles`, a try/finally on the reconcile catch" and research/architecture.md:175 says "do not touch internals". The stories do more: Task 3.1a adds `loadJournalsOlderThan` and `ensureJournalLoaded` implementations inside `GraphLoader.kt` ("GraphLoader.kt (minimal)"), Task 3.3a adds `indexStatus()`, Task 3.3b changes the `onFullyLoaded` callback contract (`degraded=true`) and the reconcile failure path. The only named seam is `BackgroundIndexSupervisor`, which covers restart only. That adds new responsibilities to a 1970-line, 63-commit hotspot while claiming "Isolate via seam" — the disposition is not honest, and the lazy-journal logic has no seam task (Lens 4, items 12-13). — **Remediation**: add Task 3.1a0 "extract `JournalLazyLoader` (new `db/JournalLazyLoader.kt`, constructor takes `FileRegistry`, `PageRepository`, a parse-and-save function reference)"; `GraphLoader` gets one-line delegating overrides of the two port methods. Put `IndexStatus` state in `BackgroundIndexSupervisor` (it already owns the job) rather than `GraphLoader`. Update the table to list every GraphLoader edit (count them, and cap at "delegations + one WARN + one try/finally"). If `onFullyLoaded(degraded)` changes a port signature, list every implementer/fake (`GraphLoaderPort` has test fakes) in the task.

## Concerns

- [ ] **Story 5.3 `fs` / `PathPolicy`** — Acceptance criteria require "symlink escaping the graph root -> Denied", "at most 64 KiB read from a 50 MB file" and `fs find`/`stat`. The commonMain `FileSystem` interface (`platform/FileSystem.kt`) has no canonical-path/symlink resolution, no ranged or streaming read (only `readFile`/`readFileBytes` whole-file), and `getFileSize`/`getLastModifiedTime` only. `PathPolicy` in commonMain can only do lexical `..` checks, so the symlink criterion is unachievable as designed, and a naive `fs cat` would load 50 MB into memory (OOM kills the Android process; see CLAUDE.md uncaught-Throwable rule). — Add a task before 5.3a: extend `FileSystem` with `readPrefixBytes(path, maxBytes)` and `canonicalPathOrNull(path)` (default `null` = unsupported, which makes `fs` deny symlink-capable paths), with JVM/Android actuals, and list the affected expect/actual files. Alternatively cap on `getFileSize` first and refuse over the cap.

- [ ] **Story 5.6 `settings list` / `get`** — `platform/Settings.kt` exposes only `getBoolean/putBoolean/getString/putString/containsKey`; there is no key enumeration, so `settings list` ("no token values print") cannot be built without changing the interface on every actual (Android, JVM, iOS, wasm, test fakes). Either drop `list` in favor of an explicit allowlist of known keys held in the console package (preferred: also the right redaction posture), or add an enumeration task with the actuals named.

- [ ] **Story 5.5 / ADR-002 write gate** — (a) ADR-002 and Story 5.5 say `SqlConsoleWriter` is "covered by the existing write-gating enforcement test as an explicit exception". No such test exists: `DirectSqlWrite` is a compile-time `RequiresOptIn(level = ERROR)` (`db/DirectSqlWrite.kt:19-25`); the only tests mentioning it are unrelated (`WikilinkBatchInsertTest`, `StorageLocationPersistenceTest`, `CaptureWriterSourceAuditTest`). The plan should create the enforcement test (allowlist of classes carrying `@OptIn(DirectSqlWrite::class)`), not "list as exception". (b) CLAUDE.md says the only approved class-level opt-in outside the actor is migration-time writers and that other helpers opt in at the private write function inside the actor lambda. A class-level opt-in on `SqlConsoleWriter` contradicts that rule and CLAUDE.md is only updated at Task 7.3a. Use function-level `@OptIn` inside the `actor.execute` lambda, or update CLAUDE.md in the same task as 5.5a. (c) `DatabaseWriteActor.execute(op: suspend () -> Either<DomainError, Unit>)` (`DatabaseWriteActor.kt:761`) returns `Unit` only; "1 row affected" and the dry-run count need a captured side channel (a `var` set inside the lambda) — state it in Task 5.5a.

- [ ] **Task 2.1c / Story 2.3 empty-remote case** — Case (d) requires `Error` with message "Remote is empty" and "no `RemoteBranchNotFound`", but the plan defines no typed variant for it; the only places to put it are `FetchFailed(message: String)` (stringly-typed) or a boolean on `FetchResult`. Type-driven rule (Lens 2, illegal states): add `GitError.RemoteEmpty` (or `DefaultBranchDetection.EmptyRemote` already exists in the glossary — thread it through `fetch`) to the new variants in Task 2.1a so the exhaustive `toSyncErrorMessage` (:320) and `SyncStatusBadge` routing handle it.

- [ ] **Task 2.4d cold worker on SAF graphs** — The existing slow path deliberately builds `AndroidGitRepository(context, PlatformFileSystem())` with an uninitialized `PlatformFileSystem`, justified in the code comment at `WorkManagerSyncScheduler.kt:~162-168` as safe "because fetch() never touches the working tree"; that justification is void once the cold path merges (merge triggers `ensureFresh`/shadow write-back to SAF). The plan does not address SAF-backed graphs in a cold process. The owner's cloned graph is app-owned, so scope the cold merge to non-SAF configs (path-mode check from `git doctor`), fall back to `FetchedOnly` for SAF, and add a test for that branch.

- [ ] **Story 6.1 / Task 6.1a `Screen.Console`** — `Screen` subclasses in `AppState.kt` carry `@HelpPage` or `@HelpExempt(reason=...)` annotations (see `LibraryStats`, `Notifications` at :46-50), and there are exhaustive `when (screen)` sites (`ScreenRouter.kt`). ## Lens summary

- **Structural**: Ports/adapters for the console (ADR-001) are sound and keep `GraphManager` out of commands; the shared resolver (ADR-003) is the right Gateway-style fix for the duplicated `doFetch`. Weak points are duplicated infrastructure (registry, `abortMerge`) that the planner did not find because it did not open the files.
- **Type-level**: Sealed `ConsoleError`, `StatementClass`, `DefaultBranchDetection`, `ColdSyncOutcome` are good; empty-remote and invalid-ref outcomes are still strings.
- **Patterns**: Command + Registry, Unit of Work through the write actor, and Strategy for `ScheduledSyncPolicy` fit complexity. Build-vs-buy (engine-enforced read-only, no SQL parser) matches `research/build-vs-buy.md`.
- **Tech debt**: Git repo classes (seam via `RemoteTrackingRef.kt`), `GitSyncService` (extend as-is, new logic in policy/runner) and `StelekitViewModel` dispositions are honest. `GraphLoader` disposition is not (Blocker 3).
