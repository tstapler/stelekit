## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | **First real sync after the branch repair is a large, unattended, diverged merge.** Before the fix the phone's push used the configured `main` (plan 2.3a only tests that no `refs/heads/main` appears after the fix). Earlier phone auto-commits may therefore sit unpushed, or sit on a stray `origin/main`. Once repaired, the scheduled full sync (owner decision, auto-commit + merge + push) hits journal conflicts or pushes months of old commits with nobody watching. Conflicts are skipped (`Skipped(Conflict)`) and surface only as a launch-time banner (Task 2.4h). | Phone shows `ahead` of dozens of commits after repair; `git_pending_conflict_<graphId>` marker set on the first scheduled run; stray `origin/main` exists. | Add a task: before enabling scheduled sync on a repaired config, require one manual sync preceded by a preview (ahead/behind counts, list of remote branches including strays, first 20 local-only commits). `ScheduledSyncPolicy` returns `Skip(FirstSyncUnconfirmed)` until a manual sync has succeeded for the current `(remote, branch)` pair. Add a Story 0.3b check: `ls-remote` for a stray `main` is part of the evidence record. | P1 |
| 2 | **Sync is still silent in practice.** Typed errors exist, but a background failure has no channel: plan says "no new alerts", and cold-run skips (`Skipped(Dirty/Conflict/Saf/RepairNeeded)`, `FetchedOnly(Saf)`) are shown only at next app launch. The platform predicate defaults to fetch-only on any exception (2.4g), so a mis-classified graph fetches forever and never merges while looking healthy. WorkManager can also be Doze-throttled for hours. | Owner opens the app days later; journals missing; badge says "synced" with an old timestamp or none. | (a) Persist `lastMergedAt` and `behindCount` per graph and render a permanent "last merged N h ago / behind N" staleness chip on the sync badge, amber after 2x the effective interval. (b) Add a `diag` and sync-badge line that prints the cold-run outcome history (last 10). (c) Make Metric 1 verification (Task 7.1a) include a forced `FetchedOnly(Saf)` classification check on the owner's actual active graph, not just a unit table. | P1 |
| 3 | **Garbage push: mass deletion or empty-tree commit.** The push guards cover conflict markers and `MERGING` state only (2.3e). A working tree that lacks files (SAF shadow desync, partial reload, restore swap, lazy journal cap, wikiSubdir mismatch) is auto-committed by `stageSubdir` as a large deletion and pushed. Remote deletions are also "deferred" while the DB keeps them (plan Unresolved Q5), so DB and disk can disagree about what exists. | Remote history shows a commit deleting hundreds of `logseq/journals/*.md`; or a push of thousands of files in one commit. | Add a push sanity gate to Task 2.3e: compute the net diff `origin/<branch>..HEAD`; if deleted files exceed `max(20, 5% of tracked files)` or any deletion hits more than N journals, refuse unattended commit/push (`Skipped(MassChange)` / interactive confirm with the file list). Never force-push (assert in code and test). Add a test with a tree where a subdir is missing. | P1 |
| 4 | **Console DB write desyncs DB from markdown, and the "disk wins" repair path then destroys DB-only notes.** `graph reload` and `restore-backup` both re-import disk over the DB (Story 5.5 cascade policy; Task 5.5e). Open Q4 says journals 2026-10-07/09/10 exist only in the DB. A routine `graph reload`, or a restore followed by reload, silently erases them. FTS triggers also fire on raw `blocks` writes; the deny list covers only direct `blocks_fts` writes. | Journals 10-07/09/10 vanish after the first `graph reload`; search returns stale hits after a console `update blocks`. | Add a precondition to `graph reload`, `graph reindex` and `restore-backup`: run `JournalDiffService` and refuse (or force a typed confirm) when DB-only journals or `ConsoleDbDirty` tables exist; auto-export DB-only journal content to the backup dir first. Add a cascade test that includes trigger-maintained FTS tables, not just the table written. | P2 |
| 5 | **`restore-backup` live-DB swap corrupts or wedges the database on Android.** Renaming `*.db`, `-wal`, `-shm` while connections, the actor and the new console read connection may still be open is platform-specific; the fallback snapshot when `VACUUM INTO` is unsupported is "checkpoint + copy" of a live file. Backups are unencrypted copies of the whole notes DB. | After restore: "database disk image is malformed", app crash loop on start, or old data reappears (stale WAL replayed over the restored file). | Make Task 5.5e depend on a spike (extend 0.2b) proving the swap on a real Android device/emulator with the console reader open; require closing the console reader connection before the drain; delete stale `-wal/-shm` explicitly and verify with `integrity_check` plus a row-count comparison before reopening. Restrict the checkpoint+copy fallback to a quiesced actor. Keep the pre-restore copy until the next clean launch. | P2 |
| 6 | **JVM-green, device-red.** Nearly all sync tests run against temp JGit repos in `jvmTest`; the real failure surface is `AndroidGitRepository`, SAF shadow, `PlatformFileSystem` pathResolver, WorkManager and process death, which are covered by Robolectric tables and owner wall-clock device passes (Epic 7). The evidence gate (0.3a) already depends on the owner installing a build. A stale installed binary (see memory: "startup lockup was a stale-binary crash loop") can invalidate the evidence. | Epic 7 device pass fails after PR-A is "done"; or diagnostics shows a different build than the one tested. | Stamp git SHA + build time in the diagnostics header and in `diag`; Task 0.3b must record the stamp and refuse to select a branch on an unstamped export. Define PR-A "done" as Epic 7.1 passed, not merged-green. Add an instrumented or emulator test for the Android clone path with a real file:// origin. | P2 |
| 7 | **Credential or note leak through the console export.** Redaction is explicitly best-effort (glossary, line 62); `sh` bypasses the fs deny-list (desktop); transcripts go to a share sheet or Downloads in plaintext; history is in memory but `export` persists it. SQL deny covers credential tables by name only; a renamed or new column elsewhere is unprotected. | A shared transcript contains a token fragment, remote URL userinfo or note text. | Make `export` show a pre-export preview with matched redactions highlighted and a "may contain note content" warning; default the credential-table check to an allowlist of readable tables rather than a deny-list of names (plan already says allowlist for settings; apply to SQL too); add a leak-audit test that seeds a known token into every credential store and runs every console command. | P2 |
| 8 | **Delivery sprawl: ~100 tasks across 4 units; PR-C gets stuck or rots.** The sync fix (PR-A) is small in user value but sits behind spikes, gates and 2.4 (scheduled full sync incl. cold runner, markers, repair routine). Owner device wall-clock delays Epic 0.3a; PR-C depends on a rebase against PR #397's `RepositorySet` change (Unresolved Q8) and on the Bazel commonMain split. | PR-A open for weeks with "sync fix" still unshipped; merge conflicts in `GraphLoader.kt`, `GitSyncService.kt`. | Split PR-A in two: A1 = typed error + resolver + doFetch fix + diagnostics commit (ships the primary success metric on its own); A2 = scheduled full sync, cold runner, markers. Land A1 before 2.4 starts; time-box 0.3a with the safe default (Branch 1) after one device cycle. | P2 |
| 9 | **Console process-level failure on Android.** A runaway `sql`, `fs find` or huge result stream triggers OOM in whichever coroutine allocates next, killing the process on Android (CLAUDE.md invariant) even though desktop only prints. Scrollback is capped, but command-side buffering (CSV export, cell materialization) may not be. | App closes while running a console command; works on desktop. | Add a test that streams 100k rows through the real cap path under a small heap and asserts the result is bounded end to end, including export; attach the `CoroutineExceptionHandler` to the console scope (already planned in 4.4b) and cover it with an injected `OutOfMemoryError` test. | P3 |
