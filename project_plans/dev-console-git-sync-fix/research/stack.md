**API recipes (INFERRED, JGit semantics; write a temp-repo test to confirm before relying on them)**
- Ref resolution: `repo.resolve("refs/remotes/origin/master")` returns null for an absent ref. The existing short form `origin/master` also works through `Repository.resolve`'s DWIM. Prefer the full name `Constants.R_REMOTES + remote + "/" + branch`, or `repo.exactRef(...)`, in the fix to avoid ambiguity with a local branch of the same name.
- Default branch via ls-remote symref: `git.lsRemote().setRemote(r).callAsMap()` returns `Map<String, Ref>`, which includes the key `"HEAD"`. When the server advertises `symref=HEAD:refs/heads/X`, JGit (since 5.x, protocol v0/v1 capability and v2 `ls-refs symrefs`) returns that entry as a `SymbolicRef`: `ref.isSymbolic` is true and `ref.target.name == "refs/heads/master"`. Fallback when not symbolic (e.g. a dumb server): find the head whose `objectId` equals HEAD's `objectId`, preferring `main` then `master`. For a pre-clone check, `Git.lsRemoteRepository().setRemote(url).setHeads(true).callAsMap()` works the same. Also call `setTags(false)` to cut payload.
- JGit's `CloneCommand` without `setBranch` already follows the remote HEAD. A clone gets the right local branch, but the stored `GitConfig.remoteBranch` default `"main"` is independent. This is the likely mismatch (hypothesis still unconfirmed on device).
- `BranchTrackingStatus.of(repo, "master")` returns null if `branch.<name>.remote/merge` is unset, so it cannot replace the explicit-ref check. `GitRefDiagnostics` already handles the null.
- Shallow: `repo.objectDatabase.shallowCommits.isNotEmpty()` is used already. Unshallow-on-fetch interaction is exactly `hasRemoteDivergedSinceShallowClone`: if `remote/branch` is unresolved it returns true (diverged), so the unshallow path may run on every fetch. Check for wasted unshallow when the fix lands.
- Android specifics: JSch SSH transport (`ssh.jsch`) vs Apache MINA on JVM, via `AndroidGitRepositoryAuth.kt`; HTTPS/token path is shared via `configureTransportAuth`. No JGit API differs for ref resolution between the platforms. Android JGit runs on-device with desugaring; ls-remote works the same.
- SAF graphs: fetch/merge run on a shadow worktree (`androidMain/.../AndroidGitRepositoryShadow.kt`, `GitShadowWorktree.kt`). Ref lookups must open the repo that owns the refs. Check which `openGit` variant `doFetch` uses (`openGitWithoutFreshnessCheck(config)`).
- Fix shape: after `fetch().call()`, take `FetchResult.trackingRefUpdates` and `getAdvertisedRefs()` from the JGit `org.eclipse.jgit.transport.FetchResult` (returned by `.call()`, currently discarded). The advertised refs give the available remote branches for the WARN log and the actionable error without a second round trip. (INFERRED API: `TransportCommand` result `FetchResult.getAdvertisedRefs()` is public.)

## 2. Compose Multiplatform terminal REPL (INFERRED patterns; no console code exists)

Nothing named console/REPL/developerMode exists in `kmp/src` (grep for `developerMode|developer_mode` found no files). Existing screen routing: `ui/ScreenRouter.kt` with `Screen.Logs` at `:228` and a diagnostics-report hook at `:108` ("builds the report behind the Logs screen's diagnostics button"). Settings: `platform/Settings.kt`, `PlatformSettings.kt` (store for the developer-mode flag).

Recommended structure
- `ConsoleViewModel`/state holder owns its own `CoroutineScope(SupervisorJob() + Dispatchers.Default + CoroutineExceptionHandler)`, per CLAUDE.md. Do not pass `rememberCoroutineScope()` into it. Expose `StateFlow<ConsoleState>` (lines, running job, history index).
- Scrollback: `LazyColumn(state, reverseLayout=false)` of line items with stable `key`; auto-scroll with `LaunchedEffect(lines.size) { state.animateScrollToItem(last) }` only when the user is at the bottom (`derivedStateOf { !state.canScrollForward }`). Cap the buffer (e.g. 5-10k lines ring buffer) and render one `Text` per line (monospace `FontFamily.Monospace`), not one giant string, to keep recomposition cheap. Add `SelectionContainer` around the list for copy.
- Input: `BasicTextField` (or `OutlinedTextField`) with `onPreviewKeyEvent` for Enter (submit), Up/Down (history), Ctrl+C (cancel). On Android soft keyboards Up/Down do not exist, so add history buttons. Set `KeyboardOptions(autoCorrectEnabled=false, capitalization=None, imeAction=Send)`.
- Streaming and cancel: command = `suspend fun run(args, out: ConsoleOutput)` (or `Flow<ConsoleLine>`) launched in a `Job`; cancel = `job.cancel()`. Commands must cooperate (`ensureActive()` in loops; JGit calls are blocking and are not interruptible by coroutine cancel, so bound them with the existing timeouts and run via `runInterruptible(PlatformDispatcher.IO)`). Batch UI updates (collect with `conflate()`/`chunked` on a 50 ms tick) to avoid per-line recomposition.
- Registry: `interface ConsoleCommand { val name; val help; suspend fun run(ctx, args, out) }` plus a `ConsoleCommandRegistry` list; per-platform commands registered through `expect/actual` or an injected provider (git/sh absent on wasm, so register only what the platform has). This gives the "one-file addition" extensibility requirement.
- History: in-memory by default (requirements). Redact secrets before logging args.
- Export: reuse section 5.
- Test: Compose behaviour belongs in `androidUnitTest` (Robolectric, headless) per CLAUDE.md. Parser/registry/redaction logic goes in `commonTest`; property tests for the tokenizer (quote/escape handling).

## 3. Guarded SQL against SQLDelight drivers

**Existing (VERIFIED)**
- `DriverFactory` is `expect class` (`commonMain/.../db/DriverFactory.kt:8`) returning `SqlDriver`. `createReadDriver()` returns a second Android connection, else null (`:50`). `ReadWriteRouterDriver.kt` routes `executeQuery` to the read driver and writes to the write driver. `TimingDriverWrapper.kt` wraps both. Raw `driver.executeQuery(identifier=null, sql, mapper, parameters)` and `driver.execute(null, sql, n)` are already used in `MigrationRunner.kt:903-1109` and `performance/QueryPlanRepository.kt:23`, so the raw-driver API pattern is established and works on all targets (it is the common `SqlDriver` interface; wasm uses the same interface).
- Writes must go through `DatabaseWriteActor.execute(priority) { Either<DomainError,Unit> }` (`db/DatabaseWriteActor.kt:761`). Its doc: "any write that doesn't have a dedicated typed method". A console `sql` write is a raw `driver.execute(null, stmt, 0)` inside that lambda, with the `@OptIn(DirectSqlWrite::class)` convention for the helper class (CLAUDE.md). Note: `ReadWriteRouterDriver` sends `execute` to the write driver, and query-invalidation ordering is the known actor hazard (memory: DatabaseWriteActor invalidation ordering), so raw writes should be followed by `driver.notifyListeners(...)`/table-name notification only if the actor does not already. UNVERIFIED which; read the actor's `WriteRequest.Execute` handler before implementing.

**Read-only guard design (INFERRED)**
- Classify statements before execution. Allow-list first token (after stripping comments/whitespace): `SELECT`, `WITH` (then confirm no top-level DML keyword), `EXPLAIN`, `PRAGMA` (read-only subset: `table_info`, `index_list`, `foreign_key_list`, `page_count`, `integrity_check`, `user_version`, `compile_options`; deny `PRAGMA x = ...` except by write path). Everything else is a write needing confirm and the actor path.
- Defence in depth for the read path: reject multi-statement input (a `;` outside string literals). Wrap as `SELECT * FROM (<stmt>) LIMIT 501` when the statement is a plain SELECT to enforce the 500-row cap at the engine and detect truncation by fetching cap+1; for `EXPLAIN`/`PRAGMA` cap in the mapper loop. On JVM/Android a hard guard is `PRAGMA query_only = ON` on a dedicated connection: Android's second read driver (`createReadDriver`) is a natural place; on JVM the pool has 8 shared connections, so setting a pragma on one is not reliable (pooled). Treat the parser classification as the primary control; do not depend on `query_only`. (grep: no existing `query_only` use.)
- Cancel: `QueryResult` is synchronous on JVM/Android; cancel via `Statement.cancel()` is not exposed by SQLDelight. Practical option: run in `runInterruptible` on `PlatformDispatcher.DB` and cap with `LIMIT` plus a deadline; document that a pathological query cannot be interrupted mid-step on Android (UNVERIFIED for sqlite-android `requery` driver, `kmp/build.gradle.kts:269`; android-driver 2.3.2 also in use).
- Wasm: `@sqlite.org/sqlite-wasm` OPFS SAH pool (`build.gradle.kts:238`) runs in a worker. `SqlDriver` there is async (`async-extensions`), so use `.await()` on `QueryResult`. Same SQL guard applies; no write actor differences.
- Pre-write backup (risk control): JVM/Android `VACUUM INTO '<path>'` (SQLite >= 3.27; sqlite-jdbc 3.51.3 bundled, `build.gradle.kts:171`; android uses requery sqlite 3.49.0) is the cheap consistent checkpoint; fall back to file copy plus WAL checkpoint (`PRAGMA wal_checkpoint(TRUNCATE)`) if VACUUM INTO is unavailable. Not available on wasm (skip, or export via sqlite-wasm `sqlite3_js_db_export`; UNVERIFIED).
- `DriverFactory.getDatabaseDirectory()` (`:28`) gives the DB location for backups.

## 4. Android in-process interpretation vs Runtime.exec

- No exec in the codebase except `jvmMain/.../platform/GitManager.kt` (and JVM benchmark tests) via `ProcessBuilder` (grep). Android has zero process-exec use today.
- `Runtime.exec`/`ProcessBuilder` on Android (INFERRED, platform facts): runs as the app uid in the app sandbox; PATH comes from `/system/bin` (toybox/`sh` present on every Android device, but no `git`, `sqlite3` or `busybox` guarantee); cannot read other apps' data or SAF trees (scoped storage; SAF content URIs are not paths, so `ls`/`cat` over a `content://` graph fails); since Android 10 executing files from the app's writable data dir (W^X, targetSdk >= 29) is blocked, so no downloaded binaries; SELinux denies a number of `/proc` and `/data` reads. Utility is limited to: `ls`, `cat`, `ps`, `df`, `getprop`, `logcat -d` (own app logs only for non-debuggable unless `READ_LOGS`), `ping`, `id`, `env`.
- Recommendation: make the in-process interpreter the primary surface on every platform (commands implemented in Kotlin against the repo's own abstractions: JGit `git`, `fs` over the existing `FileSystem` abstraction which already handles SAF, `sql`, `settings`, `logs`, `graph`, `diag`). `sh` is an optional, last-registered command: on JVM/Android `ProcessBuilder("/system/bin/sh","-c",cmd)` (Android) or `$SHELL` (desktop), `redirectErrorStream(true)`, stream stdout line-by-line, `Process.destroyForcibly()` on cancel, timeout default, working dir = app files dir, minimal env (strip tokens). Not registered on wasm/iOS. Answers Open Question 6: ship both, `sh` gated behind the second per-session confirm; do not promise `git`/SAF visibility from `sh`.
- Tokenizer: implement a small POSIX-ish word splitter (quotes, backslash) in commonMain, with no globbing/pipes in v1 (pipes are not needed for the stated use cases); property-test it.
- Redaction: console and logs must redact `https://user:token@`, `ghp_`/`github_pat_` and `Authorization:` patterns; reuse the userinfo-strip regex in `GitRefDiagnostics.kt` (`//[^/@]+@`) as the base.
