## Blockers

- [ ] **B1. The central guardrail (`WiringCompletenessTest`, Story 1.1) is placed where it cannot see its inputs and will not run on every PR.** It is a `jvmTest` that must read `desktop/Main.kt`, `androidApp/.../MainActivity.kt`, `SteleKitApplication.kt` and `ui/GraphContent*Setup.kt`. In Bazel (`kmp/src/jvmTest/kotlin/BUILD.bazel:53-98`) `jvm_tests` only has `source_audit_sources`/`wasm git_sources` in `data`, and `androidApp/` is not in the Bazel graph at all. This repo already hit this and solved it with classpath-resource bundling (`graph_content_wiring_test_sources_as_resources`, and `businessTest`'s resource idiom). `jvm_tests` is also tagged `requires-display`, so on a Wayland-only box (the owner's) the "cheap, every PR" gate is unverified until Xvfb exists (CLAUDE.md), contradicting Story 11.3 "Wiring gate runs on every PR". Plan never lists a BUILD.bazel/filegroup task. — **Recommendation**: add an explicit task: place the test in `businessTest` (no display, runs in `//kmp:business_tests`, register in `AllBusinessTests`), bundle all root files incl. `androidApp/src/.../MainActivity.kt`, `SteleKitApplication.kt` and `jvmMain/.../Main.kt` as classpath resources via a new filegroup, and make the test fail (not skip) when a root file is missing from the classpath. Add a negative test proving it fails under Bazel for a planted orphan.

- [ ] **B2. Console "credential tables are unreadable" (Story 3.2) is not implementable with the chosen design, and the Android read connection premise is wrong.** The design is "engine-enforced read-only connection, no classifier fallback". A read-only connection cannot deny reads of specific tables; that needs the SQLite authorizer (not exposed by xerial JDBC or the requery fork as far as the plan shows, and no spike covers it) or a statement classifier, which the plan forbids. Anything table-name-based is bypassable by CTEs, subqueries, views, aliases and `SELECT * FROM (SELECT ...)`. Also, `DriverFactory.android.kt:174 createReadDriver` returns a read-write `AndroidSqliteDriver` (second WAL connection, no `OPEN_READONLY`) and `DriverFactory.jvm.kt:144` returns `null`; Task 3.2b's "Android `createReadDriver` / `OPEN_READONLY`" reads as reuse. Reusing the app read pool would also let `abandon-and-close` (Story 3.2/Spike 0.3d) kill an app connection. Note that `git_connection` holds key aliases (`https_token_key`, `oauth_token_key`), not secret values, so the real exposure is smaller than the AC implies; the plan should say which tables actually need denial. — **Recommendation**: add Spike 0.3e: does either driver expose `sqlite3_set_authorizer`/an equivalent? If not, replace the AC with an honest one (secrets never live in `SteleDatabase`; list the tables with alias columns; redact those columns via the single `Redactor` and drop the "denied" claim), or serve the console from a copied DB with sensitive columns nulled. State explicitly that the console connection is a new, console-owned `OPEN_READONLY` connection that never shares the app's pool.

- [ ] **B3. Cloud egress claims in Epic 6 are partly false against the repo, and an existing Anthropic path is ignored.** (a) Story 6.3 says "`AirGapGuardTest`'s allowlist permits exactly the cloud plugin's HTTP module, and a new HTTP call elsewhere still fails it." `AirGapGuardTest` has no allowlist; it scans only `.../transfer/` for forbidden import substrings (`AirGapGuardTest.kt:23-44`). Nothing guards HTTP elsewhere, so the AC cannot be satisfied by "extending" it. (b) "Unconfigured app has no path to a third party" (Story 6.3) is false at HEAD: `ClaudeLlmFormatterProvider` (`MESSAGES_URL = https://api.anthropic.com/v1/messages`, `x-api-key`), `LlmProviderRegistryFactory` (`LlmCredentialStore.getApiKey("anthropic")`), `UrlFetcher*` and the OpenAI/Gemini providers already send note content to third parties. (c) Epic 6 builds a second Anthropic client and a second key store (`VaultCredentialStore`) next to the existing `LlmCredentialStore("anthropic")`, so the owner would have two places to enter, forget and revoke the same key, and "Forget API key" would not forget the other. — **Recommendation**: rewrite 6.3's criteria as a new `EgressSurfaceAuditTest` that enumerates every file constructing `HttpClient`/importing `io.ktor.client` in production and compares against a committed allowlist (this also documents the existing LLM providers). Decide in ADR-005: reuse `ClaudeLlmFormatterProvider`'s transport and `LlmCredentialStore("anthropic")` (recommended) or justify a second one; scope "no path to a third party" to the asset pipeline only.

## Concerns

- [ ] **C1. Definition of done depends on unshipped, out-of-plan work.** Success metric 4 ("pulls remote commits while open") is only met at Story 2.4, which depends at compile time on `ScheduledSyncPolicy`/guards that do not exist (grep empty) and that this plan declines to specify. The interim tick is `fetchOnly`, which fetches but does not merge. Story 11.5's final "N=0" and the traceability row for M4 cannot close. Plan Status says "Ready for implementation". — Add an explicit gate in the plan header: M4 is "partially met" until dev-plan PR-A1/A2 ship; or schedule them as a unit here. Do not mark Epic 2 complete at U2.
- [ ] **C2. Console backup can exhaust the phone.** `VACUUM INTO` on a 451 MB DB needs roughly that much free space and I/O; keep-last-5 is ~2.2 GB; no free-space precheck, no failure path ("backup failed, write refused"), no heap/time bound beyond Spike 0.3b's record. Auto Backup exclusions are covered, but not `adb`-less cleanup. — Require a free-space check (refuse write if free < 1.2x DB), keep 2 by default, show size in the confirm modal, and make "backup failed" block the write.
- [ ] **C3. Dry-run row count is unspecified.** "7 rows will change" for an `UPDATE`/`DELETE` needs either execute-and-roll-back inside an actor transaction (fires FTS/triggers, takes the single writer lock) or SQL rewriting (a classifier, which ADR-006 rejects). Task 3.3b ("`SELECT changes()` in the same lambda") describes executing. — Specify roll-back-in-transaction, a timeout, and what happens with statements that cannot be dry-run.
- [ ] **C4. 512 MB heap is asserted, not gated on Android.** The only heap test is JVM (`jvmTest/.../AssetStackStartupHeapTest`); the Android number arrives at device pass 12.2, after merge, and PR #501 itself says its cure is unproven. Specific unbounded risks not addressed: PDF text written to `ocr_text` has no length cap and `selectUnprocessedAssets`/`searchAssets` are `SELECT *`, so list queries materialize those blobs; the global-search `LIKE '%q%'` over `ocr_text` (Story 5.6) is a full scan per keystroke with no debounce stated; base64 of an 8 MB image plus bitmap held concurrently. — Cap stored text (e.g. 64 KB) and project columns in list queries; require debounce + `QueryPlanAuditTest` entry; add an Android Robolectric/instrumented bounded-heap assertion (-Xmx512m equivalent) before enabling the flag by default.
- [ ] **C5. Entry-point coverage gaps.** Every wired feature must have a test through its real root. Gaps: (i) `platformCaps` is built in `SteleKitApplication`/`desktop/Main.kt`, but fixtures inject fakes, so real `MlKitImageLabeler`/`AndroidPdfTextExtractor` construction is only text-matched; (ii) cloud plugin has no stack-level test with consent granted + key present + mock engine through `defaultAssetPlugins`; (iii) `KeyboardEmulationDeviceFactory` (Task 7.3a) and `AndroidUsbSerialFactory` register in app-level roots, with no test beyond the existing registry test; (iv) `PluginHost` (row 20) is covered by a settings component test, not the stack; (v) the catalog check only verifies the named test "references `GraphContentAssetSetup`", which a one-line comment satisfies. — Make the catalog check require that the test constructs the stack (e.g. calls `WiredAppFixture.*`), add a root-level test per platform that executes the real `platformCaps()` factory function, and add (ii).
- [ ] **C6. Egress ledger durability and revocation.** "Counters reset per process/day" does not say where the per-day count lives; if in memory, a process restart resets the cap. Revocation drops queued items but says nothing about an in-flight upload (cancel it). Consent is per graph but the key is global, so graph B can use the key graph A consented to unless the gate checks consent at upload time. — Persist the daily counter in `Settings`; cancel in-flight requests on revoke; check consent inside the upload call, not only at enqueue.
- [ ] **C7. Scope drift against `requirements.md`.** Out of Scope says "New product features beyond wiring existing code (except the console)". The plan builds real OCR (new port + ML Kit impl), a cloud HTTP client, USB-serial support with a new LGPL dependency and Bazel lock (7.3b), Google Photos/Drive surfaces (Epic 8), global-search Assets section (5.6a) and conditional semantic search (Epic 9). The 2026-10-27 owner decision ("wire; build out stubs if needed") covers much of it, but the requirements doc was not amended and Epics 8/9, 5.6a and 7.3b are beyond "stubs". — Amend `requirements.md` Scope to list these explicitly (do not cut them); otherwise the final traceability check has no basis.
- [ ] **C8. Hidden dependency / sequencing.** U13 (Epic 8) lists "U1" but Story 8.1 requires `AssetIndexService` registration (U7). Story 5.6 empty-state links to Settings > Plugins (5.5, U10) yet 5.6 is in U10 alongside it, fine, but 6.2 (consent UI inside `PluginsSettings`) needs 5.5; U11 depends on U10 only transitively. Task 3.1b (Redactor consolidation across ~12 files including `GitOperationSupport.kt`, a hot file the dev plan's PR-A1 also edits) is a merge-conflict hotspot and is a prerequisite of the whole console (U3). — Fix U13 to depend on U7; land the Redactor as its own early PR with only mechanical moves; document the ordering with dev-plan PR-A1.
- [ ] **C9. Redactor consolidation is broader than it looks.** `GitOperationSupport.kt` is in `jvmCommonMain`, wasm has its own git writer and credential code, and the plan wants `Logger`'s file sink, diagnostics export and the console all to call one commonMain class. A regex pass on every log line is a hot path on Android; the AC "secret-pattern literals in exactly one production file" must exclude tests and cover wasm. `ConsoleRedactor` (referenced as becoming "a thin alias") does not exist yet. — Add a cost note (benchmark per-line overhead; skip when no `ghp_`-style trigger substring), define the exact file scope of the audit, drop the `ConsoleRedactor` alias reference.

While the app is open the interval would be the user's value (5 min), but the settings text says "Android: at most every 15 minutes".
