## P1 Items (address before implementation)
- [ ] Failure #1: console writes and restore. Change U4-U6 in plan.md so that (i) Spikes 0.3a-e are a merge gate for U4 and U5, (ii) write and restore code is excluded from release builds until pass 12.1 on a copy of the real DB, (iii) U5 has a concurrent-actor-write-during-backup test on the emulator with a synthetic 450 MB DB, and (iv) a raw `INSERT OR REPLACE` FTS-consistency test is added to the Story 3.3 acceptance criteria.
- [ ] Failure #2: asset pipeline OOM and crash loop. Add the persisted-marker crash-loop breaker (auto-disable after 2 unclean exits) to Task 5.1b. Promote Task 5.2c's 512 MB emulator run to a blocking gate. Split U7 (indexing) and U9 (plugins) into separate releases. Add injected-`OutOfMemoryError` tests.
- [ ] Failure #3: false assurance from the wiring gates. Amend ADR-002 item 4 and Epic 1 so `WiringCatalog` tests assert an observable effect through the real root factory, add a planted dead-code-constructor negative test, add an "owner pass + flag-default decision" column to the Disposition Register, and require a first-open smoke test per new screen on the `androidApp` root.

## Notes on what this pre-mortem does not cover
- Metric 4 stalling on dev-plan PR-A1/PR-A2 is already declared in the plan (ADR-007, U16, wall-clock blocker 3), so it is not repeated as a failure mode. The risk remains that "partially met" becomes permanent.
- The plan's size (52 stories, 140 tasks, about 33.8M CU with verification, INFERRED) is itself a delivery risk. The plan's overrun checkpoint at +25% is the only control, and it is informational.
