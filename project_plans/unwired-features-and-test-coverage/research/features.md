## 3. Cross-cutting findings that change the plan

1. **The asset subsystem is two layers, both half-wired.** UI (`AssetBrowserScreen/ViewModel`, `GalleryScreen`) is wired and reads `AssetRepository`; every writer (`AssetIndexService.registerAsset`, `AssetMoveService`, `AssetPipelineService`, `replayPendingMoves`) is unreferenced. Wiring order that respects dependencies: (a) `AssetIndexService` into attach/import and graph load; (b) `AssetMoveService` + startup `replayPendingMoves`; (c) a plugin registry factory per platform from the ML classes above (on-device only); (d) `scheduleBackfill` behind a settings flag, bounded and cancellable (512 MB heap constraint); (e) cloud plugins last, opt-in.
2. **Desktop sync is not just the scheduler**: `startPeriodicSync` in the service is also uncalled, and on Android `GitSyncServiceRegistry.register` has no production caller (ADR-004 notes the same: "the worker's fast path is currently dead"; confirmed: `GitSyncServiceRegistry` is referenced only in `WorkManagerSyncScheduler.kt`).
3. **Delete set with no plan coverage** (all added in the `9b08f169ec` initial release, no tests): `RTCManager`, `VectorSearch` family, `DatalogEngine` family, `JsPluginBridge`, `MigrationCli`, `HtmlClipboardReader`, `command/` package, `PluginMigration`. Delete together with `CommandManagerCoordinator`; `./gradlew detekt` and compile must stay green (Bazel BUILD globs may need no change; verify).

## 4. dev-console-git-sync-fix: what PR-C requires, and what shipped

Sources read: `implementation/plan.md` (1309 lines; headings and Delivery table), `decisions/ADR-001,002,004,006`, git log, and symbol greps over `kmp/src`.

### Delivery structure (plan.md lines 11-24)
PR-A1 (typed errors, default-branch detection, repair, guards, first-sync review sheet) -> PR-A2 (scheduled full sync while open, fetch-only background, staleness UI) -> PR-B (lazy journals, diff/repair, index status) -> PR-C (console, ships dark behind developer-mode). Epic 7 is owner device verification. Release gating: A2 releases only after Story 7.1 passes on the device.

### PR-C requirements (Epics 4-6, Story 0.2)
- **Spikes (Story 0.2)**: 0.2a read-only enforcement per driver; 0.2b `VACUUM INTO` + live-DB swap; 0.2c raw-write cascade (does a `DatabaseWriteActor` invalidation trigger `GraphWriter`).
- **ADR-001 architecture**: new package `commonMain/.../console/` with `ConsoleCommand`, `ConsoleRegistry`, `ConsoleSession` (own `CoroutineScope(SupervisorJob()+Default+CEH)`, never `rememberCoroutineScope`); narrow `ConsoleContext` of nullable capability views (`ActiveGraphView?`, `GitConsoleView?`, `SqlConsoleView?`, `DbRestoreView?`, `ProcessRunner?`, `FileSystem`, `Settings`, `ConsoleRedactor`); composition root `ui/ConsoleComposition.kt` hosted by `ui/GraphContentConsole.kt`; `Screen.Console` route (`@HelpExempt`); setting `developer_mode_enabled`; commands never see `GraphManager`.
- **ADR-002 SQL**: reads only on a console-owned, engine-enforced read-only connection (`SqlConsoleReader`; JVM `SQLiteConfig.setReadOnly`, Android `createReadDriver`/`OPEN_READONLY`; iOS/wasm disabled unless a spike proves otherwise); no classifier fallback; 500-row cap by cursor, 2 KB per cell, timeout. Writes only via `DatabaseWriteActor.execute` with one `@OptIn(DirectSqlWrite)` raw-exec function in `SqlConsoleWriter` plus a `RestrictedDatabaseQueries` stub, a new `DirectSqlWriteOptInAllowlistTest`, hard-deny list (DDL, ATTACH, VACUUM, load_extension, writable PRAGMA, FTS tables, migration bookkeeping, credential tables), backups (`VACUUM INTO`, keep 5, first write per session and per destructive class), `graph restore-backup` swap with `DbOnlyRowsGuard`, Auto Backup exclusions in the manifest, nullable `sqlConsole` field on `RepositorySet` (conflicts with PR #397).
- **Commands**: `diag`, `git` family, `fs`, `sql` read/write, `settings`, `logs`, `graph` (`reload`, `reindex`, `journals-diff`, `journals-repair`, `index-status`, `restore-backup`), `sh` (desktop only, ADR-005), meta commands; tokenizer; best-effort redaction at one sink; scrollback buffer; confirm tiers; SQL result grid and CSV export; phone input ergonomics; accessibility suite; entry points and sync cross-link.
- **Dependencies**: needs A1 (typed errors, `git set-branch` via `BranchRepairService`) and B (`journals-diff`, `index-status`); Bazel placement of new commonMain sources (Task 4.1b); wasm compile check.
- **Mapping to the new requirements**: metric 3 (read-only SQL + diagnostics on device, writes blocked by default) is a strict subset of this plan; the plan's default is writes allowed with confirm and backup, which is stronger than "blocked by default" and should be reconciled with the owner (the requirements doc says "ADR-002: read-only by default"; ADR-002 itself says the owner chose full-power writes behind confirm).
