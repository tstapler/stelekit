# ADR-005: Cloud Claude plugin: consent enforced by a token at the call, shared Anthropic transport and key store, caps in the pipeline, EXIF strip, revocation; CloudVision dropped

**Status**: Accepted (owner decision 2026-10-27; amended by plan repair iteration 1) | **Date**: 2026-10-27

## Context
Data is confidential personal notes and images (faces, documents). `CloudEnrichmentConfig` has `enabled=false`, `sessionCap=20`, redacted `toString`, and an `apiKey` field. Both cloud plugins are stubs. Owner: wire `CloudClaudePlugin` with consent, cap, EXIF strip, revocation; drop `CloudVisionPlugin`.

Evidence read for the repair (all verified by grep/read):
- `voice/ClaudeLlmFormatterProvider.kt` already posts to `https://api.anthropic.com/v1/messages` (`MESSAGES_URL`), sets `x-api-key` and `anthropic-version`, wraps calls in an Arrow `CircuitBreaker`, maps errors via `LlmProviderSupport.mapHttpError`, and is reused by `ClaudeTopicEnricher` (`maxTokensOverride = 256`). Its request is text-only (`ClaudeMessage.content` is a `String`) and the model is a hard-coded constant, so it cannot send an image as is.
- `llm/LlmCredentialStore.kt` already stores Anthropic keys as `llm.anthropic.api_key` over the platform `CredentialStore`, with a Settings UI (`LlmProviderSettings`). `git/VaultCredentialStore.kt` is a different thing: an encrypted per-repo file unlocked with the vault DEK, unavailable while the vault is locked.
- `AirGapGuardTest` has no allowlist and only scans `transfer/` (`AirGapGuardTest.kt:23-44`); 20 production files already `import io.ktor.client` (recounted 2026-10-27; 23 for the loose word `HttpClient`), and the egress allowlist is generated from the test run, not typed. So "no path to a third party" is false for the app as a whole and was never testable by extending that test.
- `PlatformCaps` is built once per process (`SteleKitApplication`, `desktop/Main.kt`), but consent, key and switch are runtime per-graph state.

## Decision
1. **Reuse the existing Anthropic transport and key store.** Extract `AnthropicMessagesClient` (URL, version header, key header, circuit breaker, error mapping) from `ClaudeLlmFormatterProvider`; its content type grows from `String` to a list of text/image blocks; `ClaudeLlmFormatterProvider` delegates, and characterization tests prove the existing requests (including enricher `max_tokens: 256`) are byte-identical. `CloudClaudePlugin` calls the same client. The API key is read from `LlmCredentialStore.getApiKey("anthropic")` at call time; `CloudEnrichmentConfig.apiKey` is removed. A second client or a `VaultCredentialStore` key is rejected: the owner would have two places to enter, forget and revoke one key. "Forget API key" deletes the shared key and the UI says it also disables Claude voice formatting. The model id for vision is looked up at implementation time (claude-api skill), not hard-coded from memory.
2. **Consent is parsed at the boundary.** `CloudConsent` sealed type (`NotAsked` / `Granted(ProviderId, at, scope)` / `Revoked(at)`), stored per graph and provider in `Settings`, default `NotAsked`. `CloudConsentGate.grant(graphId, provider): GrantedConsent?` returns a token only when consent is `Granted` for that graph and the key exists, reading both on every call. `CloudClaudePlugin.processAsset` requires the `GrantedConsent` parameter, whose constructor is `private` with the gate as the only construction scope (Kotlin `internal` is module-wide, so it would not restrict minting); `GrantedConsentMintSiteAuditTest` asserts `GrantedConsent(` appears only in the gate and tests mint through the real gate over fake `Settings`/`LlmCredentialStore`; the upload path cannot be called without it.
3. **Second enforcement point in the pipeline.** `AssetPipelineService` obtains the token per asset, next to `EgressLedger`, so a future plugin cannot bypass it and a revoke takes effect mid-drain (no capture at enqueue or start). A missing token means the asset is skipped for the cloud plugin (not marked failed) and zero HTTP calls are made. Consent for graph A never authorizes graph B although the key is global. An in-flight request is cancelled on revoke.
4. **`PlatformCaps.cloud` is a factory** (`CloudPluginFactory`), not a start-time constant; `defaultAssetPlugins` omits the plugin when it is null and the plugin list is re-derived on the next drain after a grant or revoke. The structural test is "the cloud client is referenced only from `CloudClaudePlugin`, which is constructed only through the factory in `defaultAssetPlugins`".
5. Caps counted in the pipeline (`EgressLedger`): session cap, per-asset size cap, and a per-day cap whose counter is persisted in `Settings` so a restart does not reset it; a stopped pipeline says why (sealed `PauseReason`).
6. Strip EXIF/GPS and downscale before upload; assert on the payload bytes.
7. Skip when offline or metered (`NetworkMonitor`); no automatic retry loop on 4xx/5xx, and no "upload anyway" override on a metered network. `NetworkMonitor` has no metered signal at HEAD (it exposes only `isOnline`), so Task 6.3c adds `isMetered: Boolean?` (Android maps `isActiveNetworkMetered`; other platforms return `null` and copy never claims "unmetered" there).
8. One INFO log line per upload (asset uuid, bytes, provider), no content.
9. **Egress surface is audited, not claimed away.** A new `EgressSurfaceAuditTest` (`businessTest`) lists every production file that constructs an `HttpClient` or imports `io.ktor.client` against a committed `egress-allowlist.txt` with a destination class per entry; it documents the existing LLM providers, URL fetchers, Google and git clients, and the asset pipeline adds no new entry. `AirGapGuardTest` stays as the `transfer/` guard. The privacy claim is scoped to the asset pipeline.
10. Revocation drops queued items immediately and reports the count.
11. **Cloud description storage and labelling.** The result is stored through `AssetRepository.updateCloudDescription(uuid, text, mlTagsSource="CLOUD_CLAUDE")` into the existing `asset_index.cloud_description` column in the same actor transaction as the processed flag; it is never written to `ocr_text` (ADR-004), no schema change is needed (verified against `SteleDatabase.sq:1143-1163` and the `asset_index_table` migration), and search results report which column matched so the UI shows "AI description" (UW-56) versus text found in the image. Stored descriptions survive revocation; the UI offers "Delete AI descriptions" for the graph (Task 6.2d).

## Alternatives rejected
Global consent (not per graph/provider); per-asset override (nice-to-have, not built); keeping `CloudVisionPlugin` (second provider, second credential flow); a second Anthropic client with a `VaultCredentialStore` key; checking consent only when the plugin is constructed or enqueued (stale after revoke, wrong across graphs); extending `AirGapGuardTest` with an allowlist (it scans one package by design).

## Consequences
`ClaudeLlmFormatterProvider` is touched by a behavior-preserving extraction (Task 6.1a) before any cloud code is added. Revoking the Anthropic key affects voice formatting too, and the UI says so.

## Addendum (triad repair iteration 3, 2026-10-27)
- **Consent scope is part of the consent.** `CloudBackfillScope` (`NewOnly` default, `IncludeExisting`) is stored in `CloudConsent.Granted`. With `NewOnly` the pipeline makes zero cloud requests for assets imported before the consent time (`AssetEntry.importedAtMs`; semantics for backfilled files UNVERIFIED, Task 6.2c). The dialog names the graph and shows the live backlog count and day estimate, so the owner never consents to the backlog without seeing its size.
- **Backups and consent.** Consent, the run marker and the egress counter live in `Settings` and are excluded from any Android backup (the manifest already sets `allowBackup=false`; Task 3.3c adds rules as defense in depth), so consent cannot be restored onto another device.
