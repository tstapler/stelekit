# ADR-002: Wiring completeness is enforced by a source-audit test, a baseline-diffed scan and a feature catalog

**Status**: Accepted (amended by plan repair iteration 1, 2026-10-27) | **Date**: 2026-10-27

## Context
Dormant seams survived because nothing failed when an implementation was never constructed (`DesktopSyncScheduler`, asset plugins, `WaybackMachineService`). Detekt has no unused-public-declaration rule; R8 `-printusage` is Android-only and needs a minified build (`isMinifyEnabled = false` today).

Repair-iteration finding (verified): the first draft put `WiringCompletenessTest` in `jvmTest`. That cannot work as the central gate. `androidApp/` is not part of the `kmp/` Bazel graph (only `androidApp/BUILD.bazel` exists), `//kmp/src/jvmTest/kotlin:jvm_tests` carries the `requires-display` tag (`kmp/src/jvmTest/kotlin/BUILD.bazel:85-87`) so it is unverified on the owner's Wayland-only session, and `CaptureWriterSourceAuditTest` resolves sources by walking the working directory, which is empty under the Bazel sandbox.

## Decision
1. `WiringCompletenessTest` is a **`businessTest`** source audit (no display; runs in `//kmp:business_tests`; registered in `AllBusinessTests`, so `AllBusinessTestsCompletenessTest` covers it). For each listed seam interface, every implementing class must appear as `Name(` in a fixed set of composition-root files. Exemptions live in `businessTest/resources/wiring-allowlist.txt` (`ClassName  reason  YYYY-MM-DD  renewals=N`); entries expire after 90 days and may be renewed at most twice (third expiry fails; clear it by wiring, deleting, or an ADR-001 amendment; an entry owned by an owner-gated unit may instead be converted once to a non-expiring, nightly-listed `blocked-on-owner <OD-n or pass 12.n>` entry, plan Glossary `WiringAllowlist`). The allowlist is the only input of this test; `ReachabilityBaseline` is the separate input of the Story 1.2 scan (plan Glossary and Task 1.1b define how the two relate). At U1 every seam implementation that no root constructs is seeded as `awaiting-unit <Un>` so the test is green on merge and the expiry/renewal cap is the forcing function.
2. **Root files are classpath resources**, not working-directory reads: a new filegroup per owning package (`androidApp/BUILD.bazel` for `MainActivity.kt` and `SteleKitApplication.kt`, `kmp/src/jvmMain/kotlin/BUILD.bazel` for `desktop/Main.kt`, `kmp/src/commonMain/kotlin/BUILD.bazel` for the `GraphContent*Setup.kt` set, `ui/StelekitAppDependencies.kt`, `RepositoryFactory.kt`, `defaultAssetPlugins`) bundled by one `java_library(resources=...)` **per distinct `resource_strip_prefix`** in `kmp/src/businessTest/kotlin/BUILD.bazel` (strip to `.../stelekit` where bare names collide: `desktop/Main.kt` vs `browser/Main.kt`), the same idiom as `graph_content_wiring_test_sources_as_resources` (`jvmTest/BUILD.bazel:29`) and `git_shadow_worktree_as_resource` (`businessTest/BUILD.bazel:31`). The test **fails with `root not found`** when any root is absent from the classpath; an empty root set never passes. The data files (`wiring-allowlist.txt`, `wiring-catalog.txt`, `egress-allowlist.txt`, the reachability baseline) have no Bazel path by default (`kmp/src/businessTest/resources` does not exist; `business_tests` globs only `**/*.kt`), so they get their own filegroup and `java_library` resource bundle (Task 1.1c). A negative test plants an orphan implementation and must fail under the Bazel sandbox (Task 1.1c).
3. `reachability-scan.py` runs in CI against a committed `ReachabilityBaseline`; new unreferenced types fail, the baseline may only shrink. Calibrated once against R8 `-printusage` and, if available, IntelliJ headless "Unused declaration".
4. `wiring-catalog.txt` maps each seam to the entry-point test class and an observable effect (`Seam  EntryPointTest  effect:<label>`); the check requires that class to exist, to call `WiredAppFixture.` (or the platform root factory under test), to reference the stack file, and to call `ObservableEffect.assert("<label>")` after invoking the real root factory. The assertion is about runtime state (for example `asset_index` row count > 0 after loading a fixture graph, or a `SyncTick` log line after the interval), so a feature that is constructed but never runs fails. A comment mentioning the stack does not satisfy it (amended by repair iteration 2, pre-mortem P1-3). A planted dead-code-constructor fixture (Task 1.1e) must fail this check, and a first-open smoke test per new screen runs on the `androidApp` root (Task 1.3c).
5. Registration is a total function of platform capabilities where possible (`defaultAssetPlugins(PlatformCaps)`, `backgroundSyncSchedulerFactory`) with **explicit `NONE` sentinels and no defaults** on `StelekitAppPlatformIntegrations` (`ui/StelekitAppDependencies.kt:87`; hosts `desktop/Main.kt:221`, wasm `Main.kt:364/:511`, `MainActivity.kt:475` each name their value), so omission is a compile error. Entry-point tests for platform capabilities execute the real root factory functions (`platformCaps()`, `defaultMeasurementDeviceFactories()`), not fakes.

## Limits (stated)
Text matching passes a constructor that lives in dead code; the scan and the observable-effect entry-point test are the second and third layers, and only the latter catches dead code (the name-based scan does not). Every feature ships flag-off, so metric 1 reads a zero only after the owner device pass and flag-default decision are recorded (ADR-001). Reflection and manifest-registered components are handled by explicit filters, not inference. The `jvmTest` display requirement still applies to every other `jvmTest` UI test, but not to this gate.

## Alternatives rejected
R8-only (Android-only); custom compiler-resolved call graph (cost, no tool for KMP); code-review discipline (already failed: 24 dead `editor.*` files); `jvmTest` placement with working-directory file walk (cannot see `androidApp/`, requires a display, passes silently with an empty root set).
