# ADR-004: Asset services are built in a per-graph `GraphContentAssetSetup` stack; plugins from `defaultAssetPlugins(PlatformCaps)`; bounded drain

**Status**: Accepted (amended by plan repair iteration 1) | **Date**: 2026-10-27

## Context
`AssetIndexService`, `AssetMoveService`, `AssetPipelineService`, `PluginRegistry` and five plugins have no non-test construction site; the `asset_index` table is populated by nothing in production. `AssetPipelineService.drainUnprocessed` advances `offset += batchSize` over a result set whose rows leave the set as they are processed (suspected skip, unproven until Task 0.4a). `OcrPlugin` joins `ImageLabeler` labels. Phone heap is 512 MB.

## Decision
- Services are built in `ui/GraphContentAssetSetup.kt` (same shape as `GraphContentGitSyncSetup.kt`), started after `onFullyLoaded`, torn down by `DisposableEffect`, gated by `asset_pipeline_enabled` (default false). They are not fields on `RepositorySet` (consistent with `asset-management/research/architecture.md` §C).
- `defaultAssetPlugins(PlatformCaps)` is the only registration site; `PlatformCaps.cloud` is a factory (not a start-time constant) and the cloud plugin is constructed only through it, with consent enforced per asset (ADR-005). `platformCaps` and `backgroundSyncSchedulerFactory` are non-defaulted fields on `StelekitAppPlatformIntegrations` (`ui/StelekitAppDependencies.kt:87`) with explicit `PlatformCaps.NONE` / `BackgroundSyncSchedulerFactory.None` sentinels; the default constructions at `:270`/`:292` are removed.
- `AssetPipelineService.writeActor` is a non-null constructor dependency; the nullable parameter and `DirectRepositoryWrite` fallback (`AssetPipelineService.kt:37,77-93`) are deleted so no pipeline write bypasses `DatabaseWriteActor`. List queries are projected (no `ocr_text`/`auto_labels` in list rows) and `ocr_text` is capped at 64 KB before write.
- Drain: read offset 0, skip an `AttemptedSet` cleared per run, advance only past rows that stay unprocessed (the `GraphLoader.indexRemainingPages` pattern). One plugin call in flight, on `PlatformDispatcher.Default`; Throwable-guarded with a per-plugin circuit breaker; cancelled on memory pressure (via a listener registry notified from `StelekitViewModel.onMemoryPressure()` at `:1440`, reached from `MainActivity.onTrimMemory`) and graph switch.
- `OcrPlugin` takes a new `TextRecognizer` port (ML Kit on Android, no-op elsewhere). Labels and OCR text are written in one actor transaction with the processed flag.
- Images are downscaled (`ImageDownscalerPort`, later `DecodeBudget`) before any ML or cloud call.
- **Crash-loop breaker (pre-mortem P1-2).** The pipeline persists a `PipelineRunMarker` when a run starts and clears it on clean pause/finish/cancel; two consecutive unclean exits force `asset_pipeline_enabled=false` (Task 5.1g), because a user whose app dies on launch cannot reach Settings.
- **Staged release.** Indexing (U7/U8) and on-device plugins (U9) ship in different releases, after owner passes 12.2a and 12.2b respectively; Task 5.2c (512 MB `Pixel_Fold` run with the real pipeline over a synthetic 9.5k-page graph) is a blocking gate for U8, and injected-`OutOfMemoryError` tests cover the plugin, downscale and `ocr_text` write paths.
- **Cloud text has its own storage.** `asset_index` already has nullable `cloud_description` and `ml_tags_source` (`SteleDatabase.sq:1152,1161`, `updateAssetCloudDescription` at `:1211`), so cloud-derived text is stored there and never in `ocr_text`; no new `ai_description` column or `MigrationRunner` entry is added (it would duplicate existing columns). The search queries are extended to match `cloud_description` and report the matched column so the UI can label it "AI description" (Task 6.2d). If Task 6.2d finds the `ml_tags_source` value set cannot carry the marker, the fallback is a nullable additive column with a `MigrationRunner.all` entry and regenerated sources.

## Alternatives rejected
Construct inside `StelekitViewModel` (hotspot); eager plugin construction (startup heap); process on `PlatformDispatcher.DB` (blocks pooled connections); keep the label-joining `OcrPlugin` (mislabels data in `ocr_text`).
