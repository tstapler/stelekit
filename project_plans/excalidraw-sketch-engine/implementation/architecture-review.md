<details><summary>Original blockers (resolved)</summary>

- [ ] Story 1.4.2 / 1.1.1 / 1.4.2c (and Story 4.2.1c) — **The bundle pipeline is v1-only and the plan never changes its pivot types, so the reconciler will overwrite or lose v2 sheets.** Verified: `SidecarCodec.encode(ProjectBundle)` builds each sheet file solely from `bundle.primitives` (`ProjectModelJson.kt:46-58`, `sheetJson` emits `primitives[]` only); `decodeUnsafe` reads only `primitives`; `SidecarReconciler.loadLocal` builds the bundle from `repos.sheets.getPrimitives` and `reconcile()` computes `localHash = bundleHash(encode(local))`, then `WriteLocal` pushes it (`SidecarReconciler.kt:111-135`); `replaceProjectContents(uuid, ProjectBundle)` is the only pull path. `ProjectBundle` (`model/SketchModels.kt:86`), `SidecarReconciler.kt` and `replaceProjectContents` (SQLDelight and InMemory repos) are in no story's Files list. With the plan as written, the first reconcile after a v2 save re-encodes the sheet as a primitives-only `schema:1` file (v2 elements live only in `sketch_elements`/the v2 codec), the hashes differ, and the v2 sheet is silently overwritten (data loss) or a `Conflict` is raised on every sync. Also unspecified: where v2 sheets' zones, named layers, scale and dimensions live (today they are in the model's `sheetRef`, not the sheet file), and whether `V2ToV1.project` output is written into `sketch_primitives` (which would then be encoded into the bundle) or only read in memory for fusion. — Remediation: add a Story in Epic 1.1 (before 1.4.2) "Bundle model carries schema-2 sheets": extend `ProjectBundle` with a `sheetPayloads: Map<SheetUuid, SheetPayload>` sealed type (`V1(primitives)` / `V2(scene bytes or SketchDocumentV2)`), make `SidecarCodec.encode/decode`, `SidecarReconciler.loadLocal/pull/importNew`, and both `replaceProjectContents` implementations dispatch through `SheetCodec` per sheet schema, keep sheet-level metadata (zones, layers, scale) in `sheetRef` for both, and state that fusion reads `V2ToV1.project` in memory only (never written to `sketch_primitives`). Add a golden test: v2 sheet, encode, reconcile with unchanged DB, assert `Unchanged`/no write and byte-equal file. List these files in Story 1.1.1 and 1.4.2.
- [ ] Story 1.4.2 (acceptance "Crash between steps loses nothing") — **The stated crash guarantee contradicts the verified write path.** `sheetPath(uuid)` is fixed (`sheets/<uuid>.json`), `decodeUnsafe` returns `Corrupt(Truncated)` when `sha256(sheet bytes) != model.fileSha256`, `writeLocked` writes sheets first and the model last, and `ReconcileDecision` on a corrupt disk bundle is `KeepCorrupt` (never repaired). So "backup written, v2 sheet written to the same path, crash before the model write" leaves a v2 sheet whose hash does not match the still-v1 model: the project is `Corrupt(Truncated)`, not "the v1 sheet is still the referenced sheet". The v1 bytes exist only in `backup/`, and nothing reads them back automatically. The plan's "single bundle write switching the reference" is not atomic across two files in this store. — Remediation: pick and spec one of (a) a deterministic recovery rule in the reader/converter: on open, if `backup/<uuid>.v1.json` exists and `sha256(backup) == model.fileSha256`, treat the bundle as "conversion in progress", restore the sheet file from backup and re-run conversion (tested by crash injection at each of the three write points); or (b) write the v2 sheet under a distinct path first, then flip the model's `fileSha256`/path in the single model write, so the old file stays valid until the model switches. Rewrite the Story 1.4.2 acceptance criterion to match the chosen mechanism and add the crash-injection test at every step boundary. Also extend `FileProjectSidecarStore` for `backup/` (today `writeLocked` creates only the slug dir and `sheets/`; `backup/<uuid>.v1.json` needs `createDirectory` and is outside `Present(files)`/`bundleHash`, so its content is invisible to the three-way hash), and make Task 0.1.1b a code change, not a note.

## Re-review of blockers 1 and 2 (against repaired plan.md Stories 1.1.3, 1.1.4, 1.4.2, 1.4.5, ADR-001 4a, ADR-005)

Verified in code: `ProjectSidecarStore.kt` (`readLocked` L78-96, `writeLocked` L107-123, `write` L98-105, `flushPending` L157-166), `SidecarFileState.kt` (`SUPPORTED_SCHEMA = 1L`, L41), `ProjectModelJson.kt` (`encode` L50-60, `decodeUnsafe` L155-205), `SidecarReconciler.kt` (`reconcile` L114-139, `loadLocal` L189-214), `SqlDelightSketchRepositories.replaceProjectContents` L171-190 (deletes all of a project's rows, re-puts from the bundle), `InMemorySketchRepositories.replaceProjectContents` L92-100.

### Blocker 2 (crash safety): RESOLVED, protocol is sound
Walking each boundary against the verified write path (v1 file `sheets/<uuid>.json` stays hash-valid and referenced until the model's atomic rename):
- Crash after S1/S2/S3: model unchanged, `sha256(v1) == fileSha256`, so no `Corrupt(Truncated)`; staged `sheets/<uuid>.v2.json` is unreferenced. Truncated temp files end in `.tmp`, which the `.json` filter in `readLocked`/`writeLocked` never sees.
- Crash after S4 (model renamed, v1 not yet deleted): model references the v2 file whose sha matches; stale v1 file is unreferenced. Crash during S4: rename is atomic, so it is either S3 state or S5 state.
- DB lags disk after S4 (DB row still `schema_version=1`): `reconcile` sees local==base, disk!=base, so `Rebuild`/pull, which 1.1.3 now handles for `V2Opaque`. No loss.
The protocol is correct ONLY if the store changes in Task 0.1.1b are real. Today `readLocked` lists every `sheets/*.json` and classifies each, so a staged v2 file would make the WHOLE project `Corrupt(NewerSchema)` for any reader. Follow-ups (CONCERNS C1-C3 below).

### Blocker 1 (per-schema dispatch): RESOLVED for the sidecar/DB pipeline; two uncovered paths
Covered and consistent with code: `SidecarCodec.encode/decodeUnsafe`, `SidecarReconciler.loadLocal/pull/importNew/reconcile`, both `replaceProjectContents`, `ProjectBundle`/`SketchSheet`, fusion/CSV/SVG/digest (1.4.5), technical data kept in the model (1.1.4; matches `sheetRef`/`dimensions[]` in `modelJson`). Not covered: see C4 (embed preview) and C5 (legacy editor load).

## Re-review follow-ups (must be specced in the plan before Phase 5; none requires redesign)
## Concerns
- [ ] **C1 (gates 1.1.3/1.4.2)** `readLocked` must parse the model FIRST and read only referenced sheet files (`sheetRef.file`, default `sheets/<uuid>.json`); today it classifies all `sheets/*.json` before the model is parsed (L81-94). Task 0.1.1b item (3) states the outcome but not this reordering. Also `SidecarClassifier.SUPPORTED_SCHEMA = 1L` is global: it must become per-file-kind (sheets accept 2, model stays 1) or every referenced v2 sheet is `Corrupt(NewerSchema)` to the new reader. Story 0.1.1's gate test uses a `schema:2` fixture while its title/AC say `schema:3`; after this change the fixture must be schema 3 (or the pre-change reader).
- [ ] **C2 (gates 1.1.3, data-loss class)** Reconciler read-modify-write on v2 bytes. `loadLocal` takes v2 bytes from the sidecar file and `push` writes them back in a separate `store.write` call (`reconcile` L116-128; the store mutex only spans one call). The v2 file has no DB copy, so a reconcile that loaded bytes at t0 can overwrite a newer autosave written at t1 (`replace` skips only byte-identical files), and a stale push can also revert the S4 model flip. The plan says "writes its unchanged bytes (or skips the write)": decide it. Recommended: the reconciler NEVER writes `V2Opaque` bytes (store takes `files` plus an `expectedSha` for each v2 path, or `write` skips paths marked opaque), and all sidecar writers (reconciler push, SheetSaver, SheetConverter, restore 6.2.6) serialise on one per-slug lock spanning read-plan-write. Add a test: saver write between `loadLocal` and `push` survives.
- [ ] **C3 (1.4.2)** Converter must handle `SidecarWriteOutcome.Deferred` (git sync busy): S2/S4 return `Deferred` and park the WHOLE bundle map in `pending[slug]` (last-wins, replayed by `flushPending` later), so S3 read-back fails and a stale queued snapshot can later overwrite a newer one. Spec: converter aborts without queueing (new `writeNow` that returns `Deferred` without `pending`) and retries on the next trigger; add `Deferred` at each step to the crash-injection matrix. Also state that a staged `sheets/<uuid>.v2.json` is deleted by any intervening `writeLocked` whose `files` lacks it (harmless, retry), and the converter holds the C2 lock across S2-S4.
- [ ] **C4 (uncovered v1-only path)** `ui/sketch/SketchPreviewLoader.kt:37` (used by `SketchPreview`, `ScreenRouter.kt:458`) reads `getPrimitives` from the DB. A converted sheet has no DB primitives, so embeds render empty from the moment the flag can be enabled, but dispatch is only planned in Story 6.1.1 (Phase 6) and is not part of the `ConversionReady` gate. Either add `SketchPreviewLoader` to Story 1.4.5 (dispatch on `schema_version`, project in memory) or add Story 6.1.1 to `ConversionReady`.
- [ ] **C5** `ui/sketch/SketchStore.kt:30` (legacy editor load) also reads DB primitives; it is safe only via the router matrix. State that the legacy `SketchViewModel` refuses any sheet with `schema_version=2` at the store level (defence in depth), not only in `SketchEditorRouter`.
- [ ] **C6 (1.1.3/1.4.4)** v2 sheet metadata round trip: `encode(local)` rebuilds `sheetRef` (kind, scale, `layers`, zones, `file`, `schema`) from the DB `SketchSheet`. If SheetSaver updates the layer mirror in the model file but not the DB row, local and disk model bytes diverge permanently (Conflict loop). Spec that SheetSaver updates the DB sheet row (layers, `schema_version`, sha) in the same operation, `SketchSheet` carries `file`/`schema`, and `encode` emits `sheetRef.file` for schema 2. Add a golden: v2 layer edit, reconcile reports `Unchanged`.

- [ ] ADR-001..007 all `Status: Proposed` while plan.md says "Ready for implementation" — ADR-003 is gated by Spike 0.1.2 and ADR-001 by 0.1.1/1.1.1 by design, but nothing gates Phase 1-3 stories on ADR-002/004/005/006/007 reaching Accepted. Recommendation: flip 002/004-007 to Accepted at plan sign-off; keep 001/003 gated.
- [ ] Story 1.4.3 `SheetLease` and `SketchEditorRouter` placed in `CM/ui/sketch/SketchStore.kt` — `SketchStore` is `internal` to `ui.sketch` and is a repository-access helper; a lease is an application-level ownership rule shared by two editors, the preview/embed path and the importer. Recommendation: put `SheetLease` in a UI-free package (`sketch/v2/session` or `projectbridge`) behind an interface, keep only the router in `ui`.
- [ ] `CM/sketch/v2` mixes the pure engine (scene, commands, tools, hit, index, render) with `V2/persist/SheetSaver`, `SheetConverter`, `V2/constraints/SolveRunner` (own coroutine scope), `V2/image/ImageAssetStore` and `V2/telemetry`. Import-direction tests exist only for `sketch.constraints` and the importer. Recommendation: add `SketchV2EngineImportDirectionTest` (scene/commands/tools/render/hit/index import nothing from `ui`, `db`, `repository`, `projectbridge`, `merge`, and no coroutine scope) and put persistence and runners in `sketch/v2/runtime` so the ports-and-adapters claim is enforced, not asserted.
- [ ] `ElementBase` carries `groupIds`, `frameId`, `containerId`, `boundElements` as free-standing strings that `reconcile` repairs after the fact (Story 1.2.3). Parse-at-boundary is good at import, but internal commands can still construct illegal states. Recommendation: make `reconcile` an assertion in tests plus a total `Scene.validate()` used by `SketchSceneV2` factory for import/load only, and model bindings as `Binding` owned by the arrow with `boundElements` derived (not stored) in the scene, removing the reciprocity invariant.
- [ ] DB cache write amplification: `sketch_elements` is one row per element (5,000 rows) and every autosave goes through `DatabaseWriteActor`; Story 1.4.4 does not say whether the saver diffs by `changedIds`/`version`. Recommendation: specify delta writes keyed by `(id, version)` and a sheet-level replace for conversion/import, and add a benchmark to `sketch-engine-budgets.json`.
- [ ] Story 1.4.1 adds `sketch_sheets.schema_version` but nothing reads it: router and dispatcher key off the sidecar `schema`. Either drop the column or define it as the DB mirror consumed by `SketchRenderDispatcher` (avoids parsing JSON per embed), and say which is authoritative when they disagree (file wins, per ADR-001).
- [ ] OD-1 (old-build fail-closed blast radius is the whole project, verified) blocks Story 1.4.2 but the first-write confirmation is a UI hook (Task 1.4.2c) inside a persistence story; keep the policy in the router/editor and have 1.4.2 expose only a `requiresConfirmation` result.
- [ ] Story 4.2.4 wires fusion through `ProjectFusionSource` as an M task but `V2ToV1.project` rounding (ADR-002) must produce the same `SketchPrimitive` ids/z/layer ordering the fusion stage and `SketchCsvWriter` expect; add a golden over a mixed v1+v2 project (some sheets converted, some not) since fusion currently reads DB primitives per sheet.
