# Pre-mortem: excalidraw-sketch-engine
**Date**: 2026-11-14

Premise: the project shipped, and within a month either a user lost sketch data or the engine failed to deliver the headline outcomes. Code claims below were checked against the repo at `db40c57e56` (VERIFIED = read in code this session; INFERRED = reasoned from the plan).

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | The DB mirror `schema_version` is silently reset to 1, so a v2 sheet is treated as v1. VERIFIED: `insertSketchSheet` is `INSERT OR REPLACE INTO sketch_sheets (uuid, … position)` with no `schema_version` column (`SteleDatabase.sq:1503-1505`), so any call to it resets the new column to its DEFAULT 1. The legacy editor then loads zero primitives, saves an empty v1 sheet, and `writeLocked` deletes every `sheets/*.json` absent from the new map (`ProjectSidecarStore.kt:119-121`), which includes `sheets/<uuid>.v2.json`. | A converted sheet opens blank in the legacy editor, or the `.v2.json` file vanishes after a dimension edit or legacy open. | Story 1.4.1 must change `insertSketchSheet` (and its `RestrictedDatabaseQueries` stub and both `replaceProjectContents`) to carry `schema_version`, with a test that every sheet-row write path preserves a value of 2. Make the router and legacy `SketchStore` refusal read the FILE's schema when the mirror and file may disagree (file wins, ADR-001). Restrict `writeLocked`'s unreferenced-delete to files whose bytes classify as schema 1; a schema-2 file is deleted only by S5 or restore, never by the generic sweep. | P1 |
| 2 | A parked or replayed v1-shaped bundle destroys a v2 sheet. VERIFIED: `write()` parks the whole `files` map last-wins in `pending[slug]` when git sync is busy (`ProjectSidecarStore.kt:98-103`), and `flushPending` later calls `writeLocked(slug, files)` unconditionally (`:157-166`). The plan's `opaque`/`expectedSha` check (Story 1.1.3) is specified for `write` only and `writeNow` for the converter. A map parked before conversion, or one built by a dimension edit, replays after S4 and rewrites the model back to v1, or deletes the v2 file. | After a git pull or sync-idle, a converted sheet reverts to its pre-conversion state, or `Corrupt(Truncated)` appears because the model sha no longer matches the file. | Apply the `opaque`/`expectedSha` check at flush time, not park time. Store parked entries as intents (re-plan on flush) or re-validate every opaque sha under the mutex and drop the entry as `StaleOpaque` on mismatch. Add a store-level test: park a bundle, run S1-S4, `flushPending`, assert the v2 file and model flip survive. Add this to the `SidecarWriterRaceTest` matrix and to the Story 1.1.3 AC. | P1 |
| 3 | An open v2 editor overwrites another device's edits. INFERRED (plan has no handling; grep for external-change / base-sha / pull-while-open finds nothing): the owner uses desktop, Android and web over git sync. `SheetSaver` debounces and writes the whole file with an in-process version counter only. A `pull` that replaces `sheets/<uuid>.v2.json` while the sheet is open is invisible to the editor, whose next autosave overwrites it. The slug lock serialises writers but does not detect staleness. | A sketch edited on the phone loses its changes after the desktop session autosaves; no error shown. | `SheetSaver` carries the sha of the file it loaded or last wrote (`baseSha`) and does compare-and-swap under the slug lock. On mismatch it does not write: it saves the in-memory scene as `<uuid>.v2.conflict-<hash8>.json` (never named `sheets/*.json`), raises a `SketchDiagnostics` entry, and offers reload or keep-mine. Add an AC and test to Story 1.4.4: external replace during an open session, then autosave, must not lose either version. Subscribe the editor to pull events for the open sheet. | P1 |
| 4 | Old or lagging builds make the whole project unreadable after the first v2 write. VERIFIED: `classifyJson` maps `schema > SUPPORTED_SCHEMA(1)` to `Corrupt(NewerSchema)` (`SidecarFileState.kt:26,41`) and `readLocked` returns `Corrupt` for the whole project on the first bad file (`ProjectSidecarStore.kt:84-96`). The plan accepts this (OD-1), but it hits every v1 sheet, dimension, fusion and LLM digest of that project on any device not yet updated (Android release lag, wasm cache). Conflict copies (`writeConflict`) also accumulate on the old device. | Android on the previous release shows the project as corrupt or empty and digests stop; user reports "my sketches are gone". | Keep OD-1 but make the one-time confirmation name the exact consequence and list devices (app versions seen by sync, if known). Gate the FIRST v2 write on a minimum-supported-reader release being out (version check against the graph's last-seen build, or ship the reader-only release, Stories 1.1.1/0.1.1b/1.4.1, one release before conversion is reachable). Add "reader-first release" as an explicit milestone in the staged rollout. | P2 |
| 5 | The solver misses the robustness bar, so constraint sketching (success metric 3) ships flaky or not at all. Pure-Kotlin LM with Jacobian rank, redundancy and conflict classification, no branch flip on drag, 100 constraints in under 50 ms on wasmJs. INFERRED: spike 0.1.2 passing on 40 lines does not predict tangent, symmetric and angle constraints on arcs and splines; the clean-room rule also removes the easiest reference (planegcs). | Spike exit criteria miss, or in beta, dragging a constrained shape jitters, flips sides or reports spurious `Conflict`. | Keep the existing gate (4.1.x blocked on Spike 0.1.2 and OD-3). Add: ship Epic 4.2 UI only for the constraint kinds proven by property tests over randomised sketches; unproven kinds stay hidden. Define the fallback in the plan: if the spike fails, v1 of the feature is geometric-only (coincident, H/V, equal, distance) with `NoConvergence` surfaced, not a silent best effort. | P2 |
| 6 | Whole-file autosave at scale causes OOM, jank and git churn. INFERRED: `SheetSaver` writes the entire canonical JSON (up to 16 MB, 5,000 elements) every 500 ms debounce; `SheetCodecV2` builds a `JsonElement` tree and a byte array, the reconciler re-hashes the bundle, git sync then sees a changed file for each edit, and image-heavy sheets amplify it. Observability lists `native_decode_ms` but no encode or save-size metric. On Android an `OutOfMemoryError` is guarded only for the save path. | Typing in a large diagram stutters on Pixel_Fold; GC spikes in `sketch.persist` logs; git diffs of one-element edits show the whole file. | Add `sketch.encode_ms_5000` and `sketch.save_bytes_5000` to `sketch-engine-budgets.json` and a CI gate. Emit one element per line (stable key order) so git diffs and merges are element-local. Encode off the main thread with `Throwable` guards and a back-off to a longer debounce when the last encode exceeded budget. Keep image bytes out of the sheet (already planned by `fileId`). | P2 |
| 7 | Cross-target rendering and text parity fails, so "identical on JVM, Android, wasmJs" is false. INFERRED: Compose `TextMeasurer` differs per Skia target; wasm fonts load asynchronously; CJK fallback differs; Sketchy fills (hachure) depend on seeded PRNG and float ops; Robolectric may not render text and paths faithfully. The plan pre-agrees fallbacks (persisted size hint, per-element CJK metrics). | Wrapped text reflows or boxes clip text after opening on another device; Sketchy output drifts between targets. | Keep Spike 0.1.3 as a hard gate and record tolerances in ADR-004. Make the persisted text width/height authoritative for layout on every target (re-measure only on edit), and make wrap points a write-time decision stored in the element, so another device never re-wraps. Add a cross-target golden that opens the same sheet bytes on JVM and wasm and compares the draw list. | P2 |
| 8 | Delivery stalls behind a long serial refactor-first spine, ending with merged plumbing and no usable editor. INFERRED: 1.1.1 to 1.1.3 to 1.4.5 to 1.4.2 touch the reconciler, both repositories, fusion and preview before any user-visible value; seven open owner decisions (OD-1..7) block specific stories; the wiring-allowlist entries expire after 90 days and `WiringCompletenessTest` fails for unwired seams. | Weeks of green internal PRs with the flag still unusable; allowlist expiry failures; review fatigue on large PRs. | Add an early vertical slice milestone: a NEW v2 sheet (not conversion) with rect, text, one bound arrow, save, reopen and Clean render behind the flag, built right after 1.1.3 and 1.4.4, so the persistence path is exercised by real use early. Batch all OD answers into one owner session before Wave 1. Plan the allowlist deletions per PR. | P2 |
| 9 | A hostile or accidentally huge imported `.excalidraw` or git-synced v2 sheet crashes or hangs a target. VERIFIED partial: plan has `SceneLimits` and a fuzz test, but only for `SheetCodecV2`; the importer, clipboard paste and `extras` passthrough (arbitrary `JsonObject` preserved verbatim) are separate paths. | A pasted or imported file freezes the wasm tab or crashes Android on decode. | Route every untrusted entry through one `SceneLimits`-checked parser, include `extras` size in the byte budget, and add the fuzz suite to importer and clipboard stories, not only `SheetCodecV2`. Decode on a background dispatcher with a time and memory cap. | P3 |
| 10 | Licence contamination or fixture gaps invalidate ports. INFERRED: rough.js and perfect-freehand goldens need Node and network the executing agent may not have, so golden ACs slip; clean-room solver depends on nobody having read planegcs. | Golden assertions never added; a reviewer questions solver provenance. | Keep OD-3 answered before Task 0.1.2a, record who wrote what in ADR-003, and track the deferred golden ACs as explicit open items in 6.2.1 so the gap is visible, not silently skipped. | P3 |

## P1 Items (address before implementation)
Status (Phase 4 repair): all three P1 items are RESOLVED IN THE PLAN (documents only; no code written, nothing re-reviewed or re-run).
- [x] #1 RESOLVED in plan: `schema_version` reset by `INSERT OR REPLACE` plus generic unreferenced-sheet delete. `insertSketchSheet`, its `RestrictedDatabaseQueries` stub, `put(SketchSheet)` and both `replaceProjectContents` carry `schema_version` (Story 1.4.1, Task 1.4.1b); every sheet-row write path is covered by `SketchSheetWritePathsPreserveSchemaTest` (Task 1.4.1d); router and legacy `SketchStore` read the FILE schema over the mirror (Stories 1.4.1, 1.4.3); `writeLocked`'s unreferenced delete is limited to files that classify as schema 1, schema-2 files are removed only by converter cleanup or restore, `conflicts/` is excluded like `backup/` (Task 0.1.1b, Story 0.1.1 AC, Story 1.4.2 text).
- [x] #2 RESOLVED in plan: parked/replayed bundles. The `opaque`/`expectedSha` check is enforced inside `flushPending` (parked entries are intents, dropped as `StaleOpaque` on mismatch); the park-convert-flush case is a Story 1.1.3 acceptance criterion and part of the `SidecarWriterRaceTest` matrix (Story 1.1.3, Tasks 1.1.3b and 1.1.3e after the iteration 3 split).
- [x] #3 RESOLVED in plan: external overwrite by an open editor. `SheetSaver` carries `baseSha` and does compare-and-swap under the slug lock, writes `conflicts/<uuid>.v2.conflict-<hash8>.json` (outside `sheets/*.json`), raises a `SketchDiagnostics` entry and logs `sketch.save.conflict`; the pull-while-editing AC and `SheetSaverConflictTest` are in Story 1.4.4 (Task 1.4.4c).
