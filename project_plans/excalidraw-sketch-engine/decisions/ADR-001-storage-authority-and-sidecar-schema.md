# ADR-001: Native scene JSON in the sidecar is authoritative; `.excalidraw` is import/export only

**Status**: Proposed (stays Proposed: depends on owner decision OD-1, the old-build fail-closed blast radius; flips to Accepted when OD-1 is answered and Stories 0.1.1, 1.1.1 and 1.1.3 gates are green)
**Date**: 2026-11-14

## Context
Open Question 1: store `.excalidraw` or native scene JSON. Constraints: constraints, named layers with opacity, Double parametric handles and `sheet scale` have no Excalidraw field; ADR-005 of home-project-sketching makes the sidecar bundle `<graph>/assets/stelekit-sketch/<slug>/{project-model.json, sheets/<uuid>.json}` authoritative and the DB a cache.

## Verified facts about the shipped reader (this session)
- `SidecarClassifier.SUPPORTED_SCHEMA = 1L`; `classifyJson` returns `Corrupt(NewerSchema)` when a file's `schema` is greater than 1 (`kmp/.../projectbridge/SidecarFileState.kt:23-48`). VERIFIED by reading the code. It is one constant shared by `project-model.json` and every sheet file.
- `ProjectSidecarStore.readLocked` classifies the model and every `sheets/*.json`; the FIRST non-Valid file returns `SidecarRead.Corrupt(reason, path)` for the WHOLE project (`ProjectSidecarStore.kt:78-96`). A single `schema:2` sheet therefore makes the whole project read-only/unavailable on an old build, not just that sheet. It fails closed (never re-saved as v1), which is the safe direction, but the blast radius is the project, not the sheet.
- `sheetJson` writes only `primitives[]` (`ProjectModelJson.kt:137-153`), so an old writer would drop v2 data if it ever got past the classifier. The classifier is the only guard.
- `readLocked` lists every `*.json` under `sheets/`, so a backup placed there is read as a sheet file.

## Decision
1. Native scene JSON is the stored truth. `.excalidraw`/`.excalidrawlib` are import/export only; unknown Excalidraw fields are preserved in a per-element `extras` JSON object for round trip.
2. A v2 sheet is a `sheets/<uuid>.v2.json` (path rule single-sourced in `SheetPaths`, Story 1.1.3; the v1 file `sheets/<uuid>.json` stays referenced and hash-valid until the model flip, see 4a) with `schema: 2` and a `scene` object (elements, constraints, layers, groups, frames, view settings). v1 sheets stay `schema: 1`. `project-model.json` stays `schema: 1` until it needs a field of its own.
3. Replace the single `SUPPORTED_SCHEMA` constant with a per-file-kind maximum (`model = 1`, `sheet = 2`) and a `SheetCodec` dispatch on `schema` (Story 1.1.1). Old builds keep failing closed on `schema:2` (Story 0.1.1 proves it with a golden fixture before any v2 write exists).
4. The sheet's v1 backup lives at `<slug>/backup/<uuid>.v1.json`, NOT under `sheets/`, so it never enters the old reader's file list. Task 0.1.1b changes `FileProjectSidecarStore` so `backup/` is created, excluded from `Present(files)` and `bundleHash`, and never deleted by `writeLocked`.
4a. Crash-safe conversion: the v2 sheet is written to a DISTINCT path `sheets/<uuid>.v2.json`; the v1 file stays the referenced, hash-valid sheet until ONE atomic model write flips `sheetRef.file` / `schema` / `fileSha256`; then the unreferenced v1 file is removed. This is required because the reader returns `Corrupt(Truncated)` when `sha256(sheet) != model.fileSha256` and never repairs a corrupt bundle. Between writing the v2 file and the model flip an OLD build sees a `schema:2` file and fails closed (accepted, same blast radius as OD-1). Story 1.4.2 tests crash injection at every step.
4b. The bundle pipeline (`ProjectBundle`, `SidecarCodec`, `SidecarReconciler`, both `replaceProjectContents`) carries v2 sheets as opaque `SheetPayload.V2Opaque(bytes, sha256)` and never re-encodes them (Story 1.1.3). The DB holds only `sketch_sheets.schema_version` as a mirror; the file wins on disagreement. There are no per-element DB cache tables.
4d. Reader and writer rules (Stories 0.1.1b, 1.1.3, 1.4.2): `readLocked` parses the model first and reads ONLY the sheet files its `sheetRef`s reference; unreferenced `sheets/*.json` are never opened by the new reader (the old reader still scans all of them and fails closed). The path rule is single-sourced in `SheetPaths` (schema 1 -> `sheets/<uuid>.json`, schema 2 -> `sheets/<uuid>.v2.json`; a `sheetRef.file` that differs from the rule is `Corrupt`). The reconciler never writes `V2Opaque` bytes (the store takes `opaque`/`expectedSha` and returns `StaleOpaque` on mismatch), and every sidecar writer (reconciler, `SheetSaver`, `SheetConverter`, restore) serialises on one per-slug `SidecarSlugLock` spanning read-plan-write. The `opaque`/`expectedSha` check also runs at `flushPending` time (a parked write is re-validated, or dropped as `StaleOpaque`, never replayed blindly), the unreferenced-sheet delete sweep removes only files that classify as schema 1 (a schema-2 file is deleted only by the converter's cleanup or restore), the router and legacy `SketchStore` trust the FILE's schema over the DB mirror, and `SheetSaver` compares a `baseSha` under the slug lock and writes a `conflicts/<uuid>.v2.conflict-<hash8>.json` copy instead of overwriting a file that changed underneath it (pre-mortem P1 #1-#3). Conversion writes use `writeNow`, which returns `Deferred` without parking a snapshot in `pending`. The DB sheet row (`layers`, `schema_version`) is updated by `SheetSaver` in the same locked operation as the file and model so `encode(local)` equals the on-disk model.
4c. Zones, named dimensions, sum/equal constraints, layer-name mirror and scale stay in `project-model.json` (Story 1.1.4).
5. Doubles are serialised by a commonMain shortest-round-trip routine (Story 1.1.2), keys sorted, so hashes and git diffs are identical on JVM, Android, wasmJs and iOS. **One explicit exception (iteration 14, D-105): the v2 sheet header.** The emitter writes `schema` and `sheetUuid` FIRST, in that order, and sorts only the remaining keys, because a fully sorted emission puts `schema` after `constraints`, `elements`, `extras` and `layers`, beyond the 256-byte prefix the `NewSketchProject` header probe reads, so the probe could never say V2. A v2 file therefore begins `{"schema":2,"sheetUuid":"` (`"schema"` at byte offset 1; a v1 file written by `SidecarCodec.sheetJson` is pretty-printed and begins `{\n  "schema": 1,`, offset 4); the exception is one list in `CanonicalJson` (`headerFirstKeys`), part of the canonical bytes (hashes still agree across platforms), and a golden on real emitted bytes asserts the offset (Tasks 1.1.2a and 1.1.5a).
6. Images are asset files referenced by content hash (`fileId`), never inline base64.

## Amendment A4-NO-GO (triad repair iteration 9; applies only if the owner records A4 NO-GO)
If a device that must keep opening these projects cannot be updated, conversion stays unreachable (`ConversionOffered = false`, ADR-005 item 1a) and v2 sheets are created only in a `NewSketchProject` (ADR-005 item 1a, canonical sentence below) under mode `NewProjectsOnly`; no project an older build can open today becomes unreadable. The owner then picks one: (a) **v1-compatible projection**: write a lossy v1 view `sheets/<uuid>.json` beside each v2 file so an older build keeps opening and displaying the project (the view is lossy, and an older build's edits to it are discarded by the next v2 save, which the notice must say); this reverses the fail-closed decision above for those projects and so needs its own owner consent. ESTIMATE (INFERRED, not in the plan's counts): 1 story of 3 M and 2 S tasks (projection writer and two-file consistency in `ProjectSidecarStore`; reconciler and hash rules for the second file; `V2ToV1.project` reuse and `Dropped` reporting; the notice and settings copy; golden and crash-injection tests) = 500k raw tokens = 0.74M CU (1.29M CU with the x1.75 verification multiplier); shipping it sets `ConversionOffered = true`. (b) **Live with new-project-only v2**, a complete product state; no further work.

**NewSketchProject (canonical sentence):** A `NewSketchProject` is a project created by the very create action that adds the sketch, or an existing project that holds at least one sheet, every sheet of which classifies as v2 from its FILE (the database schema mirror is only a hint) and whose sheet list is complete (the sheet query reports no further page); an existing project with no sheets, with any v1 or unclassifiable sheet, or with more sheets than one query page does not qualify, because an older build opens it today.

## Alternatives rejected
- `.excalidraw` as the stored format: loses constraints/layers/handles or forces them into `customData`.
- Keep `schema:1` sheet with a v1 projection plus a side `scenes/<uuid>.json`: old builds would keep editing and re-saving the projection, silently diverging from the scene (the model names each sheet's `fileSha256`, so the hash would still match). Silent data divergence is worse than fail-closed. The A4-NO-GO option (a) above is the same shape with the divergence made explicit and consented: an older build's edits to the lossy v1 view are DISCARDED by the next v2 save (the notice says so), so it trades fail-closed for a known loss of old-build edits and needs the owner's own consent; it is not adopted by default.
- Project-level schema bump: needless; per-sheet schema keeps mixed bundles and per-sheet git merges.

## Consequences
- A device on an old build cannot open ANY sheet of a project containing a v2 sheet until upgraded. Mitigation: flag default off, release notes say upgrade all devices before the first v2 write; the first v2 write shows a one-time confirmation. Owner decision OD-1 in plan.md.
- Mixed-version reconcile: the lagging device stays read-only, never overwrites.
- Per-sheet git diff and merge granularity: a v1 sheet file is pretty-printed (one primitive field per line), so a git diff or merge conflict inside one v1 sheet is line-granular; a v2 sheet is the compact canonical emission (no indentation, `{"schema":2,"sheetUuid":"...` on one line), so any edit to a sheet rewrites that line and two concurrent edits to the SAME v2 sheet conflict as a whole, while edits to DIFFERENT sheets (one file per sheet) merge cleanly. The unit of merge for v2 is therefore the sheet, not the element, which matches the per-sheet three-way hashes of `SidecarReconciler` (Task 1.4.2b); the conflict copy (Task 1.4.4c) is the resolution path.
- Web (D-104, owner decision 2026-11-15): sheets are files in OPFS there, written by the atomic replace of Story 1.4.7 in a browser whose `V2StorageStatus` is `Ready` (an Available OPFS verdict and a finished preload); a save is acknowledged only when OPFS has committed it (`awaitDurable`, D-119, a browser has no `fsync`), sheet writes are single-writer per graph across tabs (D-123), and a browser without OPFS atomic replace, and iOS, cannot read or write them (`V2StorageAvailable` false).
