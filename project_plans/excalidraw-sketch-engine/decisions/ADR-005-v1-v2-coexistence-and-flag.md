# ADR-005: v1 and v2 editors coexist behind `sketch.engine.v2`; flag controls creation and editor choice, never readability

**Status**: Proposed (stays Proposed: the first-v2-write confirmation and fail-closed behaviour depend on owner decision OD-1)
**Date**: 2026-11-14

## Decision
1. Flag `sketch.engine.v2`: per-graph `Settings` value, default `Off`, stored as a string beside the per-graph accessors of `ProjectBridgeSettings` (the global `homeSketch` master flag, `HomeSketchFlag`, stays a global Boolean that gates the whole sketch feature and is not edited; V2Mode is read per graph only while it is on, and `V2ModeFlag`, which is keyed by graph id and rebinds when `GraphManager.readyGraph` changes instead of caching one global value as `HomeSketchFlag` does, feeds `ScreenRouter`/`AppState`). It controls which editor opens and whether NEW sheets are created as v2. Readers always understand `schema:2`.
1a. **Amendment (triad repair iteration 9, product gap P1): the flag is a three-value mode, `V2Mode` = `Off` / `NewProjectsOnly` / `On`** (a missing, blank or unknown stored value reads as `Off`; the key never shipped, so nothing is migrated). `Off`: no v2 sheet is created, v2 sheets open read-only. `NewProjectsOnly`: a NEW sketch is v2 only in a `NewSketchProject` (canonical sentence below), v1 sheets are never converted and show no Upgrade chip, v2 sheets are editable. `On`: also the Upgrade offer and conversion of v1 sheets. Two build-time constants gate it: `ConversionReady` (test-derived: 1.1.3, 1.1.4, 1.1.5, 1.4.5 registered) gates BOTH v2 modes because a new v2 sheet must reach fusion, digest and previews like a converted one; `ConversionOffered` (a release decision, default true, false in a release shipped after an A4 NO-GO) gates only conversion, `On` and the Upgrade chip; a third cap is the PLATFORM (iteration 14, D-104 owner decision, D-116): `V2StorageAvailable` is `store != null && store.isAvailable()`, true on desktop, Android and a browser whose `V2StorageStatus` is `Ready` (an Available OPFS verdict and a finished preload, Story 1.4.7), false on iOS, in a browser whose status is `Unavailable`, while it is `Checking` (the router returns `Pending`, UX-141) and when the store is null (a demo graph or no open graph), and every mode then behaves as `Off`. The effective mode is the stored mode capped by the build and the platform; a capped option is disabled, never hidden, with one reason by the precedence `Platform` before `BuildCapped` ("Not available in this build yet"). Why not a second boolean: two interacting booleans (`enabled`, `onlyNewProjects`) have an undefined fourth combination; one ordered mode cannot. Consequence for A4 NO-GO: the ceiling is `NewProjectsOnly`, so "v2 sheets exist only in NEW projects" is implementable (plan Tasks 1.4.3a, 1.4.3d, 1.4.3e, 1.4.6h; requirements "Flag modes"). Alternative recorded: ship NO-GO builds with the flag switch hidden and v2 sheets created silently in new projects (rejected: an old build then fails on a project the owner did not knowingly create).
   **NewSketchProject (canonical sentence):** A `NewSketchProject` is a project created by the very create action that adds the sketch, or an existing project that holds at least one sheet, every sheet of which classifies as v2 from its FILE (the database schema mirror is only a hint) and whose sheet list is complete (the sheet query reports no further page); an existing project with no sheets, with any v1 or unclassifiable sheet, or with more sheets than one query page does not qualify, because an older build opens it today.
2. Editor is chosen once at sheet-open time by `SketchEditorRouter`; a mid-session flag flip does not swap the open editor.
3. Flag off with a v2 sheet: it opens READ-ONLY through the v2 renderer, with the reason shown ("Turn on the new editor to edit.") and a [Use new] action that opens the flag-enable confirmation but never swaps the open editor (it applies after reopening). It is never invisible and never back-converted in place.
4. A v1 sheet converts ONLY on an explicit per-sheet Upgrade action with the flag on (amended in triad-review repair iteration 2: merely opening a v1 sheet never converts it; it opens in the legacy editor with an `UpgradeOffer` chip, the owner can decline per sheet (`Declined`, set ONLY by "Keep this sketch classic" in the chip menu; the first-write dialog has one checkbox, "I understand", gating Convert and open, and its [Open classic] only opens the classic editor with nothing written or recorded; triad repair iteration 4, U6; a NEW sketch in an unacknowledged project shows a new-sheet variant of the dialog with no backup sentence, an explicit [Create classic sketch] button and Esc and back that create nothing, iteration 5, UX-64), and after that sketch project's acknowledgement (per project, per device, not synced: iteration 3, D-16) later sketches in the same project upgrade from the chip without a modal, while the chip itself carries the one consequence line "Upgrade blocks other devices." (or, where it does not fit the width and font scale, a consent sheet) until then (the full whole-project sentence is in its Details sheet and the first-write dialog); see plan Story 1.4.6, Task 1.4.6g, ux.md 14.2). On Upgrade: write `backup/<uuid>.v1.json`, write the new sheet to `sheets/<uuid>.v2.json` (never over the v1 file), verify its hash, then switch the model's `sheetRef` in ONE atomic model write, then remove the old v1 file (ADR-001 4a). v1 DB rows are never deleted. Idempotent (`V1ToV2.lift` keeps ids). A failed conversion offers "Open in legacy editor".
4a. Router states include "legacy editable while conversion declined/failed" (and, in `NewProjectsOnly` or with `ConversionOffered = false`, "legacy editable, no offer") (`ConversionState.Declined`/`Failed`), and a v1 sheet is not converted (and a NEW sheet is created as v1) while its own `sheetRef.zones` is non-empty or the project has any dimension (dimensions are project-scoped), until the v2 editor has technical-data surfaces (Stories 1.1.4, 4.2.5); an existing classic project holding technical data is therefore unreachable for the reachable-demand counts of the pre-check, A6 and the A1 gate until Story 4.2.5 ships (requirements.md "Reachable demand", D-83). No mode other than `Off` can be enabled until the bundle dispatch (1.1.3), technical-data home (1.1.4), `SheetCodecV2` (1.1.5) and fusion/preview projection wiring (1.4.5) are done; `ConversionReady` is checked by a test and the converter refuses when it is false. The legacy `SketchStore` also refuses `schema_version = 2` sheets, independent of the router.
5. One `SheetLease` (in `RT/session`, UI-free) per sheet in the store: the v1 and v2 view models cannot both hold a sheet open.
6. Dimension/fusion reads only the IN-MEMORY `V2ToV1.project` output (ADR-002, Story 1.4.5); it is never written to `sketch_primitives`. `Dropped` elements are reported.
7. The legacy editor is deleted only after the parity suite (Story 6.2.4, Story 6.2.5) is green; that deletion is a follow-up, not part of this plan.
8. Embeds and previews dispatch on `schema` in ONE function (`SketchRenderDispatcher`).

## Alternatives rejected
Flag gating readability (turning it off would hide data); in-place back-conversion to v1 (lossy); two editors sharing a view model (the 348-line `SketchViewModel` is isolated, not extended).

## Consequences
Old builds fail closed on v2 sheets (ADR-001). **Amendment 2026-11-17 (OD-1, owner choice: ship together):** the reader and the conversion/creation paths ship in the same release, with no earlier reader-only release; both `V2Build` constants stay `true`. A device still running an older SteleKit build cannot open ANY sheet of a project that contains an upgraded sketch (it refuses the whole project and changes nothing); the first-write consent dialog is the only warning that device gets before the first v2 write. Remaining mitigations: backups and Restore original, the fail-closed old reader, per-device per-project acknowledgement, flag default `Off`. Status stays Proposed. Rollback = set the mode to `Off`; v2 sheets stay readable. A4 outcome index (written by Task 1.4.3e): the owner's A4 result and the value of `ConversionOffered` are recorded here, next to the ADR-001 choice if NO-GO.
