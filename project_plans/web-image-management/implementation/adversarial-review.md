# Adversarial Review: web-image-management

**Date**: 2026-11-01
**Reviewer note**: performed inline by the coordinator as a single adversarial re-read of `plan.md` against the code (not by an independent agent; independence is therefore weaker than the SDD default and a fresh-context reviewer pass is recommended before Phase 5). Findings below were checked against code where marked VERIFIED.
**Verdict**: CONCERNS (the one BLOCKER found during review was patched into `plan.md` in the same pass; it is listed as resolved so the history is visible)

## Blockers
- [x] **Fail-open LFS guard and whole-push failure when images are dirty without bytes** — VERIFIED: `lfsVerdict` does `getContentBytes(...) ?: continue` (`WasmGitWriteService.kt:172-173`) and the commit path returns `CommitFailed("No cached content for dirty path")` (`:509-513`). Dirty-tracking images before the store-backed blob path exists would block every push and, if "fixed" by loosening the error, would let raw files at LFS-tracked paths skip the guard. RESOLVED in plan: ordering note + `WebBinaryDirtyTracking.enabled` flag + task 8.1.1c fail-closed rewrite + P18.

## Concerns
- [ ] **Sync vs suspend API migration is wider than the plan's file lists suggest** — `readFileBytes`/`getFileSize` sync callers include `AssetIndexService`, `ImageImportService`, `AssetCopier`, annotation load, `ImageDerivativeService`; there may be more (a full `grep` of call sites should be Task 1.1.1b's first step). Recommendation: add an acceptance criterion to 1.1.1b "list of all call sites with disposition" and a structural test that forbids new sync `readFileBytes` on images in commonMain after migration.
- [ ] **Coil/Compose behavior on blob URLs is the single biggest UNVERIFIED display assumption** — if S1 fails and the Coil `Fetcher` hook cannot be injected cleanly into `buildSteleKitImageLoader` (a commonMain function, `SteleKitAssetFetcher.kt:67-79`), D3 option B (DOM overlay) is large and ugly. Recommendation: run S1 first, before any other web epic; record the result; keep E4.3 sized M but flagged highest-variance.
- [ ] **Safari may make the whole OPFS write path need a worker** — then E1.3, E2 and E10.3 change shape (all writes async through a worker message protocol, dirty tracking races). Recommendation: S3 precedes E1.3; design `WebBinaryStore.writeStream` as an interface with two implementations from the start (main-thread and worker), tested against the same contract suite (pattern: `TargetWriterContractSuite`).
- [ ] **E9 is the largest epic and depends on external hosts** — Converter mode in particular needs a workflow file in the user's repo and transient raw blobs on a staging ref (a deliberate exception to the safety floor). Recommendation: keep it strictly behind an opt-in flag with a confirmation dialog stating the cost; require B5 before shipping the Converter; make Direct/ReadOnly shippable without it.
- [ ] **ML epic scope vs the brief** — the brief lists "ML/depth features that cannot run in a browser" as a thing to cover. This plan makes them run (tesseract.js, ORT-web) because the owner's standing rule is full scope; but depth/labeling models are tens of MB, need same-origin vendoring and possibly cross-origin isolation for threads (INFERRED). Recommendation: D6 stays an explicit owner decision; E7 is last and independent so declining it costs nothing elsewhere; the "capability not available" disabled-state work (E6.2.1b) ships regardless and is what delivers parity for the unavailable ones.
- [ ] **Memory budget is asserted by tests but not by the platform** — a 64 MiB Kotlin-heap cap does not bound JS-side memory (Blob/ArrayBuffer/decoded bitmaps); only S4 and the 2,000-image test inform this. Recommendation: E1.4 also records JS heap (`performance.memory` on Chromium) in the test output and the plan adds a note in docs; no hard JS cap is claimed.
- [ ] **Remote image fetch changes network behavior for all web users** — lazy fetch on view (D12) issues authenticated requests to the git host for every missing local asset; a page with 100 absent images triggers 100 requests (rate limits, battery). Recommendation: concurrency cap 3, per-host backoff, negative cache for 404 (session-scoped), setting to disable; test for each.
- [ ] **Host-folder reconcile rewrite (1.3.1c) touches 1,953 lines of heavily tested sync code** (`HostDirectorySync.kt`) — high regression risk to note sync. Recommendation: confine the change to the non-text branch (`:1276-1292`) behind the existing structure, run the full `HostDirectorySync*Test` set, add a differential test (old path vs new path produce identical OPFS contents for a fixture).
- [ ] **Wiring gate** — `WiringRoots` omits wasm `Main.kt` (VERIFIED); plan task 5.2.1c covers it, but `AssetPipelinePlugin` implementations for web ML must be avoided or wired too. Recommendation already in architecture section 3; make it an acceptance criterion of 7.2.1a-c.
- [ ] **Test-hygiene for async browser events** — synthetic `ClipboardEvent`/drag tests need to await Promises, not `delay`; recommend a shared `awaitPromise` helper in `wasmJsTest` and a lint-style check that the new wasm tests contain no `delay(` with real-time arguments (the hygiene audit covers `jvmTest`; verify whether it scans `wasmJsTest`).
