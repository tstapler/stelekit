## Happy Path Scenario
Given a Logseq-compatible page whose pipe table (`| Name | Qty |` header, three body rows, a `Total | =SUM(B2:B4)` row) renders today as a read-only wrapped table with both flags off, when the owner turns both flags on, taps the `Qty` cell of row 2, types `4`, presses Enter, opens the maximized sheet with Ctrl+Shift+Enter, pastes a 3x2 Sheets TSV, sorts by `Name`, closes the sheet and presses Ctrl+Z, then the file shows only the edited/pasted/sorted rows changed (untouched rows byte-identical, `=SUM(B2:B4)` still a literal cell and displaying the right total), each action was exactly one undo step that restored the exact prior file text, and with the flags off the same file renders and taps exactly as before. *(Anchor for every test below.)*

## Conventions

- **Source-set abbreviations** (all under `kmp/src/<set>/kotlin/dev/stapler/stelekit/`): `CTEST` = `commonTest` (default home for pure logic, per CLAUDE.md; runs on JVM/Android/iOS/wasmJs), `BTEST` = `businessTest` (source-scanning gates and wiring), `ATEST` = `androidUnitTest` (Robolectric/Roborazzi, headless; the home for every Compose-behaviour test), `JTEST` = `jvmTest` (only for a real SQLDelight driver or real pixels; any file importing `androidx.compose.ui.test` needs `// jvmTest-reason: <pixels|desktop-only>`), `WTEST` = `wasmJsTest` (real Chrome via `:kmp:wasmJsBrowserTest`).
- **No Compose test in `jvmTest` unless pixels are the point.** All Compose UI behaviour below is `ATEST`. `TableSheetRealFeedTest` is `JTEST` because it needs the real SQLDelight JDBC driver; it must not import `androidx.compose.ui.test` (the host's decision logic is driven through the pure host adapter, not a composition), so it needs no `jvmTest-reason` tag and `TestPlacementAuditTest` stays green.
- **No wall-clock sleeps, no `runBlocking`/`Dispatchers.IO` in `CTEST`** (wasm compile rule, `TestHygieneAuditTest`). Gesture timing uses `mainClock.autoAdvance = false` + `advanceTimeBy`.
- Tests marked `(new)` in the File column are not named in plan.md and are added by this plan; the owning plan task is in the "New test classes and owning tasks" table below. Registration for every class: `scripts/kmp-module-tests-sync.py` (CTEST), `AllBusinessTests.kt` (BTEST), `AllAndroidUnitTests.kt` + `kmp/src/androidUnitTest/kotlin/BUILD.bazel` (ATEST), `AllJvmTests.kt` (JTEST); enforced by `scripts/check-bazel-test-listing.sh`.
- Type column values: **Unit** (happy or error, see Scenario), **Integration** (real manager / real repository / multiple collaborators), **Property** (kotest-property `Arb`/`checkAll` inside `runTest`), **Failing-first**, **Mutation**, **Real-feed**, **Guard** (source-scanning/wiring gate).
- Domain Glossary names (`TableDoc`, `RowLine`, `CellText`, `CellAddress`, `TableEdit`, `TableEditOutcome`, `TableCalc`, `RefRewriter`, `GridSelection`, `GridNavigator`, `CellDraft`, `TableSyncPolicy`, `OwnCommitLedger`, `TableCommitter`, `TableClipboard`) are used verbatim.

## Test Stack
- **Unit / Property**: `kotlin.test` `@Test` + `kotest-assertions-core` + `kotest-property` (`Arb`, `checkAll` in `runTest` from `kotlinx-coroutines-test`); no Kotest Spec runner; `commonTest` so one run covers JVM, Android, iOS, wasmJs.
- **Integration**: real `BlockStateManager` over in-memory repositories (the `BlockStateManagerTest` harness) and, for the real feed, the real SQLDelight JDBC driver on in-memory SQLite (`JTEST`); recording fakes for `TableClipboard`, `LocalUriHandler`, `LocalOpenTableSheetAction`; a gated fake repository for suspended-write cases.
- **Compose / UX**: Robolectric + `compose.ui.test` in `androidUnitTest` (`@RunWith(RobolectricTestRunner::class)`, `@GraphicsMode(NATIVE)`, `@Config(sdk=[29], qualifiers="w360dp-h780dp-xxhdpi")` for renders); Roborazzi PNGs opened with `Read`; `mainClock.autoAdvance = false` for gestures.
- **Platform**: `:kmp:wasmJsBrowserTest` (real Chrome; `./scripts/fix-wasm-karma-tooling.sh` first if Karma fails); `Pixel_Fold` AVD for device steps; Chrome tools for the web pass.
- **Gates**: `BTEST` source-scanning guards (`TableEngineImportDirectionTest`, `ModuleManifestGuardTest`, `WiringCompletenessTest`, `TestPlacementAuditTest`, `TestHygieneAuditTest`, `MigrationRunnerSchemaSyncTest`).
