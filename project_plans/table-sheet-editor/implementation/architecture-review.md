## Blockers
- [ ] **Story 5.1 (Undo from inside the dialog), Story 4.3 / ADR-004 / Tech Debt Disposition row `BlockUndoManager`** — The plan says `BlockStateManager.undo()/redo()` and `BlockUndoManager` need nothing ("Extend as-is (untouched)") and that Ctrl+Z "shows the previous value". The undo and redo closures recorded by `applyBlockContentUpdate` (`BlockStateManager.kt:1080-1100`) both end with `requestEditBlock(blockUuid, oldContent.length)` / `requestEditBlock(blockUuid, newContent.length)`. `requestEditBlock` sets `_editingBlockUuid`, and `BlockItem` renders the raw `BlockEditor` for the editing block (`BlockItem.kt:360`). So every table undo or redo flips the block into raw-markdown edit mode, unmounts the inline `TableBlock` (losing its hoisted `CellDraft`, selection and `TableCalc`) and puts a raw editor behind the open Dialog. This breaks the acceptance criteria of 5.1 (undo from the sheet), 4.3 (cell commit undo), 5.4 (paste undo "restores the original string exactly" is true for the string but not for the UI state), 5.5, 5.7. It also adds a second behavioural change to a 32-commit hotspot (`BlockStateManager`) with no row in the Tech Debt Disposition table. — **Remediation**: add a task before 4.3a (new Task 4.0a, S): give `applyBlockContentUpdate` / `updateBlockContent` an additive parameter (default preserves today's behaviour), e.g. `restoreEditFocus: Boolean = true`, threaded into the recorded undo/redo closures; table commits pass `false`. Add the Tech Debt Disposition row "`BlockStateManager.applyBlockContentUpdate` — hotspot, **Isolate via seam** (one default-valued parameter, no table logic)" and a test in `BlockStateManager`'s existing suite proving a table commit's undo leaves `editingBlockUuid` null. Update the ADR-004 text and the disposition row for `BlockUndoManager` to say it stays untouched but `BlockStateManager` gets this parameter.

## Concerns
- [ ] **Story 5.4c / Story 5.7 announcement "Undid: Sort rows"** — `BlockUndoManager.UndoEntry` holds only two closures, no label (VERIFIED, `BlockUndoManager.kt:18-21`). The undo announcement cannot be produced as specified, and the disposition says the manager is untouched. — Recommend one of: add an optional `label: String?` to `record` (additive, still no grouping API) and expose the last-undone label; or drop "Undid: <label>" from the criteria and announce "Undone" generically. Decide in ADR-004.
- [ ] **Task 4.3c / Task 5.1b / Unresolved Question 6 (version semantics)** — `BlockItem` supplies `onContentChange: (String, Long)` with `++localVersion` and resyncs when `block.version > localVersion` (`BlockItem.kt:105,165`); `applyContentChange` drops writes whose version is lower than the stored one (`BlockStateManager.kt:~1135`). The plan's seam is `onContentChange: (String) -> Unit` and the sheet host has no `localVersion`. Two committers (inline `TableBlock` and the sheet) can mint colliding or regressing versions. — Resolve now, not in 5.1b: define the table commit as `commit(blockUuid, content)` that reads `block.version + 1` inside one place (the host/`TableBlock` seam callback, as `BlockStateManager.kt:935` does) and make both inline and sheet use it. Add a test with two interleaved commits.
- [ ] **Task 3.2b / ADR-004 `TableSyncPolicy`** — Echo detection compares against "the last string this session serialized". `updateBlockContent` launches each commit in its own `scope.launch` on a multi-threaded dispatcher (`BlockStateManager.kt:1064`, `:1113-1118` comment documents out-of-order arrival). With two quick commits S1 then S2, the observer can emit S1 after the policy has recorded S2; S1 != S2 is then misclassified as an external change and rebuilds from stale content or raises a false conflict. — Track a bounded set (or a monotonic version) of strings/versions this session wrote, and treat any member as `Echo`; add a test with out-of-order echoes.
- [ ] **Epic 1/2 package structure (Tasks 1.2a/2.3b/2.2c)** — Package cycle: `table.TableEditor` calls `table.formula.RefRewriter` (2.3b) while `table.formula.TableCalc(doc: TableDoc)` and the evaluator import `table`. The plan avoided the cycle for sort values (injected `valueOf`) but not for reference rewriting. `TableEngineImportDirectionTest` does not check intra-`table` direction, so nothing would stop it. — Pick one direction: `table.formula` depends on `table`; define a small `ReferenceRewriter` port (or a `FormulaCellTransform` function type) in `table` that `TableEditor` receives, with `RefRewriter` supplied by `formula`/the caller. Add the direction rule (`table` must not import `table.formula`) to Task 1.4b.
- [ ] **Story 2.3 / ADR-003 vs Story 1.1c property (c)** — A structural edit "rewrites all formula cells" through `FormulaPrinter` "canonical text". Formulas whose references are unaffected would be re-printed (spacing, function-name case), changing untouched cells and contradicting "untouched cells are unchanged by any single edit" and the small-diff goal. — Re-print only formulas whose AST actually changed under the rewrite; leave others byte-verbatim. Add this as an acceptance criterion in 2.3 and a property in 2.4b.
- [ ] **Story 1.1 acceptance (SetCell address)** — Glossary: `CellAddress` is 1-based with row 1 = header. The example doc has one header and one body row, so the body row is `CellAddress(2,1)`, yet the criterion applies `SetCell(CellAddress(3,1), "9")` and expects source "line 3" to change (conflating source-line numbers with row numbers; line 2 is the delimiter). Written as is, the test targets a nonexistent row. Also `InsertRows(after=1)` (1.2) vs `InsertRows(before=3)` (2.3) use different anchors. — Fix the example to `CellAddress(2,1)`, name one anchor convention (`before`) in the glossary, and add a single mapping function `CellAddress -> RowLine index` with its own test since the delimiter row sits between rows 1 and 2.
- [ ] **Wave schedule (Critical path section) violates its own dependency graph and serialization rule** — (a) `5.1a` is in W8 with `4.3c`, which it depends on; (b) `5.8a` (W11) needs `5.3b` (W11); (c) `6.1a` (W11) depends on all `5.x` yet runs parallel to them; (d) `TableBlock.kt` is declared one-task-per-wave in the order 4.2a, 4.3a, 4.4a, 4.5a, 4.5b, but W8 contains `4.3c`, `4.4a` and `4.5b`, all editing `TableBlock.kt` (4.3c lists it under Files). — Re-wave: move 5.1a to W9, 5.8a to W12, 6.1a to W12, and split W8's `TableBlock.kt` edits across waves (4.3c, then 4.4a, then 4.5a/4.5b). This lengthens the path by roughly one wave (expressed as waves, not time).
- [ ] **Task 1.4a / Task 4.2a / `ui/components/sheet/` placement** — `scripts/kmp-modules-sync.py` reports files in a directory with no owner as orphans (VERIFIED, script docstring and `orphans` branch); no source today lives under `table/` or `ui/components/sheet/` (VERIFIED: manifest search). The plan hand-places `table/` and `table/formula/` but not `ui/components/sheet/` (ui_main), and the integrator note says "never hand-edit generated manifests" while 1.4a requires it. — State in 1.4a that `ui/components/sheet/**` is placed in `ui_main` by hand in the same step, and reword the wave-integrator rule to "never hand-edit except the one-time orphan placement".
- [ ] **Story 1.2 `TableEditResult` (Lens 2)** — `TableEditResult(doc, announcement: String, notices: List<String>)` encodes a refused edit as "unchanged doc plus a notice" (e.g. delete header, delete last column, over-cap paste). Callers must compare docs to know whether to commit, and user-facing strings live in the pure core (no i18n seam). — Return `sealed TableEditOutcome { Applied(doc, summary: EditSummary), Refused(reason: RefusalReason) }` with enum/structured data; map to strings in `ui_main`. Same shape for `CellDraft` in the Glossary, which says `TextFieldValue` (Compose type) while Task 3.2a correctly says plain text/selection/composition flag; fix the Glossary.

## Nitpicks
- `TableClipboard` (new port, `COMMON/table/`) overlaps the existing `export/ClipboardProvider` (`writeText`/`writeHtml`, in module `export`); copy could reuse it and only paste needs a new port. Note the reuse decision in ADR-008. Also state how the commonMain host obtains `WasmPasteEventBridge` (expect/actual or composition local); 7.1b/7.1c leave it implicit.
- Read-only mode (Story 5.1) cites `TargetWriterCapabilities`, which is the cross-graph write convention, not a per-block read-only flag; name the actual source of read-only state (Unresolved Question list).
- `TableCalc`'s "guard returns Err for any Throwable incl. StackOverflowError/OOM" cannot catch stack overflow reliably on Wasm/JS; the depth bound of 64 is the real protection, say so in Task 2.2c.
- Inline `TableBlock` stays composed behind the Dialog while the sheet edits the same block; 4.5a specifies commit-first only for "Edit as markdown". Add the same rule for opening the sheet so two editors never hold drafts for one block.
- `TableEditor.kt` accumulates structure ops, sort, paste and rewrite across tasks 1.2a, 1.2b, 2.3b; consider one file per op family (`StructuralOps.kt`, `SortOp.kt`, `PasteOp.kt`) to keep it from becoming a God file, since the plan deliberately avoids per-op methods on `TableDoc`.

## Round-1 blocker: undo flips block into raw editor - RESOLVED
- VERIFIED the defect is real: `BlockStateManager.kt:1088-1097` undo/redo closures end in `requestEditBlock(...)`; `:1140` guard `pageBlocks[idx].version <= version` would reject an `oldVersion` replay after a higher-version edit.
- Repair (Story 0.5, Tasks 0.5a/0.5b, Tech Debt row, ADR-004): default-valued `restoreEditFocus: Boolean = true`, closures skip `requestEditBlock` and re-apply at `block.version + 1` when false; failing-first test 0.5a precedes it (W1 then W2, both before 4.3a/4.3c/5.1a). Default keeps all text-block callers identical, so it is a legitimate isolate-via-seam on the hotspot. The `oldContent == newContent` early return (`:1085`) is unaffected. Inline commits route through `LocalTableCommitAction` (4.3c) so inline undo is covered too.
