| 1 | The sheet's commit/echo/undo machinery (`OwnCommitLedger`, `TableCommitter`, `expectAdopt`, `undoRecordCount`, depth counters) is stacked on INFERRED behaviour of `BlockStateManager` and the DB feed. ## P1 Items (address before implementation)

- [ ] **Failure 1: sync/undo machinery** — patch `plan.md` as follows.
  - Add **Task 0.6a (S, W1, agent-only): record the real emission trace.** A real `BlockStateManager` over the SQLDelight repository (the 5.1c harness) with two quick commits, one commit then undo then immediate re-commit, redo, and one foreign write; log every `getBlockByUuid` emission and manager content as an ordered list into the task report and a committed fixture. Depends on 0.5a. Blocks 3.2b (its scripted cases cite this fixture, so the sequences are real rather than imagined).
  - Extend **Task 3.2b** with a randomized test: generate event sequences (commit, echo in any order, undo, redo, foreign write, markDone) against a model, and assert "display never older than the latest sheet commit" and "no committed content is lost"; record a mutation proof for it as for 5.1c.
  - Add to **Story 5.1** a degraded-mode criterion: if the policy returns `Stale` for the same content more than twice in a row, or `sheetUndoDepth` disagrees with `undoRecordCount` after joining, the sheet flushes, closes with a one-line message and re-opens from DB content. Nothing is ever displayed from a guess.
  - Add to the **Overrun checkpoint** a named trigger: if 5.1b/5.1c need a third repair round, stop and record the decision whether to simplify (sheet-exclusive commits, undo disabled in the sheet and only on page close) before continuing. Report the delta, not a cut invitation.
- [ ] **Failure 2: late device reality** — patch `plan.md` as follows.
  - Add **Task 8.2b (S, owner machine) "early device smoke"** after 4.3a lands (W6/W7) and again after 5.2b (W10/W11): `Pixel_Fold`, tap-edit a cell with the soft keyboard, scroll the editing row 30 rows away and back, tap a link, long-press. Pass/fail recorded; a fail blocks the next gesture/grid wave. Both emulator runs stay "one emulator, one Gradle run at a time".
  - Give **Tasks 0.3a and 0.4a** explicit decision rules written into the task text: if the Wasm spike shows IME composition not reaching a Dialog `BasicTextField` or the paste event unavailable, then the Web target ships view-only plus "Edit as markdown" and the plan drops Wasm edit-mode tasks (5.3a Wasm part, 7.1b) rather than adapting later; if the Android spike shows the hoisted draft does not preserve composition across recycling, then the sheet renders the editing row outside the `LazyColumn` (pinned editor) instead.
  - Add to **Story 4.2** a criterion that the gesture owner delegates to platform text selection (no custom drag) on touch, matching the #240 lesson, and an owner-confirmed wording of the flag-on touch behaviour before 4.4a starts.
